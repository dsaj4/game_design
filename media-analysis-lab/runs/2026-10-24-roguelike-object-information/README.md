## 方法与证据边界

先查官方商店/官网，再在浏览器实际查看远程原图像素。实际成功途径为 `mcp__cua_repl` 创建后台IAB标签，`tab.goto(原图URL)` 后 `tab.getScreenshot()`；web.open图片只有空文本，未把它当作像素证据。截图由工具即时呈现给研究agent，没有保存进仓库。下文 **V** 是直接视觉观察，**T** 是网页文字事实，**I** 是分析推断，**S** 是可迁移建议。静图只能证明该帧的呈现，不能证明鼠标悬停、出牌、升级操作已实际发生，也不能据此重建完整结算顺序。所有外部链接访问日期均为 **2026-10-24**；官方商店截图和press kit的游戏构建版本均为 **Unknown**，不宣称代表当前运行版本。社区表格数值只辅助理解，不与官方旧截图强行合并为同一版本。

## 1. Slay the Spire：把行动预算和规则连在同一张卡上

**证据入口：**[官方Steam页](https://store.steampowered.com/app/646570/Slay_the_Spire/)；[S1：Zap+战斗原图](https://shared.akamai.steamstatic.com/store_item_assets/steam/apps/646570/ss_01aa3e7759e457bfbf2422f31c325d7b3ba8a6eb.1920x1080.jpg)；[T1：社区wiki Zap](https://slaythespire.wiki.gg/wiki/Zap)。T1正文抓取403，但搜索服务返回了该页完整相关字段段落；因此以下获得/升级关系属于社区索引文本核对，非官方手册或运行确认。

- **V / 普通展示：**S1底部手牌可读Strike、Dualcast+、Defend+及各自左上费用；重叠手牌没有把所有规则同时展开。中央大卡是Zap+，绿名、左上0、类型Skill、下部生成1个Lightning的规则。这里是放大卡帧，究竟是悬停、出牌动画或其他展开机制，**Unknown**。
- **T / 身份与获得：**T1将Zap记为Defect的Basic Skill，开局持有；基础费用1、升级0，规则仍生成1球。不能把这些字段全部说成S1卡面直接可见。
- **V / 强化：**S1确认“+”与绿色名称及0费共存；没有基础/升级左右对照，也未观察升级操作。**T**的基础/升级差异与画面相容。
- **V / 运行：**S1左下能量4/3，人物旁球标3，敌方30/50生命；这是同屏当前读数。不能由此判定Zap+一定导致该敌人损失多少生命。球自身详细规则、目标选择和临时改费说明 **Unknown**。
- **I / 判断：**比较Zap和Zap+时，收益相同而行动预算不同；比较Zap+与直接伤害牌时，还要知道球的后续收益、槽位与触发规则。费用是支付，生成球是收益，Skill是身份，升级是构筑改动，当前能量是情境。把这些混成“强度数字”会丢失选择理由。
- **边界：**大卡可读不等于整手信息随时可读；简短关键词压缩了规则，却把学习负担转移给词典/经验。本次未观察关键词提示面板。

## 2. Monster Train：同一物件在“部署卡”和“场上单位”承担不同问题

**证据入口：**[官方Steam页](https://store.steampowered.com/app/1102190/Monster_Train/)；[M1：Clipped Guard战斗图](https://shared.akamai.steamstatic.com/store_item_assets/steam/apps/1102190/ss_edce778e9006c559cc347542ba2a61ed1461c945.1920x1080.jpg)；[M2：Fel战斗图](https://shared.akamai.steamstatic.com/store_item_assets/steam/apps/1102190/ss_cd1c375e15c677f1d79a5dcd59692f918b19ebde.1920x1080.jpg)；[T2：社区wiki Animus of Speed](https://monster-train.fandom.com/wiki/Animus_of_Speed)。T2直接open失败，搜索服务返回了完整相关信息段及版本历史；其策略评价未作为本报告结论。

- **V / 普通展示：**M1右下手牌Animus of Speed：1费、顶部两个黄色圆点、名称、Quick可读，卡下部被画面边缘裁掉。M2再次出现同插画与Quick。**T**：wiki标Awoken / Animus / Uncommon，费用1、容量2、攻击25、生命3；加入历史1.0.0，正文当前适用版本 **Unknown**。黄色圆点解释为容量由T辅助，不能声称该帧同时清晰展示25/3。
- **T / 获得与比较：**T2称其Banner Unit。官方页说明多层战场及单位/卡牌升级；具体本次如何获得这张卡 **Unknown**。
- **详情/强化：**未观察该物件完整展开、商店强化槽或改前改后对比，均 **Unknown**；不能把wiki推荐升级当作实际已强化。
- **V / 运行：**M1场上实体下方有刀剑攻击、红心生命、紫色效果标，另有橙色负数（如敌方-34、己方-5）；M2还有绿色+5及敌方-16。楼层上方有亮/暗容量灯。静图确认“当前值旁另呈变化数”的表达，变化究竟是预测、动作中还是其他状态，仅凭图 **Unknown**。未把场上任一实体冒认为Animus of Speed。

- **边界：**需要同时看手牌、楼层和实体；图标浓度高、单位规则无法仅靠战场缩略像获得。

## 可迁移原则（S：设计建议，非验证结论）

1. **先定义玩家当下要作的比较，再选字段。** 行动比较需要费用/目标/收益，部署比较还需要空间与存活，长期构筑比较需要触发条件和占位。适用于确有这些选择的系统；不为凑字段硬加稀有度或分类。
2. **区分身份、构筑改动、当前值。** 名称/类型用于识别，升级或装配用于解释改变，能量/生命/触发进度用于当前决策。三者可相邻，但应可辨来源；前提是系统确有跨时段变化。
3. **把代价、收益、限制写成不同语义。** 0费用不是0机会成本，25攻击不是存活能力，3金币不包括占格。适用于有多个预算的游戏；用单一综合值会遮住取舍。
4. **缩略视图服务筛选，展开视图服务解释。** 以稳定位置显示少量高频字段，详情补关键词和条件；前提是展开便捷、关键选择不会因隐藏信息而误导。这里未验证四游戏实际展开效率。
5. **组合规则需要能定位到关系对象。** “不同Food”“含Pair”“楼层容量”要知道作用的是谁、哪里、何时；有空间关系时图形范围可能比一段抽象文字更有效。前提是关系规模可读，不能仅画连线却隐藏触发条件。
6. **运行反馈应让人区分读数与变化。** 当前生命、正负变化、累计分数承担不同问题；若另给预览，必须明确它是预测还是已发生。静帧看到变化量不足以证明玩家能解释原因，需要后续理解测试。
7. **强化比较应说明改了哪项。** Zap例提示：升级可能只改成本而不改收益。适用于可改造物件；若只用更亮外框或等级数，会迫使玩家记住旧值。本次没有观察完整升级对照交互，因此这是建议而非对原作功能的背书。

## 不能直接迁移的机制假设

- 固定能量与回合制、三层容量、扑克牌型/Chips×Mult、格子邻接和自动战斗分别是原作机制前提，不是通用信息设计要求。
- 稀有度不必代表即时强度，类型标签也不必都显示；只有进入规则判断的身份才值得占用显著空间。
- 关键词压缩、动态图标或计分动画是否提高理解，本研究没有玩家证据；市场成功不能替代信息理解测试。
- 不能把这些外部数值、资源数量、强化方式、槽位上限直接定为目标项目参数。
