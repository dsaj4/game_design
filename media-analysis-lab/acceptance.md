# 第一阶段验收标准

## 验收范围

本阶段只验证“图片 + 文本材料 -> 游戏拆解稿”的能力。

不验收：

- 视频下载。
- 自动抽帧。
- ASR 转写。
- BiliSum 数据库读取。
- 自动联网查商业数据。
- 真实 LLM / VLM 调用质量。

## 必须通过的功能

1. 能读取一个素材包 `materialpack.json`。
2. 素材包至少包含 1 个文本材料和 1 个图片材料。
3. 能生成分析任务包，且任务包包含：
   - 拆解对象和拆解范围。
   - 目标问题。
   - 图片证据表。
   - 原始文本材料。
   - 输出模板。
   - 写作约束。
4. 能生成拆解稿初稿，且初稿包含八大模块。
5. 初稿必须包含核心循环图和系统关系图。
6. 初稿必须包含“对本项目的转化”。
7. 能生成质量检查文件，指出通过项和缺口。

## 质量门槛

一份样例稿可以进入人工评审前，至少满足：

| 项目 | 门槛 |
| --- | --- |
| 八大模块覆盖 | 全部出现 |
| 核心循环 | 有 Mermaid 图或清晰文本流程 |
| 系统架构 | 有 Mermaid 图或清晰系统关系 |
| 证据映射 | 至少列出图片和文本证据 |
| 未确认信息 | 单独列出，不硬编事实 |
| 项目转化 | 至少 1 条可验证设计假设 |
| 当前状态 | 明确为 Research / Prototype Lab |

## 推荐人工评审问题

- 报告是否准确概括玩家反复做什么？
- 报告是否区分“事实、截图观察、文本推断、作者判断”？
- 核心循环是否闭合，还是只是系统清单？
- 系统联动是否说明了输入、消耗、产出和反馈？
- 结论是否能服务本项目的唯一核心卡、辅助卡、费用、组合或动态平衡判断？
- 哪些内容必须等真实视频转写或更多截图后才能确认？

## 示例运行

```powershell
py -3 media-analysis-lab/tools/build_analysis_packet.py `
  --pack media-analysis-lab/examples/core-card-duel/materialpack.json `
  --out media-analysis-lab/examples/core-card-duel/dist `
  --check
```

成功时终端会输出生成文件路径，并在质量检查中标记核心门槛通过。
