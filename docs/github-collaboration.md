# GitHub协作规范

现行版本：2026-09-30 / layout.3。具体项目路径以项目AGENTS映射为准；言咒在yanzhou，旧兼容目录已退役。

## 修改前

执行`git status --short --branch`和`git branch --show-current`。不得在main/master或空白默认分支修改保护文件；自动创建自己的任务分支。已有合适的非默认任务分支可继续使用。不要把他人的暂存、未提交修改、删除和未跟踪内容并入本任务。

分支默认使用`codex/YYYY-MM-DD-short-task`，遵从用户明确命名。不要无授权强推、reset --hard或覆盖远端历史。

## 保护范围

项目核心设计、GDD与系统正文、素材资格、提案/评估/拟修改、决策、AGENTS、README、CONTRIBUTING、共享模板/规则、项目注册、协作规范和资料迁移映射均受保护。修改这些内容后，必须本轮提交并推送当前分支。

玩法规则变更先有合格来源与提案/评估，再写Draft Change。用户明确采纳后更新权威规则、受影响摘要和决策记录。已有明确授权不重复询问；文档管理决定不扩展玩法采纳。

## 提交与推送

1. 检查本任务差异、来源链接和所需验证。
2. 用明确文件列表暂存；大型清理按处理清单暂存，不使用无范围的git add -A。
3. 确认暂存列表没有无关修改和私有/第三方原始缓存。
4. 提交清楚说明结果的commit，推送当前分支；不自动合并main。
5. 报告文件、状态、检查、分支和提交。失败则明确本地/远端状态，不隐藏错误。

## 清理与历史

用户授权清理时，先核对独有内容、未提交修改和引用。已有提交中的重复快照可退出工作树，使用固定提交和原路径取证；不得把历史来源改写成当前规则。未提交内容在删除其目录前逐字节保存到明确恢复位置并校验，不擅自发布。

本仓库的研究原始缓存、临时工具输出、凭据和未获授权的未跟踪资产不自动提交。检查范围和缺口如实报告；静态文档校验不等于玩法验证。
