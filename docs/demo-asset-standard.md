# Demo 与素材管理规范

版本：DA-1 / 2026-10-01。状态：Accepted / Workspace Administration；依据用户要求统一管理正式系统和探索方向的 Demo、素材，方便复用参考。适用于已注册游戏及公共参考区域，不改变玩法资格、采纳、阅读范围或实验权限。

**先查[统一目录](registry/demo-assets.md)，再到原位置使用；同一资源登记一次，每次复用留下目标和版本。** 小方向继续一份 README，不预建资源库和流程目录。

## 1. 管什么、由谁维护

| 对象 | 管理范围 | 不混淆的对象 |
| --- | --- | --- |
| Demo（DM） | 可操作原型、动效/交互演示、可玩构建、验证小样 | 录屏、截图是展示素材，不代表可运行 Demo；计划不能标为已交付 |
| 素材（AS） | 图片、UI、模型、纹理、动画、音频、字体、参考图、媒体包、提示词及可复用源文件 | `sources/materials/` 的 M 是通过资格确认的设计素材；AS 登记不能替代 M |
| 代码与工具组件 | 可作为 Demo 的外部依赖引用，复用时记录代码来源 | 源码、安装、API、构建脚本仍在代码仓库，不放入 GDD 或公共素材目录 |
| 验证证据 | 关联报告、截图、录屏、实际版本与覆盖范围 | Demo 可打开、视觉被选中、代码已实现，都不表示玩法被采纳或验证成立 |

统一目录只维护身份、归属、入口、固定版本、可访问性和复用条件。设计细节归 GDD/方向页，实现状态与证据归项目 development，视觉判断归项目 visual/方向页，技术说明归实现仓库。已存在的字段引用其权威记录，不复制多份维护。

每条资源只设一个归属 Project ID、一个主要方向或 `main`/`shared-reference`，以及一个维护位置。被多个方向使用时增加“被哪些对象引用”，不复制资源条目或自动转为正式系统资产。跨项目复用不继承原玩法、资格或实验结论。

## 2. 最小目录与编号

```text
docs/demo-asset-standard.md                 唯一管理规范
docs/registry/demo-assets.md                全项目检索目录（仅元数据）
game-design-workflow/templates/
  demo-asset-record-template.md             按需嵌入已有README的登记模板
<项目>/development/README.md                Demo交付、范围和证据
<项目>/exploration/DIR-.../README.md         方向用途、素材引用与复用记录
<项目>/visual/...                           正式系统视觉包；原文件就地保管
media-analysis-lab/...                      公共拆解参考及其来源
<外部实现仓库或持久演示目录>                 Demo源文件、构建和技术说明
```

- 不重建已退役的根 `assets/`、`exploration/`、`workspaces/`。新非视觉素材先按项目自身布局按需指定位置，不为每个类型建空目录。
- ID 使用 `DM-<范围码>-NNN` 或 `AS-<范围码>-NNN`；现有范围码 `G002`=game-002及其探索，`NR`=new-roguelike，`SH`=公共方法/参考区域。范围码只是编号，Project ID 仍写注册表原值。
- 同类同范围独立递增，分配前检查目录和归档记录；编号不复用。迁移或跨项目引用保持原 ID；形成独立维护的分支/改作时分配新 ID，记录 `derived-from: 原ID@版本`。
- 新独立记录文件用 `ID-short-name.md`；有现成 README 时直接加 `## ID 名称`，不额外建文件。新制作文件建议 `主题-v01-用途.ext`，区分源文件、预览与导出；原有文件无需仅为命名规范改名。
- 只管理一种用途的小包可登记一个 AS；需要独立复用/不同许可的子资源再拆 ID。包的每个版本须有文件范围或 manifest，不能把整个可变目录当成固定版本。

## 3. 登记内容：通用字段 + 必要补充

最小登记需明确：**ID/名称、归属与用途、主入口、固定版本、状态、来源/复用条件、关联对象及边界**。暂缺可写 Unknown，并写下一步；不得因字段缺失虚构已运行、可分发或兼容结论。字段用[登记模板](../game-design-workflow/templates/demo-asset-record-template.md)嵌入现有维护位置。

| 字段 | 具体要求 |
| --- | --- |
| 归属 | Project ID，main 或 DIR 编号，维护文档；公共资料标 shared-reference |
| 用途与类型 | 例如“评审翻牌动效”“旧Demo视觉参考”；给少量检索标签，不塞入完整玩法 |
| 主入口 | Demo 的预览/构建与技术说明分别给入口；素材的原件/源文件与预览分开。注明仓库相对路径、外部仓库、持久本地目录或已发布URL |
| 固定版本 | 本仓库用完整 Git 提交+路径；外部 Git 同样固定提交；无Git的交付用版本+文件SHA-256或包manifest。分支名、latest、localhost不是固定版本 |
| 设计来源 | 对应规则/方向/视觉包及版本；旧RC1或方向候选保持原身份，不因主系统改为TL-1就改写旧交付 |
| 状态与可访问性 | 生命周期与访问检查分开，记录最后检查日期和检查内容；本机存在不代表其他机器可用 |
| 来源与复用条件 | 自制/用户提供/生成/第三方；作者、原来源、许可或授权依据、署名及允许范围。权利未知写Unknown，不能标“可直接复制分发” |
| 关系 | `uses`使用了哪些AS/依赖，`derived-from`改作自谁，使用者记录具体版本及目标。未用某概念图的二进制文件时写“视觉参照”，不写已导入 |

**Demo补充**：明确演示范围/未实现项、打开入口、操作说明入口、运行环境与依赖说明入口、设计偏差、关联素材版本、最近验证证据和未测内容。这里只存说明入口；安装命令与代码细节留实现仓库。可选录屏帮助无法运行的读者，但不能代替原件。

**素材补充**：按实际类型记录足以判断能否复用的规格，不填满无关字段：

| 类型 | 必要规格示例 |
| --- | --- |
| 图片、UI、纹理 | 格式、尺寸、透明通道、切片/图集关系；生成素材附实际使用的提示词和已知生成来源 |
| 模型、动画 | 源工程/导出格式、单位/朝向、骨骼或动画依赖、纹理关联 |
| 音频 | 格式、采样率/声道、时长、循环点（若适用） |
| 字体 | 字体名称/版本、字形覆盖、嵌入和分发条件 |
| 参考/材料包 | 文件范围、来源清单、用于什么参考；混合许可逐项标记 |

已登记的旧资源可以先处于 Catalogued / Unknown，后续第一次实际复用时补齐相关规格和依赖；“已登记”不等于“已可用”。

## 4. 状态不混用

- 生命周期：`Planned` 尚未交付；`Catalogued` 已发现并登记；`ReadyForScope` 在指定环境和用途下已核验；`Archived` 停止维护但保留取证。被替代写后继 ID/版本，不抹掉旧记录。
- 可访问性：`PresentLocal` 本机路径存在；`Reachable` 已检查远端可访问；`Missing` 已知入口缺失；`Unknown` 未检查。页面能打开不等于运行通过。
- 原设计状态（Raw/Qualified/Accepted等）和原证据状态（NotRun/LimitedEvidence等）继续沿原记录。本规范不新增另一套玩法资格等级。
- 任一检查注明“检查了什么、哪版、何时、哪些没测”；登记人员不得把历史通过结果写成这次重新验证。原型失败也保留版本和观察。

## 5. 新建、复用与交付

1. **先查重。** 在目录元数据查名称、标签、Project/DIR和用途。普通探索先受READ-1/项目材料范围约束：管理任务可横向盘点；普通方向未经授权不得打开其他方向、项目或历史资源正文。目录可检索不等于材料自动纳入。
2. **选定具体版本。** 分清参考、直接引用、复制改作或独立实现；检查适用设计、规格、依赖及复用条件。无法确认的项目留Unknown；已有明确授权直接按范围执行。
3. **记录使用。** 在目标方向README、项目开发索引或视觉说明中记“目标 → 源ID@版本 → 用途/方式 → 改动/限制”。源记录只保留使用者链接；参数和资格仍留目标项目。
4. **产物就地保管。** 默认引用原件；同内容不重复打包。确需改作时保存独立版本或新ID并记录来源，不覆盖被其他产物固定引用的旧版。运行依赖需要随构建封装时由代码仓库处理，不用消除重复破坏可运行包。
5. **完成登记。** 给出可定位入口、源/预览/导出关系、版本和证据，更新目录及所属项目入口。没有执行任务授权时只登记/编写计划，不安装依赖、启动Demo或发布网站。

探索成果用于正式系统时，资源技术复用与玩法采纳分别处理：图片或动效可先作为参考；若改变正式交互、规则或范围，仍走资格、提案/评估、Draft Change和采纳。不同DIR即便都在言咒，也不自动兼容。

## 6. 保管、迁移与归档

- 原件尽量保存在可追溯仓库或明确持久位置。用户目录下的可视化交付可先登记为本机资源；跨机器复用前检查所需源文件与依赖是否齐全，按授权迁入实现仓库或持久交付位置，并补新入口，不默默移动旧文件。
- 源文件、可玩构建、预览和证据分别定位。临时服务器地址只作当前会话提示；有稳定发布地址时仍保留来源版本和技术入口。大构建/原始媒体放适当外部存储，仓库登记清单和校验；不为此任务自动安装LFS或上传二进制。
- 现有第三方原始缓存、未跟踪资产和私有产物不因登记而自动入Git；原件位置可用本地路径记录，缺失路径标Missing。公共分发仍按实际许可/授权，不把Unknown补成通用开放许可。
- 迁移先查使用者，核对文件范围和哈希，再同步目录与活动链接；原固定提交、历史路径、授权和失败证据保持原义。删除前确认可恢复且没有独有未提交内容，遵循现有清理规则。
- 归档将生命周期标Archived并给固定取证入口/后继版本；不重新使用旧ID。已经消失的旧Demo记Missing，不承诺可恢复或可运行。

## 7. 验收与维护

一次登记/复用完成时核对：ID唯一、归属明确、主入口和版本可定位、设计身份无混用、源/派生/使用关系可追踪、复用条件真实、检查范围明确。仅改路径和索引时做文档检查即可，不为验收管理规范运行玩法实验。

新资源按需登记；不要求把每个过程截图和自动生成文件拆成记录。本规范和目录是共享入口，项目内引用其ID；不再增建平行的机器注册表。保护文件按[Git规范](github-collaboration.md)同轮提交推送。
