# 项目 Skill 管理规范

版本：SK-1 / 2026-10-02。适用于本仓库的工具治理，不改变任何项目的玩法资格与采纳规则。

直接使用全局 [skill-registry-control](C:/Users/Administrator/.codex/skills/skill-registry-control/SKILL.md) 管理安装、更新、移除和盘点；不复制一份项目版。项目入口为[安装清单](registry/project-skills.md)，机器范围的可见性、重复安装与变更日志由该 skill 的注册表维护。两者分别回答“本项目如何使用”和“这台机器发现了什么”，不能互相替代。

## 准入与安装

1. 明确当前任务缺口，先检查已有能力；报告推荐只算候选，不算执行指令。运行时安装目录是 `.codex/skills/`；源码克隆、评估样本、缓存均不等于安装。
2. 使用注册控制登记计划，检查同名技能、项目/全局作用域及既有改动。需要安装时使用 `skill-vetter` 审查选定子目录的全部文件及根许可证；涉及执行、联网、凭据或自动写入的路径另列权限。未完整审查的候选不得写成“安全通过”。
3. 固定仓库、提交和子路径，确认许可证适用、能力必要且不与现有技能职责重复。来源不可取证、许可不明或限制尚未解决时暂缓；不以热度代替审查。
4. 通过可信安装工具只安装需要的子目录，不执行来源仓库安装器，不顺带引入 CLI、hooks、MCP、插件或后台服务。新增执行能力需重新界定和审查范围。
5. 保留许可证与 `source-lock.json`，记录上游文件哈希、原始提交、项目改写和新增文件。入口先读项目适配层；上游方法与项目材料分开，项目路径、READ-1、资格流程及注册模板优先。
6. 检查格式、入口、链接和来源完整性，再做明确标注的边界演练。静态通过、人工演练、独立运行效果及真实任务效果分别记录；不得从安装成功推断设计有效。
7. 安装后扫描注册表、补变更日志与项目清单，只提交本任务文件并推送任务分支。新装技能从下一轮会话开始使用；若列表未刷新再重开会话。

## 使用边界

- 按任务选择最少的技能，不强制每轮走完全部工具。一般目录管理不调用玩法设计器。
- Skill 提供方法，不提供新的玩法权威。链接不自动扩大材料范围；每个参与者继承同一 READ-1 白名单。
- Raw Idea 仍留 inbox 或所属方向；审查意见不自动成为正式 Evaluation，GDD 草稿不自动成为 Accepted。代码完成、测试结果和体验假设分别登记。
- 对可从允许材料解决的问题先查；剩余资格问题按依赖成组列出推荐与影响。已授权的具体工作不重复索要许可。
- 不自动创建第二套 `.design-context/`、复制整套模板、启动实验或生成持续运行代理。并行协作遵循[言咒分工规范](../yanzhou/governance/agent-collaboration.md)。

## 更新、停用与回退

更新视为一次新的准入：固定新提交、审查差异及新增能力，保留项目适配，重新检查许可证、来源哈希和材料边界。不自动追随上游最新版。行为变化较大时先在运行时目录外评估，不能仅凭同名替换。

停用候选或备份存到运行时发现根之外并登记；不要在 `.codex/skills/` 内放 `.disabled`、旧版副本或评估用 `SKILL.md`。删除/移走实际安装需要任务授权，并保留可恢复的固定 Git 版本。回退只恢复该任务拥有的技能和关联清单，不对整个工作区 reset，不覆盖他人改动。

评估文件可记录复审触发条件：新任务确有缺口、许可获得确认、上游能力变化或实际使用失败。没有这些触发条件，不定期批量安装或全量扫描玩法资料。
