# GIC → 《言咒》的吸收、评估与更新流程

日期：2026-09-20。Project ID：`game-002-optimization`；目标游戏：`game-002`。流程版本：`GIC-ABSORB-v1.0`。研究结论为 `Research / Provisional`；新机制为 `Agent Proposal / Raw Idea / Unqualified`。

## 本轮问题与范围

在保留“实体词卡构句、战前编排、战中自动执行”的前提下，哪些外部设计能改变玩家的选择，而不只是增加词卡数量或伤害倍率？用户授权自主研究、筛选、更新候选并给出几个方向；没有要求直接采纳新玩法。

唯一项目设计来源是用户指定的[全游戏 GDD RC1](../../../../workspaces/game-002/game-design-workflow/gdd/GDD-2026-09-14-yanzhou-full-game.md)及其正文中构句、元素两个相关章节。它是本轮显式补充来源，不更新活动背景包，不递归追溯素材或读取其他探索方向正文。治理入口中的历史导航仅用于路由，不作为本轮创意来源。

本轮先浏览 GIC 224 份档案的标题与创新摘要，再按机制差异选择 24 款有足够正文的游戏，合并同游戏的多份档案逐款分析。只有一句摘要且原图未可靠取得的条目保留在目录，不假称完整拆解。24 款不等于 224 份全部深读，也不代表站内全部独立游戏。

## 1. 吸收：先保存证据，再抽出结构

1. 登记访问时间、档案 ID、类型、原图 URL、正文哈希；保留原始名称和拼写，修订显示名须保留映射。
2. 同游戏不同档案合并为一案，但逐条保留 ID；它们仍是同一网站的资料，不能视作多个独立来源。
3. 用自己的话回答：玩家有什么信息、做哪个选择、放弃什么、得到什么反馈、为何需要下一次选择。
4. 分开写“GIC 描述”“结构推断”“迁移设计”。GIC 是评选者对创新点的二手描述，不是开发者规则书或玩家测试。
5. 不从标题推导精确时序、数值或边界。不把“创新”“好玩”“天然平衡”等评价当作实验结论。

## 2. 评估：四道过滤

| 过滤项 | 问题 | 处理 |
| --- | --- | --- |
| 证据 | 是否能说清来源实际描述的动作与代价？ | 只有标题：待补资料，不为其补规则 |
| 新增价值 | RC1 是否已经有相同决策？ | 已有：吸收表达/验收方法，不包装成新方向 |
| 合同 | 是否要求战中操作、多人读心、无限物理或永久变强？ | 标明冲突；可分离的结构留下，依赖冲突的部分放弃 |
| 可证伪性 | 能否用小规模、同资源的对照观察选择变化？ | 不能：缩小候选，仍不能则研究后置 |

最终方向用五项 0–3 分的**作者排序工具**比较：独特性 D（相对 RC1）、有意义取舍 C、基线相容 F、最小验证容易度 V、额外复杂度 B。排序参考 `D+C+F+V-B`，不解释为成功率、好玩分或市场预测。分数必须附理由；硬冲突和缺证据优先于总分。

## 3. 更新：逐款产生一条处理决定

每款建立独立研究卡，保存机制、可借鉴结构、不迁移项、RC1 差异、候选更新及 Unknown。更新动作只有：`保留结构 / 缩小范围 / 合并 / 研究后置 / 不迁移`。它们是研究处理，不是正式设计状态中的 Accepted、Parked 或 Rejected。

候选保留 v0→v1 变化及触发来源；后续有新来源或反例则追加 v2，不覆盖旧版本。每次更新必须说明哪个玩家选择发生变化，不能只把两个游戏名称拼在一起。先扩展机制视角，再对照基线和负面案例收敛，最后才排序。

## 4. 资格与正式回写

已使用 grill-with-docs 对照 RC1 检查设计对象、玩家情境、行动、体验、关系和验证方式。这里能查清的是既有规则和新增差异；用户对新增成本及游戏重心的选择仍未知，agent 设想不会因字段齐全自动变成合格素材。

本轮完整交付到研究报告和原始候选。选定方向后，按本项目资格闸门晋级本地素材，再形成 Proposal / Evaluation；如需改变 game-002，另走目标项目复审与 Draft Change。这里的比较表是研究性适配比较，不在 `evaluations/` 创建正式 Evaluation。

## 5. 下一轮怎样更新

| 触发 | 最小动作 | 候选处理 |
| --- | --- | --- |
| GIC 档案正文哈希变化 | 对比变化段，检查既有推断是否仍成立 | 新版本来源记录；不能静默改旧研究 |
| 官方规则与档案矛盾 | 官方明确规则优先，记录冲突范围 | 受影响候选降为证据不足或修订 |
| 纸面规则出现无代价强选项 | 给出反例，缩减奖励/增加真实排他成本 | v2；禁止用“数值以后再调”跳过结构问题 |
| 原型能运行但用户不理解 | 保存真实错误与解释过程 | 优先简化词义/显示；运行成功不等于体验成功 |
| 用户选择方向 | 一次处理一个影响结果的关键取舍 | 独立资格确认，保留来源链 |

本轮是一次有限研究任务，没有创建定时自动任务。预算为一轮目录整理、24款逐案处理、最多5个最终方向；0场玩法模拟、0个可玩原型、0次真人测试。
