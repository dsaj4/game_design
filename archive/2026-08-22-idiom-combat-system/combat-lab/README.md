# 成语组合战斗独立测试系统

> 状态：`Archived / Superseded`
>
> 本原型只保留旧“成语组合 + 攻防共享战斗能量”方案的实现与测试证据，不再作为当前战斗系统或客户端实现基线。当前入口见[归档说明](../README.md)。

`combat-lab/` 是与正式游戏构思链隔离的确定性规则原型。它用于检验“低数值辅助卡 + 字段匹配 + 核心卡成语组合”是否可计算、可构筑和可平衡，不代表规则已经被正式采纳。

## 第一批原型边界

- 双方基础血量值暂定为 30。
- 核心卡只包含 4 个公开成语组合，不包含常驻被动或独立主动能力。
- 每张核心卡至少包含 1 个攻击组合和 1 个防御组合。
- 辅助卡只有一个属性和一个数值为 1 的基础效果，不产生场面；单独行动固定为 1 费。
- `attack` 对应 1 点伤害，`defense` 对应 1 点护盾，`dispatch` 对应抽 1 张，`disrupt` 对应弃 1 张。
- 属性决定基础效果；字段只用于组合匹配。一张辅助卡可以有多个字段。
- 第一批卡组各 20 张，每张辅助卡模板放入 2 张。
- 每名玩家拥有固定 4 点攻防共享能量，在己方回合开始时重置；进攻后剩余能量公开保留到对手攻击阶段。
- 组合采用整体定价，材料牌费用不重复累加；辅助卡可以作为 1 费保底动作单独打出。
- 完整回合、启发式电脑策略和批量胜率模拟已作为可替换的测试层加入。

## 组合匹配条件

字段条件被实现为不考虑顺序的多重集合，但参与牌必须是不同卡牌实例：

- `羊 x3` 必须选择三张不同的牌。
- 一张同时包含 `羊`、`牢` 的牌，在同一次组合中只能填一个字段槽位。
- 选择的牌数必须恰好等于组合要求的字段槽位数，不能加入无关牌。
- 同一张牌在一个回合内只能参与一次组合；当前引擎通过结算后进入弃牌区保证这一点。
- 攻击组合只能从攻击方手牌发动；防御组合只能从防守方提前公开的 `prepared` 防御准备区发动。
- 一次 `resolve_exchange` 只允许一个攻击组合和至多一个防御组合。
- 单独辅助卡与同阶段组合共享行动位：己方回合二选一进攻，对手攻击时二选一响应。
- 防御准备不扣费、不锁定能量；只有实际发动防御动作时才扣费。

## 原子结算顺序

一次攻防交换按固定顺序执行：

1. 验证参与牌属于正确区域、满足字段条件并且当前能量足够。
2. 原子扣除动作费用，将参与牌移动到弃牌区。
3. 按动作记录中的稳定顺序结算参与牌的基础效果；当前枚举器按卡牌 ID 排序。
4. 组合动作再按数据表顺序结算组合效果；单卡动作到此结束。
5. 若防守方响应，以相同步骤结算准备区中的单卡或防御组合。
6. 先从攻击伤害中扣除 `block`，再由护盾吸收剩余伤害，最后扣除血量值。
7. 防御准备区中未使用的牌返回手牌。

所有步骤在状态副本上完成；任何条件不合法时，整次交换回滚，不消耗牌或血量。

`pay_health` 直接扣除自身血量值、无视护盾，并且支付后必须至少剩余 1 点。回复不能超过 30 点血量上限。

第一版沿用“所有辅助卡基础效果都会结算”的已确认原则。因此攻击属性牌参与防御组合时会反击对手；防御属性牌参与攻击组合时会先给自己增加护盾。这是显式测试假设，后续可以根据试玩结果修改。

## 持久组合

- 持久组合消耗参与的辅助卡，场上只保留结构化状态，不保留牌本身。
- 每位玩家最多拥有 3 个持久状态。
- 第一批持久状态在玩家自己的回合开始时触发，共触发 2 次。
- 同名状态不叠加；再次生成时刷新为 2 次触发，不占新槽位。
- 持久组合只在建立或刷新状态时收费；状态后续触发免费。
- 第一批持久效果只允许回复或增加护盾，禁止递归生成状态或额外行动。

以下数值只是便于比较的 `v0` 测试基准。辅助卡基础效果需要另行加到组合收益中。

| 核心卡 | 组合 | 分类 | 费用 | 字段条件 | 组合效果 |
| --- | --- | --- | ---: | --- | --- |
| 羊 | 三羊开泰 | 持久防御 | 1 | 羊 x3 | 抵挡 2；随后两个己方回合开始时各获得 1 护盾 |
| 羊 | 亡羊补牢 | 瞬时防御 | 2 | 羊 x2 + 牢 x1 | 支付 2 血量，获得 6 护盾 |

| 羊 | 顺手牵羊 | 瞬时攻击 | 2 | 羊 x1 + 手 x1 | 造成 2 伤害，回复 2 血量 |
| 舟 | 破釜沉舟 | 瞬时攻击 | 3 | 釜 x1 + 舟 x1 | 支付 3 血量，造成 7 伤害 |
| 舟 | 顺水推舟 | 瞬时防御 | 2 | 水 x1 + 舟 x1 | 抵挡 2，回复 2 血量 |

## 数据和代码

- `data/auxiliary_cards.json`：20 张辅助卡模板及其属性、字段、基础效果和单卡费用。
- `data/core_cards.json`：两张核心卡、8 个结构化组合及其整体费用。
- `data/decks.json`：两套 20 张测试卡组。
- `combat_lab/matcher.py`：字段多重集合匹配。
- `combat_lab/engine.py`：原子攻防结算和持久状态触发。
- `tests/`：数据约束、字段匹配和结算测试。

## 运行

在本目录执行：

```powershell
python -m combat_lab validate
python -m combat_lab show
python -m combat_lab analyze
python -m combat_lab enumerate --core sheep_core --nature attack --cards lamb_charge,tiger_pounce,wool_guard,guiding_hand
python -m combat_lab simulate --games 1000 --seed 20260821
python -m combat_lab simulate --games 1000 --seed 20260821 --energy-capacity 3
python -m combat_lab simulate --games 500 --seed 20260821 --combo-cost break_pot_sink_boat=4
python -m combat_lab simulate --games 100 --seed 20260821 --json
python -m pytest -q
```

`analyze` 会精确枚举 20 张卡组的全部四张起手和五张可见牌组合，报告每个成语以及任意攻击/防御组合的可达率。它只测字段供给，不把费用、出牌策略或此前回合已经消耗的牌计入结果。

`--energy-capacity` 用于覆盖每个攻防周期的能量容量。`--combo-cost COMBO_ID=COST` 可重复传入，在不修改数据文件的情况下扫描一个或多个组合的 1–4 费变体。覆盖值仍会经过目录校验，未知组合和范围外费用会直接报错。

## v0 字段可达率基线

当前两套卡组用于覆盖所有规则路径，字段密度有意偏高，不能视为平衡结果：

| 卡组 | 可见牌 | 任意组合 | 任意攻击 | 任意防御 |
| --- | ---: | ---: | ---: | ---: |
| 羊 v0 | 4 | 99.7% | 89.5% | 82.6% |
| 羊 v0 | 5 | 100.0% | 94.9% | 96.3% |
| 舟 v0 | 4 | 99.7% | 95.4% | 99.7% |
| 舟 v0 | 5 | 100.0% | 98.3% | 100.0% |

单组合四张起手可达率为：三羊开泰 65.7%、亡羊补牢 54.3%、羊入虎口 62.0%、顺手牵羊 62.0%；破釜沉舟 62.0%、顺水推舟 79.0%、同舟共济 99.7%、逆水行舟 79.0%。

这表明当前 `v0` 更适合验证结算与组合选择，不适合检验“凑成组合”的稀缺感。下一批卡组应在不改变八个组合定义的情况下减少核心字段密度，并比较组合可达率、无组合手牌比例与基础效果损失。

## 胜率模拟模型

每局采用以下测试规则：

- 双方洗牌后各抽 4 张，并在首回合前准备一个可用防御组合或单卡响应。
- 每个己方回合开始时将能量重置为 4，免费触发持久状态，再抽 1 张。
- 手牌上限为 7；超出时，AI 优先弃掉对当前合法组合数量影响最小的牌。
- 每个回合最多选择一个攻击组合或一张单独辅助卡；对方最多从公开准备区选择一个防御组合或一张单独辅助卡。
- 防守结束后，准备区中未使用的牌返回手牌。
- 当前玩家回合结束时，从剩余手牌中准备下一次防御组合；模拟器只准备一个组合所需的材料，因此最多三张。
- 每位玩家最多获得 12 个回合。有人血量归零时结束；否则比较血量，血量相同则平局，护盾不参与终局比较。
- 攻击、防御和单卡动作都支付同一份周期能量；费用不足的动作不会进入合法枚举。

启发式 AI 会枚举全部能量合法的组合与单卡动作，预演对方的所有公开防御回应，再选择估值最高的结果。进攻估值会计入留给下一次防御的剩余能量；防守方同样在“不防御”和所有合法防御之间比较。准备防御时，AI 会权衡防御效果、占用牌数、失去的攻击组合数量与当前可支付费用。

提供三种估值画像：`balanced`、`aggressive`、`defensive`。可靠结论应在多种画像与多个随机种子下方向一致；只在单一画像中出现的优势应视为策略偏差。

批量模拟会交替先手，并报告胜/负/平、将平局按 0.5 计入的对局得分率、95% 置信区间、平均局长、击倒率、无进攻动作率、组合/单卡使用次数，以及平均进攻费用、防御费用和进攻后保留能量。进攻单卡率、防御单卡率和无进攻动作率都以该玩家实际获得的己方回合数为分母，便于跨卡组和策略直接比较。使用 `--json` 可以获得结构化结果。

当前费用模型的首轮结果见 [`reports/2026-08-21-v1-energy-baseline.md`](reports/2026-08-21-v1-energy-baseline.md)。报告中的胜率是明确规则、固定卡组和指定启发式策略下的条件胜率，不等同于真人环境胜率。
