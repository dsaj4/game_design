Use case: ui-mockup
模板：UI Screenshot System / UI 截图系统（ui-screenshot-system），游戏桌面UI设计评审效果图。
为中文单机法术编排游戏《言咒》制作一张精致、清晰、可供评审的高保真UI效果图。横版16:10，高分辨率。是一块完整的UI设计展示板，不是照片，没有设备边框，没有真实桌面或人物手部。
画面上方约75%是一张大的“展开视图”游戏界面；下方约25%是一张宽而紧凑的“折叠视图”局部对照。上下两部分是同一布局的两个显示状态，不是需要在游戏里同时打开的两套面板。主要视觉必须是时间轴卡牌，而不是战斗场景插画。

美术：克制、成熟的法术书桌UI。暗色石墨面板、暖纸色牌面、精细金属边线、少量火焰琥珀和冰青色元素图标，柔和间接光；大量清楚的留白，文字高对比。东方文字法术的气质，但不堆砌书法、符咒、山水或武侠人物，不做紫色霓虹科幻仪表盘。小插图精致但不抢信息。整齐的二维正视图，卡面无透视缩小，仿真实游戏截图的专业完成度。

展开视图：
1. 顶栏左方标题“言咒”，次级文字“时间轴铺卡战斗”。右方状态“战前编排”，开关“展开 / 折叠”。
2. 主内容左侧约16%宽是法杖身份栏，右侧约84%宽是共享时间格。时间从左到右，8列清晰标“01 02 03 04 05 06 07 08”。每列垂直对齐敌方与所有法杖行。
3. 最上方是一行“敌方行动”。8张深色背面卡牌，保留未知；第04列牌背上可见小标签“进攻”，第02列小标签“准备”，不是翻开的敌方法术。其余只显示简洁牌背纹理与小问号。敌方信息与己方视觉上分区，但共同刻度。
4. 下方是“己方法杖”，准确4行，“法杖 A”“法杖 B”“法杖 C”“法杖 D”。每行左侧放一支短小漂亮法杖图标、法术名、很小的词卡组合条，旁边可有“编辑法术”小按钮。每行绑定一个法术，重复牌面应一致，空档有淡格背景。
法杖A：“火焰术”，小词条“释放”“火焰”，只在01、04、07列放同样的浅色火焰卡。
法杖B：“护甲术”，小词条“获得”“护甲”，只在02、04、06、08列放同样的浅色盾牌卡。
法杖C：“冲击术”，小词条“伤害”“敌人”，只在03、06列放同样的浅色冲击卡。
法杖D：“强力法术”，只在05列放一张特别醒目的金边卡，在该卡角上标一个清楚的小徽标“独占”。只展示独占属性，不画封锁敌方、不画其他牌被取消、不确定独占影响范围，不跨多列占格。
5. 第04列有一条精致的竖向浅金预览线，上端小字“预览 04”，让同刻法杖A和B两张牌明显垂直对齐，同刻并行；不要画谁先谁后的箭头。
6. 展开视图底部薄操作条，短提示“构造法术 · 自动生成时间轴”，主要按钮“开始战斗”。不要出现抽牌、结束回合、战中换牌、拖动行动牌、联网聊天或商城。

折叠视图对照：
单独小标题“折叠视图”。保持同样01–08刻度、相同顺序与事件。敌方仍是独立牌背行，玩家四行合并为一行“己方总览”。每个时点使用小卡或卡片叠层表达其法术，卡片显示来源字母A/B/C/D。04列清楚显示A与B两张小卡，06列清楚显示B与C两张小卡，05列D卡保留“独占”小徽标。折叠不隐藏同时施法数量，不把两张不同法术融合成新牌。留一个明确的“展开”按钮。

文字必须简洁、准确、可读，简体中文。大部分空间用于卡牌与时间关系，不加长段说明、不加装饰性英文、不加无关统计。不要设计详细伤害、生命、费用等数值；01–08仅为时间列。底角可用极小标签“UI 概念稿”。生成一张最终精修的设计展示图。
