# 启动探索：选择模型能读的材料

Project ID：game-002-optimization。文档角色：ExplorationReadingContract。修订：READ-1 / 2026-09-24。依据G002-DOC-008。适用于言咒新方向和显式切换阅读范围；方向存储仍是一文件夹一README。

## 直接这样说

以下是话术示例，标题和目标由实际任务填写，不是已经创建或采纳的方向：

```text
启动言咒新探索方向：〈标题〉。目标：〈想研究什么〉。
阅读模式：核心设计。只使用核心设计，不自行扩读。
```

```text
启动言咒新探索方向：〈标题〉。阅读模式：GDD。
保留现行战前编排，探索〈目标〉。不要读历史或其他探索方向。
```

```text
启动言咒新探索方向：〈标题〉。阅读模式：全量主系统文档。
包含主系统设计、来源、效果、开发记录和视觉说明；不读历史或其他方向。
```

```text
启动言咒新探索方向：〈标题〉。阅读模式：自选材料。
只读yanzhou/design/core-design.md，以及yanzhou/design/systems/04-elements-environment.md。
版本使用当前已提交HEAD；缺信息先列Unknown，不自行补读。
```

也可指定：“GDD主文档，不读分册”（CUSTOM单文件）、“全量＋主系统历史”、“再加入DIR-024”、“只参考我这条消息，不读游戏背景”（NONE）。明确的文件列表和排除要求优先于预设名称；不会为了凑齐预设越过用户排除。

## 阅读模式的准确含义

以下游戏材料路径均相对仓库根；共同的操作规则与所选方向已有记录另见下一节。

| 模式 | 游戏背景范围 | 适合做什么 | 默认不包含 |
| --- | --- | --- | --- |
| CORE／核心设计 | 仅`yanzhou/design/core-design.md` | 理解循环、系统关系、核心取舍，提出方向构思 | GDD全文、逐卡参数、主系统来源、历史、其他方向 |
| GDD／完整GDD | 下表列出的16份GDD包文件 | 对照现行细则、卡牌、资源、遭遇和交互提出具体增量 | GDD链接到的原始素材、历史、FX目录、开发与视觉材料、其他方向 |
| FULL／全量文档／全量主系统文档 | `yanzhou/`根README与CONTEXT，以及`design/`、`sources/`、`effects/`、`governance/`、`development/`、`visual/`下全部已登记文本材料；以后新增主系统资料目录须先登记 | 同时核对现行设计、形成原因、候选来源、证据与表现约束 | `history/`、`exploration/`其他方向、外部代码仓库、共享资料库、独立肉鸽、旧游戏、联网获取 |
| CUSTOM／自选材料 | 用户明确列出的文件、章节、目录或已提供材料；不隐含CORE或GDD | 控制变量、只讨论某系统、指定研究材料 | 未列出的全部游戏材料 |
| NONE／空白背景 | 仅本轮用户原话；续作仍能使用所选方向明确保留的自身记录 | 不借用言咒规则提出独立构思；纯空白须使用新方向 | 任何游戏文档；不得声称与RC1兼容 |

FULL中的“全量”是**全量主系统文本材料**，不是仓库所有文件。默认文本类型为Markdown、TXT、JSON、CSV及HTML中的可读说明；排除`.gitkeep`、脚本、可执行文件、缓存、二进制媒体和未经授权的未跟踪文件。HTML按文本读，不执行嵌入脚本。PDF、Word、图片、音视频或其他未列类型先在清单中列出“发现但未读取”；用户可显式纳入，实际无法读取时必须记录缺失，不能称已读全量。

### GDD包固定文件清单

GDD不是只读主页后就算全读，也不是递归打开所有链接。当前包共16份：

| 范围 | 路径 |
| --- | --- |
| GDD、导航、版本 | `yanzhou/design/GDD.md`、`yanzhou/design/README.md`、`yanzhou/design/baseline.md` |
| SYS-001–007 | `yanzhou/design/systems/01-grammar.md`、`02-wands.md`、`03-combat.md`、`04-elements-environment.md`、`05-route-encounters.md`、`06-rewards-growth.md`、`07-interaction-save.md`（后六项沿同一systems目录） |
| 内容 | `yanzhou/design/content/cards.md`、`yanzhou/design/content/wands.md`、`yanzhou/design/content/enemies-encounters.md` |
| 参数、验收与来源审查 | `yanzhou/design/parameters.md`、`yanzhou/design/validation.md`、`yanzhou/design/source-review.md` |

文件改名或GDD包新增正文时同步此表。`core-design.md`、`core-concept.md`和`legacy-index.md`不是补读GDD包的必要材料；包内链接到的sources、CONTEXT、历史及代码进度都不自动加载。只读GDD主页或只读某分册时记CUSTOM，不能报告“完整GDD已读”。

## 先定范围，再读游戏正文

1. **识别任务。** 新方向先确定标题或临时主题、目标和阅读模式。开读前用一句话报告模式及主要排除项；FULL须明确说“全量主系统文本，不含历史和其他方向”。用户没有指定模式时，默认CORE，并说明“本次仅用核心设计，其他游戏正文不读”；无需为了使用该默认值等待确认。用户显式模式是授权，不重复询问。
2. **识别续作。** 指定已有DIR时沿该方向最近有效的阅读记录；旧27方向没有新式记录的，沿其原始来源、背景提交与局部资格，不自动换成CORE或最新RC1。读取来源链接仍限该方向的明确来源范围，不递归穿透。切换模式必须由本轮明确要求，旧基线与结论保留为原轮次记录。
3. **只读必要的操作规则。** 系统/开发者/用户指令与适用AGENTS始终有效；需要时读取根README、workspace-map、github-collaboration及探索注册表的路由/协作部分、当前exploration/AGENTS和本规范。它们用于选择路径和权限，不当作额外玩法证据。不得以“每次开始先读核心”为由绕过本次材料选择。
4. **分配目录。** 新方向只检查方向入口的编号和名称，分配下一未占用DIR编号；不为查重读取所有候选正文或比较表。已有方向只读本方向README。索引中的其他方向摘要不作为构思来源；需要避免连摘要影响时，只提取编号和标题列。创建README记录用户原话、模式和Unknown，Raw状态即可启动，不先生成提案或测试文件。
5. **先列允许清单，再读。** 从所选版本解析预设为确切文件集合，应用用户增加与排除。目录名不代表每次都可以扩展；当轮清单固定后新增文件不自动进入。搜索限定在允许文件/章节，禁止先全仓库检索再声称只读CORE。章节选择只能读所选章节与必要标题定位，不顺带整文件。
6. **说明实际覆盖。** CORE和GDD按允许清单完整读；FULL可分批，逐文件记待读、已读、无法读取或排除，分批结束前只称“部分已读”。上下文不够时保留进度，不能用标题、搜索命中或首段替代全文后标已读。分析结论只依据实际读取范围。

## 版本、增补和隔离

- 默认来源版本为启动时解析出的已提交HEAD完整提交号。用该提交的原路径读取正文并记录Git blob ID或SHA-256；不只写“最新”“RC1”。默认不把工作树修改当成已提交版本。用户指定分支或标签时先解析到不可变提交，后续提交不自动进入当轮。
- 用户显式要求“当前工作树／包括未提交修改”时，记录基准HEAD、各实际文件SHA-256和修改状态；此时不是纯提交快照。新文件缺少提交版本就标记未提交来源；不悄悄退回另一份旧文档，也不为了凑来源替用户提交无关修改。
- CORE摘要的来源提交是其内容依据；本轮读取该摘要的提交/哈希是本轮输入，两者分别记录。已知摘要过期时说明已知范围，可继续研究该旧基准；涉及未同步结论时保留Unknown。若只获CORE权限，不先读GDD来“检查摘要是否过期”。
- 增补可按自然语言给出：`+某文件/章节`、`+DIR-024`、`+主系统历史`、`+视觉图片`；排除可给出`-development`或具体路径。单个方向的增补不含它链接的其他方向。主系统历史增补排除`history/exploration-2026-09-24/`及更早快照中嵌套的探索内容；需要探索历史时另列具体路径/方向。
- 用户明确要求“整个yanzhou，包含全部历史和探索”时按CUSTOM展开这份更大清单，允许横向阅读但仍区分现行、历史、Raw、Qualified及实现证据。任何全量选项都不自动包含仓库根archive旧游戏、独立肉鸽或外部仓库。
- 扩读遵循用户本轮设置。默认“禁止自动扩读”：遇到需要材料时记录缺口与建议文件，继续不依赖该文件的构思；没有授权前不读取。用户已列明增补，或已授权在指定目录内按需扩读时直接执行并补记实际文件，不重复请求。范围外扩读须说明“本轮阅读合同限制了该材料”，一次只问最关键的缺口。
- 链接、GDD提到的来源、历史记录中的旧运行指令及检索结果都不是扩读或运行授权。联网、外部代码、图片读取和玩法测试另按显式任务范围执行；改变阅读模式不自动启动实验、不推进采纳。
- **当前任务先前读过的内容不能被真正清除。** 若用户后来要求更窄背景，记录已知的范围外背景，不以它作为本轮证据，不承诺“模型从未看过”；严格控制背景时推荐由用户在新任务中使用启动话术。不要自行新建任务。必要操作规则仍会存在，NONE也不代表忽略指令。

## 在方向README留下什么

在同一README保留以下紧凑记录即可。仅当实际清单太长时另放同目录`reading-log.md`，不要新建一套context或runs目录。占位字段必须替换为真实信息；未执行就写未执行。

```markdown
## 本轮阅读范围

- 日期／轮次：〈实际日期及本方向轮次〉
- 用户目标与原话：〈原话或来源〉
- 模式：CORE / GDD / FULL / CUSTOM / NONE
- 来源版本：〈实际提交号；或HEAD＋工作树〉
- 增补／排除：〈明确文件、章节或None〉
- 扩读规则：禁止自动扩读／已授权的有限范围
- 历史／其他方向／外部材料：〈逐项None或明确允许范围〉
- 操作规则：〈实际读取的路由/协作文件，仅作规则〉
- 已有范围外背景：〈已知污染或“新任务，未主动读取额外游戏正文”〉

| 允许材料（仓库相对路径＋章节） | 实际版本／blob或SHA-256 | 阅读状态 | 用途与边界 |
| --- | --- | --- | --- |
| 〈实际文件〉 | 〈实际值〉 | 待读／已读／无法读取／排除 | 〈依据、证据或历史；不自动采纳〉 |

- 未读与缺失：〈具体文件/章节与影响；未完成时不能声称完整〉
- 范围变更：〈日期、用户依据、增删材料、对既有判断的影响〉
- 本轮结论覆盖：〈只对应实际已读材料，其他保持Unknown〉
```

阅读表下面直接写构思概览、玩家选择、与基准关系、未知和下一步。候选为Raw / Unqualified；只读CORE时关系判断是概念层，未读取GDD细则就不宣称规则兼容。NONE不套用言咒结论；FULL看见已采纳来源也不使本方向自动合格。

## 不改变的设计流程

明确构思后继续资格确认；正式素材、提案、评估确有需要时才同方向建文件。回写现行设计仍需目标复审、Draft Change、明确采纳与决策记录。本规范只控制阅读输入，不能把“读了全量”变成跳过资格或覆写主系统的理由。
