### 候选 D：两杖接句——让一次时间冲突成为有代价的协作

Candidate ID：`C-sentence-handoff-v01`。目标对象：法杖／共享槽，GDD §3、§5、§7。

**具体场景。** 一杖准备“标记敌人”，另一杖准备“伤害敌人”，两者同刻尝试开始。战前安装并明确配对一个“接句扣”：前一句放弃本次实际动作，将本次已绑定的目标身份交给后一句；后一句对该目标执行自己的伤害。没有免费先标记再伤害的双动作。

**新增规则草案。** 仅明确配对的两杖、同刻有效尝试、兼容敌人角色可接；只传一个目标身份，不传层数、效果量或成功事件。后杖仍保留自己的敌人实体、范围与合法性检查；前句需要条件词时同样付实体及时间成本。接句占一个可换镶嵌槽。选择前句目标时使用原有实例／合法条件，不额外获得最低生命之类免费排序。

**玩家取舍。** 用低频选择句为更重要的后句提供特定目标，后句本身省去重复放置某些条件词的成本；代价是牺牲前句那一次动作、占用一根出战杖和组件槽，并且需要制造可控的同刻相遇。错开时两句各自执行正常法术。若后句无合法对象，已牺牲的前句不恢复。

最小示例只能说明身份传递；普通“标记敌人→伤害敌人”未必优于已有目标绑定。只有前句承载真实稀缺的筛选词、它自身在其他时刻也有用、后句还能从较短句获益时，接句才可能值得。是否有这样的实际可达配置是本候选首要未知，不虚构必然强势组合。

**核心冲突。** 这为 INV-06／覆盖无效果新增明确例外：被牺牲的一句虽无原动作，却提供选择结果。后杖赢开始槽、取消不复活、正常周期、敌攻打断、一层触发与实体独占均需逐项复审。先限制本场一个配对，禁止接句链、接自己、复诵供接句、被第三杖覆盖后仍偷传效果。

**未知与验证。** 如何裁决第三杖冲突与已取消前句？首轮建议这两种情况接句都失败，具体条款待确认。比较“把条件直接写进攻击句／分杖接句／错开两次动作”，看是否出现真实时空与实体取舍。若只是复杂地重做现有条件选取，应放弃该机制。它不应成为修补普通冲突惩罚的免费奖励。
