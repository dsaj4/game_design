## 系统协作：每条连接传递什么

这是依据CORE重述的系统网络，不是新增规则。关系分类来自通用方法，不能充当采纳证据。

| 来源 → 接收者 | 载体／关系 | 接收规则与后果 | 限制、延迟与玩家应看见的因果 |
| --- | --- | --- | --- |
| 环境／加工产出 → 资源池 → 维护与新加工 | 材料数量／转化、争夺 | 同一份材料只能按优先次序进入一个用途；维护会延后新批次 | 维护先分，余料按杖序；显示谁占了料、谁缺料 |
| 法杖成品 → 战斗行 → 效果兑现 | 行动卡及所在阶段／阻滞 | 行满使原杖等待，后续批次不能凭名义时刻补发 | 有限队列、入行时间、同刻一张；显示等待原因 |
| 敌牌揭示 → 玩家判断 → 后续路由 | 公开威胁与尚可修改的批次／反馈 | 新信息改变未来生产选择，已承诺批次保留 | 展示预计兑现时刻及依赖，区分“看见威胁”与“来得及处理” |
| 打断生产链 → 敌牌 | 已生效的打断结果／改写 | 仅在到期前实际生效才取消；成功后留空档 | 与攻击共用生产／排队能力，不旁路免费即时执行 |
| 维护短缺 → 产物休眠 → 补料恢复 | 产物运行状态／续航、恢复 | 停用而不删除身份与增幅，补料后恢复作用 | 不把每次恢复视为新对象；具体时序待GDD |
| 胜利 → 携带选择 → 下一场生产 | 可携带资源数量／分化 | 容量取舍改变下一场可用材料 | 不带增幅与运行状态；跨战链未验，不能称已闭环 |

主要风险：维护和新加工争料导致长期停工；多杖共用战斗行造成打断迟到；调整反馈慢而不可解释；可携带资源导致下一场只剩单一最优开局。现阶段仅列风险，不判定已发生。

## 卡牌试点与Demo的候选切片

以下功能覆盖已由Q3确认；“攻击／防护”等是试点职能，不是已经存在的新词卡名称或合法句法。卡数、词义、配方、数值及独立卡牌身份仍Unknown。

| --- | --- | --- | --- |

| 专门打断 | 提前准备并留产能，还是承受威胁继续输出 | 揭示 → 判断 → 生产 → 排队 → 到期前生效 | 若必定来不及或无代价必选，修改卡／遭遇窗口 |

Q2–Q4已确认分层推进，所有实施先以确认后的卡牌与规则为依据：

1. **基础单战**：合法编排、供料、加工、交付、有限战斗行、敌情、应对、完整胜败和重新开始；能对照解释一次拥堵与一次打断结果。
2. **系统短局**：两场相连战斗，加入战间奖励、资源携带和重新编排；加入最小维护型高阶链，确认其确实改变选择。
3. **通过观察后扩展**：付费干涉具体能力、更多卡组与完整路线／商店。暂停／恢复等既有规则的Demo支持范围另在原型规格明示，不静默删改。

Q6已确认占位美术、PC单人鼠标交互及暂停；不排除GDD已有键盘等价与信息可达性要求。开发索引没有符合TL-1的新实现，具体新实现落点尚未建立。此仓库只保存设计、范围、偏差和证据；实现、构建、Bug与技术测试归对应代码仓库。Demo创建／复用时再依DA-1登记实际资产，当前未创建资产，不预占AS编号。
