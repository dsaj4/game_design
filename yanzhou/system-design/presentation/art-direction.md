## 共同画法

| 项目 | 当前基准 |
| --- | --- |
| 轮廓与器形 | 深褐、略不规则的圆墨线，外轮廓强于内部线；主体大形先于材质细节。器物古朴、手制、适度夸张；按实际显示尺寸控制线粗 |
| 色块与明暗 | 少量平涂大色块、概括的两级明暗；高光也用色块表达。玻璃、水线、炭火等必要辨识保留，避免拟真反射和琐碎体积 |
| 配色 | 暖铜、赭土、米白、灰蓝、青绿为共同色域；火焰、红芽等身份色局部突出。颜色服务物件识别，不强行把所有材料涂成同色 |
| 材质纹理 | 少量成组、顺着曲面或生长方向的短线；优先放侧缘、口沿和结构转折。法器中央保持安静，卡面背景纹样低于主体对比 |
| 细节上限 | 主体最强轮廓，纹理不能盖过剪影；不随批次添加铆钉、雕刻、饰环、复杂岩地或额外人物。按基准板同类源件比较密度，整卡示例不另算新画法 |

## 从设计参考转入生产

先沿[炼金内容手册](../alchemy/handbook.md)定位本批稳定身份、名称及来源状态，只读取目标条目与依赖。B01材料身份与配方已有资格；R05命名、R08法器／占形及其他候选不能因画成图片就视为规则已采纳。当前32个材料身份仅五种有图，余27种未生成；多版同物件不重复计数。八类法器候选也不等于八件已定版资产。

制作顺序：**锁定本批对象与用途 → 一个代表样件完成原件、派生、字体及宿主装载 → 按每批5件扩量审阅**。现有源件符合生产要求可直接复用，不要求重画；首件建议沿清泉水验证“透明物品＋适配卡图＋公共模板＋真实名称”的完整链路。此建议是生产顺序，不新增内容或玩法决定。扩量前先闭合首件暴露的共同技术问题。

| 生产项 | 当前依据与要求 | 尚需在首件／对应批次完成 |
| --- | --- | --- |
| 原件与派生 | 原PNG、原提示词、SHA只读保存；生成源、运行纹理、整卡导出分别标识 | 实际尺寸按输出记录；归一化或重构图存新版本，不能覆盖旧源或重新压包冒充原包 |
| 完整卡面尺寸 | 静态交付基准1024×1600；图窗与名称板保持02比例。参考模板原生1003×1568，图窗`(33,34,938,1077)`、名称区`(63,1166,877,333)` | 若制作标准尺寸模板，须连同图窗、标题区域一起换算并核对；原坐标不能直接套到1024画布。独立插画等比装入，禁止挤压或裁掉主体 |
| 物品／法器尺寸与定位 | 透明RGBA完整画布、完整轮廓；源件实际尺寸不同，不强制全部正方形。画布留白不等于占格 | 每项记录目标宿主、画布、锚点／pivot、可视范围及实际内容占形来源；尚无已定宿主的项只生成视觉源件，不伪称完成装载 |
| 字体 | 保留已选宋体／衬线气质和独立名称层。现样件依赖Windows系统SimSun，未携带字体文件 | 首件确定可随项目使用／分发、字形覆盖合适的字体与回退；按本批实际名称核对宽度、最小字号及溢出处理。现有仅通过五个3—4字名，不能外推完整词库 |
| 透明与边缘 | 模板图窗／外角透明；当前名称板为近不透明，源检查254/255、Godot采样253/255，不能写成严格全不透明 | 生产版明确板底是否全不透明，并在新版本实现；物品／法器在浅、深、紫底核对残边、孔洞和光晕。冻结源不为修alpha而覆盖 |
| 分层与状态 | 当前是独立文件职责：插画、框与名称底板、真实名称；不宣称PSD可编辑分层。法器铭文／激活反馈另层 | 实际工程按当前显示合同组织状态／命中／几何；如需动画、背面、选中状态或分件，另列具体任务，基础原画不烘焙反馈 |

每项最小交付记录：**内容稳定ID＋显示名／表面用途＋源AS与版本＋准确生成输入／提示词＋源文件／尺寸／alpha／SHA＋派生与宿主定位＋验收证据／未测项**。已有字段引用manifest，不再另建平行台账。独立可复用新包按[DA-1](../../../docs/demo-asset-standard.md)登记；实现与制作脚本放外部工程，文档／manifest／提示词在本仓库，二进制按现有本机保管方式继续。

## 保留的制作经验与验收

- 先让题材直接可辨。旧护盾曾误成手抓圆球，水流与风线也容易混淆；具体材料的识别修正留在物品制作页。
- 细小刻纹、复杂铜边、碎纸纹和人物互动会争夺主体；短线成组，法器大面留白，卡面环境降对比。
- 分件会额外要求切口、遮挡面和对齐，宽白光晕会洗掉材质。选定当前画风不延续旧拼接／骨骼方案；后续动画按独立任务实现，基础图不烘焙生产亮光。
- 旧题签、装饰环和固定效果栏不再作为绘画模板。插画无字不等于隐藏必要信息；真实文字使用字体排字，显示职责沿现行合同。
- 保留原画布与PNG字节；宿主等比contain，复用纹理，按接入需求配置无损与mipmap。不把图片比例、留白或alpha当作点击几何。
- 每批用深浅背景和实际小尺寸核对：法器224／64px，独立物品152／64px，整卡放入155×229宿主并看96×150缩图；主体、器形与物品—卡图身份一致。宿主contain产生的边距允许存在，不能把宿主宽度误写成实际绘制宽度。
- 源件核对、原生预览、实际宿主接入、玩家辨识分别报告。当前02已保留Godot独立合成证据；新基准板只检查分组、背景、缩图、剪影及浏览器显示，没有重跑Godot或玩家测试。

本轮基准源图、既有运行副本与交付ZIP指纹均保持；[02基准板清单](E:/Project/yanzhou-ui-prototypes/ways-art-baseline-2026-10-31/production-v02/review-manifest.json)固定实际18个引用的路径／尺寸／SHA，[浏览器检查](E:/Project/yanzhou-ui-prototypes/ways-art-baseline-2026-10-31/production-v02/browser-qa.json)记录本轮范围。**已确认：共同画风、物品／场景卡图区分、02完整卡面版式。待生产验收：正式字体、统一模板派生、透明边缘、小尺寸质量、实际内容占形及主工程接入。** 历史checks中的PendingReview表示当时状态，当前视觉选择以本页及02 manifest为准。
