# 交互与保存：规则

2026-10-23 · CurrentSpec / CORE-065 round-hand.1。[采纳依据](../../../sources/draft-changes/D-2026-10-23-round-hand-settlement.md)。CORE-064的收尾与恢复原则保留，当前生产拍／结算列／回合末按本页限定；旧EX-002与3D合同只在其旧版范围有效。新2D宿主仍待PRE2D-Q01，实现与检查统一见[开发入口](../../../development/README.md)。

## TL-31 战前配置与可表达性

用真实库存装配核心／可选辅槽，设战前法器序、基础路由、已有用途和本场投入；未投入材料留背包，本战不可取用。至少一台完整合法铭刻法器才能开始，缺核心、不兼容、重复占用或悬空引用先修复；空辅槽、暂缺料或无直接伤害不单独禁止开战，基础加工不能代替铭刻门槛。

初态须凭真实库存和公开供给支持可执行路线，零材料可无启动料；不赠虚构实体、不靠彩蛋、不每战补满。跨战保留配置偏好仍须重核实体、资源和目标，不自动改绑同名实例。新首场的完整敌表与初态尚未冻结，不把机制就绪写成整战内容就绪。

## TL-17 暂停与信息

生产拍观察窗口沿[TL-11](../../systems/action-card-system/rules.md#tl-11-共同拍序与效果边界)受理原免费设置，关闭后新输入待下一个合法受理窗口复查。收尾中的付费整理不预扣、不自动排队，停稳后才提交。最终整理作为额外受理窗口：先接收此前合法待受理的免费输入，再接受新提交，按提交先后复查；过期／失格操作整项拒绝，显示实际受理位置，不偷偷改数量。

结算启动前处理已提交且合法的最终整理输入；启动提交之后，包括列间暂停和回合末阶段，所有玩法编辑关闭，不缓存为下轮自动付费或锁解。设置与只读详情仍可用。

### 拍末暂停（CORE-064）

CORE-065沿用“收尾已经进入的单位及动画再停”，区分如下：

| 当前状态 | 请求暂停／详情／设置／失焦／正常退出 | 单步 |
| --- | --- | --- |
| 第0拍就绪 | 已停，不自行开工 | 完成第0拍首次开工及动画后停，不走第1生产拍 |
| 生产拍推进中 | 收尾本生产拍的完工、合法开工及音画后停，下一生产拍不开始 | 从拍末完成下一生产拍后停；第X拍完成后进入最终整理 |
| 最终整理 | 无时限，保持停住，可合法整理与免费设置 | 须明确启动结算；以单步启动时只完成第1列再停，不重复执行第X生产拍 |
| 结算列推进／列间暂停 | 完成当前列及动画后停，未开始下一列；只读、设置可用 | 完成下一列后停，列间不加工，不开启玩法编辑 |
| 第X列已完成、回合末待处理 | 保持停住，尚未处理的疲劳不能抢跑 | 仅处理回合末疲劳（若到期）、结束及下一轮准备后停，不走下一生产拍 |
| 回合末事件处理中 | 完成该事件和必要清理后停，不开始下一生产拍 | 完成尚未结清的回合末阶段后停 |

每列停点在回合末疲劳之前；疲劳不是第X列的卡效。连续播放时列X后接回合末阶段，未终局才清旧行、布下轮敌牌、重置点数各一次，再推进下一生产拍；若有暂停／单步则停在对应边界。最终整理每回合仍须明确确认，不以“继续播放”越过尚未确认的新最终整理。

任何终局立即停余步骤，仅播放已发生结果，不为凑拍／列／回合补收益。重复暂停或单步不积累额外推进。收尾动画只延长现实等待，不增加逻辑时间；环境／加工循环在停点冻结，静音与减动效仍生效。异常恢复不是正常暂停点，见TL-19。

| 对象 | 必须可查 |
| --- | --- |
| 时间／桌面 | 回合、累计生产拍、当前阶段／结算列；固定X位，实牌、空位与只读已结算结果明确区分 |
| 手牌／操作费 | 卡的来源、内容、顺序、是否可用；H上限、最右超限移除、剩余行动点及每项费用 |
| 法器 | 当前承诺、未来用途、配方、冻结D、进度、完工生产拍、等待原因与可能溢出；不显示不存在的容量预留 |
| 敌情 | 原生暗牌的合法牌背信息；已生成后续牌的完整效果、可用回合、顺序与锁定／无对象，不重新隐藏 |
| 资源／标记 | 实有、可消费、锁定、托管／合法冻结、待用及可用生产拍；未采用的扩展不摆空账目 |
| 结果 | 生产完成与卡效生效分开；失败、溢出、打断、空放、费用拒绝和终局停止均说明原因 |

### 玩家消费锁定与预警（CORE-055）

资源与标记共用免费库存分配：锁住自有未承诺数量则自动消费者不能花，解锁恢复后续合法消费资格，不提前执行效果或补做失败。生产观察及最终整理可受理；最终整理的锁定影响随后本轮卡效支付，用途影响之后的开工，不撤回第X拍已形成承诺。

锁定不作用敌方或未来新增量，不撤销托管／冻结，不阻止伤害、合法失效或非消费读取。冻结量不能供其他批次或卡效使用。结算一经启动，不得在列间锁解以选择哪张牌付费；只按启动前已受理的设置和真实余额执行。

预告显示预计消耗、可用与锁定以及失败／溢出风险；未兑现依赖不是已到账资源，不逐批要求确认。未迁移的维护内容不能借共用锁定提前启用。

## TL-18 付费整理与干涉接口

当前每回合整理行动点为3，回合准备重置而非累加；不是金币、标记或制造材料。自动生产、自动入区、超限移除、暂停、原免费路由／用途／阶级／锁定不收该费用。每次成功操作如下：

| 操作 | 前提与结果 | 费用 |
| --- | --- | --- |
| 桌面互换 | 任意两张不同且未执行的己方桌面实牌交换位置；不能拿空位或结果记录交换 | 1点 |
| 桌面与手牌互换 | 选各一张，分别占对方原位置；手牌数不变，不先追加第四张再丢牌 | 1点 |
| 手牌补入 | 选已有手牌放桌面最左空位；手牌空隙闭合、其余相对序不变 | 1点 |

只在生产拍停稳后或最终整理受理，不在运行动画中插入；运行中操作先请求正常暂停，停稳后核对实际状态再提交。全部前提及足额点数满足才共同改变位置和扣费；不足、对象失格、同牌互换均整项拒绝不扣费。成功后改回是另一付费操作，不退款；未提交的选择／草稿可放弃，不改变牌或费用。

整理不改牌身份、内容、来源与卡效费用，不催熟法器、不复制、不额外抽牌，不开放免费手牌调序或丢牌。后续卡效仍按TL-30支付。无手牌／无空位不允许补入；未完成批次不可作为手牌。

未定义的其他提速、停机、改速干涉仍归TL-Q09；旧“所有干涉每战固定费用”不适用于已采纳的每回合整理。暂停本身不开放单器启停、战中重铭或打造。

## TL-19 中断与恢复

正常退出先完成当前已进入的生产拍／结算列／回合末事件及表现，已有停点直接保存退出；不主动确认最终整理或进入下一单位。异常中断只保留最近结清事件和已提交操作，静态载入且暂停；明确继续才完成余步，不自动补跑到停点、不重播旧音画。

| 保存对象 | 必须保持 |
| --- | --- |
| 时间与阶段 | 当前规则版本、回合、累计生产拍、最终整理是否确认、列／组／步骤、末尾疲劳与换轮准备是否已做 |
| 卡与牌位 | 双方桌面各位置、已执行／取消记录、玩家手牌相对序、敌后续手牌、来源与承诺内容、绑定名单、生成序和资格回合 |
| 费用与余额 | 已付行动点、剩余点数及本轮重置事实；制造托管／消费、标记真实／锁定／冻结／待用、生命护甲及疲劳次数 |
| 批次与设置 | 当前用途、D、进度、材料归属、未来用途与供料、唯一临时方案及结束生产拍；无预留／待复用容量 |
| 敌表与公开 | 本轮基础表位置、被跳过项、后续覆盖、原生揭示范围、锁定法器／无对象；不读档重抽、补发或重锁 |
| 输入与结果 | 合法已提交但待受理的免费输入，付费成功事实，暂停请求、终局与奖励／选留提交；结算时被拒操作不能在下轮自动执行 |

恢复不返行动点、不重复制造／伤害／释放／疲劳、不重新布牌或重置行动点，不提前让待用量可用。单步恢复只完成所在单位余下合法步骤；异常事件内部不是重新选择点。终局恢复保持同一清理完成的结果，未完成的确定性清理不形成新选择窗口。

旧连续拍存档与当前回合规则不是同一种进度，不默默换算旧Q、倒计时或牌序续打；版本不匹配必须保留原存档并说明，迁移方案未定不冒充可恢复。真正战终才沿[经济](../run-economy/rules.md)清理／选留，不因暂停触发战后重置。

## TL-36 决策保存与信息可达性

保留一份进行中本局存档，设置独立；节点选择、交易、休整、开战、整理付费、最终结算确认及战果等已提交事实保持，不重抽退款。保存失败保留同一结果重试并停止后续不可逆提交；读档失败不覆盖或新开局。新局替换／主动放弃说明后果并确认，普通草稿不逐步审批。

详情／设置／历史运行中先请求本页停点，关闭仍停、焦点回来源；失焦收尾后返回不自动继续，同进程草稿保留，关闭才丢未提交草稿。点击和键盘可完成必要操作，不只靠拖拽、悬停、颜色或声音；静音／灰度／减动效仍能判断费用、威胁与结果。动画不决定规则时间和胜负。

桌面固定显示完整X位，不随中心线滚动。结算或取消后保留原位只读结果，下一回合清行；历史是只读，不成为库存或可再次执行的牌。暗牌详情、历史与预测不得泄密；已公开后续牌不能再隐藏。类别仍为▲攻击、■防御、⊘打断、✱其他并配文字，时间行为标识另列。

## 资源用途、背包与预告（CORE-058／059）

未来用途与指定阶级沿[TL-06](../../systems/artifact-system/rules.md#tl-06-路由与临时设置)，材料与背包沿TL-43／25。铭刻预设空缺与实际配方资格分开，材料与目标说明不提供任意改写能力。发现与知识保存仍待INS-Q07。

## 首场战斗操作合同（CORE-060）

此ID原合同只适用旧EX-002。其0拍揭示、r8自动暂停、7／5显示列、每拍秒数和旧键位，按[固定旧版合同](https://github.com/dsaj4/game_design/blob/084e529e2c852d2e1a508f74a8766e55763f9933/yanzhou/design/common/interaction-save/rules.md#首场战斗操作合同core-060)取证，不直接作为CORE-065的新首场交互输入。新回合的停点、费用和可达性以本页TL条款为准；具体新2D宿主及制作参数待定。

## 首场表现与声音合同（CORE-061）

旧限定参数按[同一旧版](https://github.com/dsaj4/game_design/blob/084e529e2c852d2e1a508f74a8766e55763f9933/yanzhou/design/common/interaction-save/rules.md#首场表现与声音合同core-061)保留。当前沿用：按已结清结果呈现一次、不重播旧事件，静音／减动效可读，停点冻结循环；收尾单位改由本页生产拍／列／回合末事件确定，不抄旧“全部同拍行动”算法。

## 首场主窗口失焦与返回合同（CORE-062）

沿用失焦请求收尾、返回不撤销暂停、保留同进程有效草稿与选择、不补离线时间；当前收尾单位见TL-17。显示设置超时独立于游戏逻辑暂停，不因失焦自动确认。旧EX证据不证明新列／回合停点已实现。

## 首场桌面3D主交互合同（CORE-063）

physical-table.2仍只约束旧EX-002三维表现，全部原件及约束见[固定旧版](https://github.com/dsaj4/game_design/blob/084e529e2c852d2e1a508f74a8766e55763f9933/yanzhou/design/common/interaction-save/rules.md#首场桌面3d主交互合同core-063)。CORE-065明确新机制固定整行和手牌关系，不替用户选新2D操作宿主、页面、引擎或资产。旧预留图形、r→T投影和移动时间轴不能作为新机制默认表现，其他旧三维约束不因本次规则变更自动成为新2D合同。
