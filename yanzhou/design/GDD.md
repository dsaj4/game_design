# 《言咒》核心规则

GDD-G002-FULL-001 · game-002 · 2026-10-23 · **2.6 / GDD-0，阅读版2**。这是整款游戏唯一需要连续读完的核心正文；当前制作先闭合首场。规则沿CORE-037—063与physical-table.2，文档整理不增加玩法、发行内容或运行证据。

本页是TL-04、08、10、12、13、21、24的唯一规则正文；其余段落解释整体，精确条件由所链接细则维护。细则不得暗改核心；遇到冲突先查适用范围和明确例外，再进入设计裁决，不能由实现者任选一版。版本与Accepted／Qualified范围统一见[基准](baseline.md)。

## 1. 玩家做什么

单人离线、Windows、简体中文、键鼠。玩家用实体铭文构筑能自动运行的法器：法器反复加工行动卡，行动排队后兑现攻防或资源效果；敌人按固定程序揭示倒计时威胁。玩家观察运行、读懂将来的压力，在合法窗口调整未来计划，并承担已开工承诺的后果。

目标体验是“我理解了配方、安排了工序，看到了投入如何兑现”。普通区间应能自行运行，关键调整应有可解释的收益和放弃项。这些是体验假设：若玩家只能背组合表、反复点击维持产线、分不清完工与生效，或每个局面只有同一选择，就需要重新检查设计。具体观察按任务查各系统experience页，不能把规则正确当作体验成立。

## 2. 整局与单战循环

看下一节点 → 战前装配和投入 → 自动生产、排队与战斗 → 战果及材料选留 → 休整／购买 → 下一场。路线到分叉再选，进入节点后不撤回重抽；普通失败结束本局，终点首领胜利结束本局。完整路线与内容尚未齐备，当前先制作一场。

~~~mermaid
flowchart LR
  A["战前：铭文、法器、用途、投入"] --> B["联合检查并承诺一批"]
  B --> C["处理D拍"]
  C --> D["完工入行"]
  D --> E["取得行动机会后生效"]
  E --> B
  F["敌牌揭示与截止"] --> G["观察：调整未来计划"]
  G --> B
  E --> H["完整事件后检查胜败"]
~~~

循环中只有明确提供的操作可用。暂停用于观察，不给单台法器增添停机、撤销或改速权限；玩家不会逐张点击出牌。当前可免费调整未来路由、供料先后、已声明用途、兑现材料阶级，并可锁定／解锁自有未承诺量。战中不重铭、不打造、不任意改卡效；未定义的付费干涉不提供按钮。

## 3. 七类对象怎样连接

| 对象 | 玩家需要理解的职责 |
| --- | --- |
| 铭文与核心槽 | 法器预设名词／动词空缺；全部核心填齐且语义与器具兼容才是合法铭刻。词性相同或句子通顺不保证兼容。一枚实体只装一处，循环不消耗 |
| 辅槽 | 可选修饰，挂接法器预设原词／词义，不新增核心、不选材或改目标。生产侧时间与行动量值权限由具体条款声明 |
| 法器与用途 | 运行一种合法铭刻用途，或内容明示的无铭文基础加工。同一合法铭刻可提供有限固定用途；下一批开工才锁定所选用途 |
| 资源卡 | 制造和维护的材料／产物，性质与最低阶级参与配方匹配。与实体铭文、金币和玩家干涉费用分账 |
| 行动卡 | 法器完工的产物，经玩家队列生效。每卡声明目标、步骤、支付和失败，类别本身不决定结算先后 |
| 标记 | 玩家或敌人的分种类状态，供简单条件与明示支付使用。首场区分实有、锁定与可消费；内容使用开工标记费或定时效果时，才展开冻结、待释放及未来预告 |
| 敌人程序 | 一场只有一名来源敌人，按开战固定的循环表发牌，不临时根据玩家选择改牌；打断可以依公开加工状态锁定法器 |

战前用真实库存装配、设定法器序和已有用途，选择投入材料。至少一台完整合法铭刻法器才能开战；仅有基础加工不足。暂缺材料、空辅槽或没有直接伤害不单独禁止开战。初态仍须提供至少一条公开可运行的基础路线，不能靠虚构库存或隐藏彩蛋启动。

精确装配、实体和目标绑定见[铭文TL-02／26—28／39—42](systems/inscription-system/rules.md)；实际物件见[内容合同](content/cards.md)，没有填写的能力不由名字推断。

## 4. 一批生产承诺了什么

配置、完整配方、容量和必要标记同时满足才开工；失败不部分扣料或占位，按有效供料优先级继续检查下一台。普通材料开工托管、完工消费；若内容另声明开工标记费，则开工冻结、幸存完工扣除。首场两护符没有开工标记费。明确零材料是合法配方，空白配方不是零材料。

每批只有处理耗时D，整数且至少1拍。a拍末开工，在a+D拍幸存完工；开工当拍不额外推进，没有独立冷却、完工等位或可调首次起点。D在该次合法检查中确定并冻结；处理中改变外部状态不重算本批。

开工预留本批全部行动容量。**实牌＋有效预留＋待下拍复用容量≤Q**；预留不预占未来牌序。完工按战前法器序把预留转为实牌入队，不再抢位。普通离队腾出的空位可在当拍末使用，中断回收的容量最早下拍可用。

切换未来用途、路由或阶级不改当前材料、D、产出、预留及已入行牌。临时供料仅保留一份，到期回基础方案，不恢复被替换方案。零材料护符没有可停供材料，改变优先级不等于停机。

完整检查与D公式见[法器TL-03／05／06](systems/artifact-system/rules.md)。若内容启用付费时间修饰，即使取整或最低1拍抹平收益，仍按声明收费；使用该内容时必须说明这一成本。

## TL-04 实际节拍顺延

缺料、缺位和返工推迟实际开工及后续产出，不追赶名义周期、不补发。预览分别显示开工前等待、加工、入行后排队。

## TL-08 玩家战斗行

开场无已入行牌，每格一牌。按实际入行先后排队，同拍入行按战前法器序；预留只占容量。t拍入行，最早t+1拍取得生效资格，每拍最多一张玩家牌；不保证入行下拍一定生效。

Q包括实牌、有效预留和待下拍复用容量。正常离队空位可当拍末使用。己方目标在生效时按承诺预设自动选择。

**TL-21 无合法目标：**空放离队，占本拍行动机会，不补翻、不补发、不退制造材料，也不在队首等待目标。

## 5. 一拍怎样推进

一拍是规则时间单位，与动画时长分开。第0拍先揭示／观察，再用初始库存首次开工；初始玩家行为空。

| 阶段 | 应能理解的顺序 |
| --- | --- |
| 边界准备 | 有限期状态先失效；上拍待用量释放；到期临时方案回基础 |
| 揭示与观察 | 揭示敌牌并锁定，接受本窗口操作；关闭后固定到期事件及唯一合格玩家队首 |
| 已有行动 | 先防护，再其余步骤；每组为定时效果→敌方→玩家；到期疲劳最后处理。每个完整事件后检查终局 |
| 幸存完工 | 未被中断且到达a+D的批次结清并入行，新牌不回到本拍行动阶段 |
| 维护、恢复、开工 | 到期维护→旧休眠恢复→空闲法器逐个检查一次；失败不在同拍回扫 |

“防护”只指直接护甲或明确抵挡伤害／打断的保护，治疗、加层、取消和攻击属于其余组；复合牌可能跨两组，但仍只有一次行动机会。一个完整事件是一项基础步骤及其检查／支付、结果、已获准的一层反应和必要清理，不是整张牌或整拍。

即时新增标记可供后续合法步骤使用；新资源、补给和退料最早下拍使用。未来定时预告不是实有层数，也不占普通Q；是否可用取决于已声明登记和生命周期。

实现共同排程、复合效果或保存时必须展开[TL-11完整总序](systems/action-card-system/rules.md#tl-11-共同拍序与效果边界)，不能仅凭本表实现算法。维护内部序见[资源细则](systems/resource-system/rules.md#维护与恢复次序core-057)，定时与余额资格见[标记细则](systems/action-card-system/mark-system/rules.md)。

## 6. 敌情、支付与失败

开战只公开敌牌程序位置、翻开拍r和种类；r拍才公开完整效果、正延迟Δ、T=r+Δ及目标并锁定。暗牌的外形、详情或预计位置不得泄露隐藏信息。取消不移动循环表；首版不安排敌牌同拍到期，不启用敌方护甲、防御牌、其他类牌或附属物。

指定打断在揭示时锁定剩余加工时间最长的法器，含本拍将完工者；并列按战前序。锁的是法器，T拍作用它当时的批次，因此原批次先完成不保证后续批次安全。普通生产和排队会推迟实际应对时间，正延迟不保证每个局面都有补救。详见[敌人窗口与信息](systems/enemy-system/rules.md)、[TL-09](systems/action-card-system/rules.md#tl-09-敌牌揭示与锁定)。

## TL-10 取消敌牌

只有明示取消权限的行动能取消对应敌牌；它也须经普通生产和队列，实际生效拍必须<T。T拍来不及取消。取消保留原空档，后续不提前、不补发。

## TL-12 伤害与法器中断

普通伤害先扣护甲，超出扣生命；掉血不打断法器。支付生命与疲劳是独立损耗。明确打断作用锁定法器当时的批次，按法器TL-07退料、损失进度。

到期无锁定对象、法器已消失或没有批次时，落空一次后离场，不改选、不等待、不转伤害。锁定后新开的批次也会被打断；危险开工带为[T−D,T−1]。护甲不抵挡单列打断；特殊保护按声明范围抵挡。

被打断批次丢进度且不交产物，普通材料及容量最早下拍复用；冻结标记只释放仍有效部分，不复活失效量。若另有本来可用的完整材料、标记和独立空位，当拍末可以重开。已入行牌不受来源批次中断影响。这些边界的唯一正文见[TL-07](systems/artifact-system/rules.md#tl-07-打断与返工)。

行动每一步先按同一状态检查目标、条件、完整费用与量值，成功才支付并执行。没有合法目标不付该步未付费用；不足不部分支付，不重试，不退款此前已成步骤。只有内容明示基础回退才保留基础效果。制造承诺与行动生效费用属于不同阶段，细则见[TL-30](systems/action-card-system/rules.md#tl-30-制造材料与效果支付分阶段)。

首场的施法次数只需理解：**已有多少，锁住多少，剩下多少可付。** 锁定是玩家保留不让自动消费，非消费条件仍可读取；兑现到行动生效时才付款，刚新增的层不能倒补此前失败。只有实际内容采用开工标记费，才需要区分批次冻结：冻结量不能供其他读取／支付，仍会自然失效，失效不重算D也不补扣新层。见[标记规则](systems/action-card-system/mark-system/rules.md)。

## TL-13 生命、程序循环与终局

每个完整事件后：玩家生命归零判负；否则唯一来源敌人死亡判胜。同检查点双亡玩家失败。终局停止余下步骤、完工、开工及未来登记，未到期敌牌作废，已成结果不回滚。不发牌附属物不计胜负。

未终局时固定程序循环，跨段保留旧倒计时，不重置或复制。首版敌牌到期互不重合。

**TL-24 递增疲劳：**战斗拖长后双方承受递增生命损耗，不耗护甲、不打断加工；双方同次损耗作为同一事件检查终局。[EX-002](examples/complete-battle.md#2-疲劳参数与恢复)已确定本场参数与恢复约束；跨构筑全局参数继续见[TL-Q07](../governance/questions.md)。

## 7. 暂停、恢复与信息

全局暂停冻结双方计时，落在完整事件结清边界，不能拆支付与结果。结算途中提交的用途／锁定意图留下一观察窗口复查受理；不能插入当前拍余下步骤。退出或异常后恢复最近已结清状态和已提交操作，进入暂停；不重付、不补翻、不重选目标、不重做完工，不提前释放待用量。

当前承诺、未来设置和实际结果必须能分辨。法器说明正在做什么、何时完工与为何等待；队列区分实牌、预留和待复用；敌牌按公开阶段显示；标记与资源说明可消费量、锁定及费用失败。必要信息和操作具备点击／键盘路径，不只靠颜色、声音或悬停。

首场支持自动播放、暂停、到下一观察窗口的单步及回看；新战暂停在第0拍观察，打断揭示默认自动停。OS失焦在合法边界暂停，返回仍停，明确继续才推进；恢复与单步静态显示结果、不重播旧战斗音画。逐项合同和保存字段见[交互TL-17／19／36与CORE-060—062](common/interaction-save/rules.md)。

现行CORE-063仍约束旧首场3D表现，允许绑定物件的必要只读文本。新2D方向已确认，但二维操作宿主与页面关系尚未采纳；该问题只影响相应制作，不用“新方向”推定旧合同已失效。细节按界面任务展开，不混入通用战斗算法。

## 8. 局内成长与长期边界

新局满预设生命、0金币；普通胜利不回血。法器、实体铭文和金币属于本局库存。每场胜利收益包只领取或放弃一次；材料选留另行提交，不以尚未生效的资源行动冒充已得材料。

战前投入材料进入本场；未投入者仍占背包且本战不可取用。战后将未投入、有携带资格的剩余投入及新材料一起检查种类和容量。身份、数量、阶级可保留，临时增幅、休眠、维护进度及战斗状态重置。普通耗材未完工退回参选，已完工不退。

休整恢复与拿铭文互斥；无法形成合格三候选时仅恢复／跳过。商店抵达生成固定货架，一项一件；足额支付与交付同时成立，不刷新、退款或保证配齐。细则及例外见[经济TL-25／33—35](common/run-economy/rules.md)与[路线TL-32](common/run-route/rules.md)。打造实际流程、完整获取链与容量参数仍未完成。

局外成长尚未设计，不提供永久属性或实体解锁；铭文发现和长期知识是另需闭合的合同，不能由局外占位页补成默认玩法。

## 10. 用一个场景理解

EX-001在第7拍观察改为集中兑现：6→9的普通批次继续，9拍才开兑现，12拍入行，14拍才生效。13拍打断毁掉的是后来12→15的批次；已排队的兑现牌保留。有独立空位则13拍末可重开，刚回收容量14拍才可用。

兑现生效时才检查能否支付5层；有合法目标但只有4层可消费则回退6伤害，不先扣4，且成功非终局后再记1层。9层中锁5也只有4层可消费。不同输入要重新算，不能把14拍的结果写死。

完整物件值与步骤见[EX-001 §2—8](examples/simple-spell.md#2-开战配置)。开发从[任务设计包](../development/task-pack.md)选择必要条款；人工由agent按[场景审阅规范](../development/design-review.md)讲正常、失败和代价，不要求逐页阅读细则。[验收](validation.md)只维护可判断预期，[来源](source-review.md)按需追溯。
