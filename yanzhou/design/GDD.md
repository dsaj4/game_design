# 《言咒》GDD

## 0. 文档控制

GDD-G002-FULL-001 · game-002 · 2026-10-11 · **2.2 / GDD-0**。用户负责设计决策，Codex整理。规则依据CORE-037—059；资格、采纳和证据状态统一见[基准](baseline.md)。本版保留原0—18章，改为开发阅读主线。

## 1. 产品与体验合同

单人离线、Windows、简体中文、键鼠。玩家用铭文构筑法器，让程序自动运行，在关键敌情下调整未来计划。

| 目标 | 玩家应能做到 | 失败信号 |
| --- | --- | --- |
| 配方有含义 | 用词义解释并推测组合 | 只能背表或穷举 |
| 程序自己运行 | 普通区间无需逐拍输入 | 重复点击才能维持运行 |
| 决策有后果 | 说明改动影响哪批和放弃什么 | 只有唯一固定操作 |
| 兑现清楚 | 说明哪次行动改变战况 | 完工、入行、生效混淆 |

## 2. 玩家循环

看路线与遭遇 → 战前装配／投入 → 自动生产与队列兑现 → 揭示关键威胁后调整未来计划 → 战果与资源选留 → 休整／购买 → 下一场。

## 3. 核心对象与规则入口

铭文占用配置；材料支付工序；法器产行动；行动经队列生效；标记承接持续状态与协同。[术语](../CONTEXT.md)只解释词义，具体行为查各rules页。

## 4. 系统规格

| 系统 | 开发读取重点 |
| --- | --- |
| [法器](systems/artifact-system/rules.md) | 生产状态、D公式、容量、用途、打断 |
| [铭文](systems/inscription-system/rules.md) | 核心合法性、实体占用、修饰挂接、打造接口 |
| [辅槽](systems/inscription-system/augment-system/rules.md) | 修改权限、条件与支付 |
| [行动卡](systems/action-card-system/rules.md) | 队列、敌情、总序、目标、支付、终局 |
| [标记](systems/action-card-system/mark-system/rules.md) | 宿主、余额、冻结、期限与定时登记 |
| [资源](systems/resource-system/rules.md) | 托管与消费、产出可用拍、维护、阶级 |
| [敌人](systems/enemy-system/rules.md) | 固定程序、首版内容、窗口核对 |
| [公共流程](common/README.md) | 路线、经济、交互与保存 |

局外成长暂未设计。

## 5. 状态与时序

每拍：边界准备 → 揭示／观察提交 → 已有行动 → 幸存批次完工 → 维护／恢复／统一开工。行动分防护与其余两组，每组定时→敌方→玩家。

唯一结算权威为[TL-11](systems/action-card-system/rules.md#tl-11-共同拍序与效果边界)。生产a+D完工，队列最早下拍生效；新资源下拍可用，即时标记可供后续步骤。完整事件后检查胜负，终局停止余下步骤。

## 6. 内容与数值

[参数表](parameters.md)维护共同常量及取值域；具体物件值在内容／案例中各维护一次。D与普通量值采用不同取整方式。缺失参数统一见[问题登记](../governance/questions.md)，不在正文填默认猜值。

## 7. 卡牌与组合

[内容合同](content/cards.md)规定必填字段。[EX-001](examples/simple-spell.md)是首批简易法术流：两护符、庇护／打击、迅速、三行动、一标记及炼金学徒。积蓄和资源链未进入该配置。

## 8. 经济与成长

新局满预设生命、0金币；普通胜利不回血。本局库存、一次性收益包、有限背包、恢复／拿铭文互斥、固定货架按[经济规则](common/run-economy/rules.md)。打造具体流程见集中问题。

## 9. 遭遇与路线

每场一名来源敌人，按固定循环时间表发牌；开战公开翻开表与种类，揭示后公开完整效果。首版不安排同拍到期，不使用敌方护甲、防御牌或附属物。路线按[TL-32](common/run-route/rules.md)单向推进。

## 10. 引导

首批按“合法铭刻 → 看加工 → 分清完工与生效 → 看敌牌截止 → 看标记积累与兑现 → 看中断与续开”组织。每步用案例里的实际物件和结果说明。

## 11. UI与可读性

先满足[交互规则](common/interaction-save/rules.md)的信息与操作合同。现场区分当前承诺、未来设置、实际结果；法器显示加工／空闲及原因，队列显示实牌／预留／待复用，敌情显示公开时点与目标，标记显示不同余额。

点击与键盘可达，文字配符号；暂停、静音、灰度、减动效时仍可判断。当前视觉输入与布局版本见[资产接入](../development/asset-readiness.md)；自动暂停、生命读数、播放速度及动态信息接入的剩余工作见TL-Q08。

## 12. 音画

法器体现施法工序，行动体现最终使用效果，标记用砝码表达残留。首版敌人为秘仪与炼金；地域牌组保留通用类别符号。正式意象出处及图谱页布局在UI／美术阶段处理。

## 13. 当前开发范围

以已采纳规则和EX-001明确配置做UI与规则实现对照。完整资源流派、全局疲劳、打造、付费干涉、局外成长和整局内容仍按问题表分项完成。发现与长期知识的Qualified意图需先补采纳／保存合同。

## 14. 原型与测试计划

现已进入正式开发准备；[阶段计划](../development/production-plan.md)从Unity／Godot同题评估开始，依次完成规则、界面、保存、局内循环及内容扩展。本轮未启动实现或玩法测试，按范围冻结案例与参数再验收；GDD成熟度不随进入开发自动升级。

## 15. 验收

[validation](validation.md)维护规则验收预期；各experience页维护体验观察。纸面算术、实现行为与真人体验分别记录。
