# 《言咒》核心设计

2026-10-12 · v0.21 / CORE-SUM-16。详规见[GDD](GDD.md)，状态及来源见[基准](baseline.md)。

玩家把铭文装入法器，形成能自动运行的施法配置。法器加工行动卡，行动卡进入有限队列逐张生效；敌人按固定程序揭示倒计时威胁。玩家平时观察运行，在关键时刻暂停思考，调整未来用途、供料或标记保留，承担已作安排的后果。

首场主窗口切走或最小化时在合法完整事件边界暂停，返回仍停并明确继续；保留批次、回看和同进程草稿，详见[CORE-062](common/interaction-save/rules.md#首场主窗口失焦与返回合同core-062)。

首场主页面全部操作入口由真实3D物件承担，自动运行以真实卡片入列、合法揭示／使用及离场呈现结算；必要精确值、名称和公开短提示可用绑定物件的精简只读容器。点击暂停近观说明和系统界面采用独立图形页面，详见[CORE-063](common/interaction-save/rules.md#首场桌面3d主交互合同core-063)。暂停、单步和载入保持真实静态末态，新制作与体验按各轮证据记录。

## 系统分工

| 系统 | 作用 |
| --- | --- |
| 铭文 | 配方语言与组合；法器预设名词／动词核心空缺，全部补齐并兼容才能施法；一枚实体只装一处 |
| 法器 | 执行工序和承接生产调整；每批只有处理耗时D，开工承诺材料、容量及必要标记 |
| 辅槽 | 保留核心逻辑，修饰本法器D或已有行动量值；通过共享标记形成修饰协同 |
| 行动卡 | 攻防表现与资源兑现；目标、步骤、支付与失败明确声明 |
| 标记 | 玩家／敌人的持续状态、简单条件及支付；实有与未来预告分开 |
| 资源 | 运行约束、精炼积累和环境取材；普通配方按性质及最低阶级匹配 |
| 敌人 | 固定循环程序和分阶段公开的信息，提供关键威胁 |

## 核心规则

1. 合法配置、完整配方、容量和必要标记均满足才开工。配方可以明示零材料；D≥1，每批产出行动卡。D在开工确定并冻结。
2. a拍开工、a+D拍完工并入行；入行最早下一拍生效。预留只占容量，同拍完工按战前法器序入行，每拍至多一张玩家牌。
3. 同一合法铭刻可声明有限固定用途，观察窗口选一个用于未来批次。当前批次与已入行牌不变；战中不重铭，不手动出牌或任意改卡效。
4. 敌牌揭示时公开效果、锁定目标，经过正延迟Δ到T生效。取消须在T之前；T拍已有资格的防护先结算。普通伤害不打断生产。
5. 明确打断中断指定法器当时的批次，退料、丢进度；回收容量与仍有效冻结标记下拍可用。独立可用条件齐备时可在当拍末重开。
6. 每拍依次为边界准备、揭示／观察、已有行动、幸存完工、维护／恢复／开工。行动先防护后其余，各组定时→敌方→玩家；完整事件后检查终局。
7. 无合法目标空放离队，占用本拍行动机会，不退制造材料。普通伤害先护甲后生命；同检查点双亡玩家失败，来源敌人死亡且玩家存活则胜。
8. 暂停冻结双方全部计时；恢复最近结清状态及已提交操作，保持支付、进度、敌情和队列。

## 局内成长与体验目标

路线单向前进；战斗收益、背包选留、休整和商店分别结算。休整恢复与拿铭文互斥，商店固定货架一项一件；普通胜利不回血，新局满预设生命、0金币。材料可按携带资格跨战保留身份与阶级，运行状态重置。

希望玩家感到自己读懂了配方、安排了工序，并看到投入兑现为清楚的攻防结果。普通运行无需逐批操作，关键调整应有可解释的收益和放弃项。各系统experience页保留待观察的支持与失败信号。

[EX-001首批案例](examples/simple-spell.md)保留原物件与回归；[EX-002完整单战](examples/complete-battle.md)已有本场疲劳与胜败预期，播放／回看／数量操作沿[首场合同](common/interaction-save/rules.md#首场战斗操作合同core-060)。暂停归位、单步有序静态摘要与载入不重播旧音画沿[首场表现合同](common/interaction-save/rules.md#首场表现与声音合同core-061)。操作与表现政策已采纳；运行证据见开发入口，音画实现与体验仍待验证。[集中问题](../governance/questions.md)保留扩展调度、泛化UI、跨构筑疲劳及整局内容；局外成长暂未设计。
