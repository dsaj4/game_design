Project ID：game-002。文档角色：CurrentSpec。2026-10-01 / GDD 2.0 / TL-1。结构已采纳；完整内容Unknown，体验Hypothesis / NotRun。

## 目的与玩家旅程

战前编写法术、绑定法杖并安排周期与首次起点；战中看自动生产，敌牌揭示关键威胁时暂停思考并提交允许的调整；应对结束后自动恢复基础设置，查看实际收益或返工，再继续运行。战后复盘失败原因并调整下一场。

保留Windows桌面、单人离线、简体中文和键鼠可读性要求；点击与键盘应有等价路径，不能把关键操作只放在拖动、悬停、颜色或声音中。旧观看倍速和0.5秒／刻属于待复审参数，不决定新战斗的操作压力。

## TL-17 暂停与信息

全局暂停冻结双方倒计时、加工、排队推进及资源寿命；玩家只能通过合法操作改变允许的设置，不能让己方在敌方静止时继续生产。

敌牌新揭示后，玩家须能在后续时间推进前观察和决定。本拍已完成的效果不能被后来指令撤销。暂停在完整结算边界落定，不能利用暂停切开一次扣费与结果。具体完整时序仍须SYS-003补齐。

| 区域／对象 | 必须表达的信息 | 可以支持的判断 |
| --- | --- | --- |
| 敌方行与倒计时 | 未知类型线索；揭示后的全部效果、目标、到期、打断条件 | 威胁是什么、还有多少战斗时间 |
| 资源区 | 可用、托管、待下拍可用，来源及必要维护信息 | 哪根杖缺料、改线影响哪一批 |
| 玩家战斗行 | 顺序、来源、预计生效与拥堵 | 已入行不等于赶得上截止 |
| 法杖 | 程序、基础设置、临时覆盖、进度、成品滞留及实际顺延 | 哪处被阻塞、何时自动恢复 |
| 玩家费用 | 本场额度、已付费用、合法操作费用与不可用原因 | 要不要花有限干涉机会 |
| 结果记录 | 普通伤害、指定打断、退料、无目标、行满及延误分别记录 | 为什么没有按原预览兑现 |

## TL-18 独立干涉系统接口

每场费用固定，暂不设计成长。提速使用玩家费用并允许净增产，不强制等量补休。免费输入输出路由仍遵SYS-002，只改未来未承诺批次。

保护、停杖、提速／减速等具体能力另设系统后续设计；本次不擅自给数值、价格、时长、回充、共享方式或额外免费次数。战斗行中的“打断敌牌法术”与玩家直接付费干涉是不同渠道，不能混为即时施放按钮。

## TL-19 中断与恢复

战中退出或异常关闭后，恢复**最近已结清的一刻及已提交操作**，进入暂停状态。必须保留：
- 已揭示敌牌、锁定目标、剩余倒计时与原程序位置；
- 当前生命／护甲、资源的可用与托管状态；
- 生产进度、成品、玩家队列及已承诺规则；
- 基础路由、临时覆盖及自动恢复条件；
- 本场剩余费用与已提交支付，已经成立的胜负与领取状态。

不从开头重新决策，不刷新暗牌或材料；只保存时间位置而清掉费用或恢复原配置不符合该规则。暂停期间已确认且已付费的操作也必须保留，不能因为下一拍尚未运行就免费撤销。

保存失败时说明失败，保留同一结果供重试；不虚报成功，不重新抽取既定结果。已结束战斗不能继续行动或重复领奖。旧RC1开头锁定重播已被明确替代。

布局三案、固定“现在”的运动、己牌朝向、堆叠样式与连线常显方式仍属于DIR-028的UI候选。此次确认卡牌主战场不等于确认所有UI细节；发布可视化也不构成设计采纳。

未来检查暂停与恢复、付费后退出、敌牌揭示后退出、行满后恢复及键盘／静音／减动效下的信息完整性。观察玩家是否能从画面比较生效时刻与截止、是否被迫日常搬卡。全部NotRun；具体UI交互在完整时序与卡表采纳后补齐。

## 战中恢复与战后携带分开

战中退出沿TL-19保存真实增幅、维护、休眠、托管和进度；不能借退出触发战后重置。真正战斗结束后按SYS-006结算可携带资源，只有种类与数量进入下场，增幅与运行状态重置。携带选择及结算提交也必须存档，不能重复领取或重新抽取奖励。
