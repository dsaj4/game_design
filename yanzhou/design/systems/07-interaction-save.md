# SYS-007 操作、展示、暂停与保存

Project ID：game-002。文档角色：CurrentSpec。2026-10-05 / GDD 2.1 / TL-1 + INS-1 / processing.2。结构已采纳；完整内容Unknown，体验Hypothesis / NotRun。

## 目的与玩家旅程

战前选法器、补齐核心铭文并选择辅槽修饰，配置基础供料与法器序，读取处理耗时；战中看自动生产，敌牌揭示关键威胁时暂停思考，用一份临时方案调整未来供料的去向／优先级并指定结束拍，以换取攻防或避开打断；到期分料前自动恢复基础方案，查看实际收益或返工，再继续运行。新方案替换旧临时方案，不叠加恢复层。战后复盘失败原因并调整下一场。

保留Windows桌面、单人离线、简体中文和键鼠可读性要求；点击与键盘应有等价路径，不能把关键操作只放在拖动、悬停、颜色或声音中。旧观看倍速和0.5秒／刻属于待复审参数，不决定新战斗的操作压力。

## TL-31 战前配置与可表达性

战前按“实际持有铭文与法器→补齐全部核心空缺并检查语义／兼容→可选辅槽修饰”编辑，同时设置法器序和合法基础路由；不再提供独立周期、冷却、休歇或首次起点S设置。唯一处理耗时D由内容声明，取正整数拍。默认配置可以帮助起步，但不能生成免费铭文、法器或耗材。至少配置一个完整合法法器才能开始；核心未补齐、语义／兼容非法、实体重复占用或悬空实例引用须先修复。未启用的空法器不算有效配置；辅槽可以留空。

语法合法与当前有料分开：当前缺料、条件暂不成立或没有直接伤害，不单独成为禁止开始的理由；可提示当前无产出／尚未满足条件，不替玩家判定必败而锁住开始。反之，设计初始库存和遭遇时必须能用真实拥有的实体、允许的资源初态与供给链编出至少一条可执行基础程序；只有名词、动词数量够不算满足可表达性，还须符合实际法器的预设词义与槽位兼容。

跨战可保留程序与配置偏好，但按新场实际库存、资源和目标重新检查；旧战实例失效不自动改绑同名对象。初始可表达性是内容设计责任，不承诺每个合法配置都强、安全或必胜。

## TL-17 暂停与信息

全局暂停冻结双方倒计时、加工、排队推进及资源寿命；玩家只能通过合法操作改变允许的设置，不能让己方在敌方静止时继续生产。

敌牌新揭示后，玩家须能在后续时间推进前观察和决定。本拍已完成的效果不能被后来指令撤销。暂停在完整结算边界落定，不能利用暂停切开一次扣费与结果。具体完整时序仍须SYS-003补齐。

| 区域／对象 | 必须表达的信息 | 可以支持的判断 |
| --- | --- | --- |
| 敌方行与倒计时 | 未知类型线索；揭示后的全部效果、目标、到期、打断条件 | 威胁是什么、还有多少战斗时间 |
| 资源区 | 可用、托管、待下拍可用，来源及必要维护信息，当前供料优先级与基础顺序 | 按有效优先级同时检查材料和容量；哪一批满足条件、哪一批本次跳过 |
| 玩家战斗行 | 实际牌序、来源、入行拍及最早可翻开拍、预计生效；已入行牌／有效预留／中断后待下拍复用的容量分别可查 | 预留不占未来牌序，入行后最早下拍翻开；待复用容量不是当前空位 |
| 法器 | 核心缺项与兼容、辅槽预设修饰关系、对应行动及制造要求；基础方案、唯一临时方案及结束拍、进度与本批预留；缺料／缺位等待 | 新临时方案替换旧方案，到期回基础；配置是否成立、缺料还是缺位 |
| 玩家费用 | 本场额度、已付费用、合法操作费用与不可用原因 | 要不要花有限干涉机会 |
| 结果记录 | 普通伤害、指定打断、退料、无目标、行满及延误分别记录 | 为什么没有按原预览兑现 |

## TL-18 独立干涉系统接口

每场费用固定，暂不设计成长。提速使用玩家费用并允许净增产，不强制等量补休。免费合法路由调整仍遵SYS-002，只改未来未承诺批次的供料去向和优先级；开工调时先仅由供料间接实现，不提供独立调时按钮。

保护、暂停法器、提速／减速等具体能力另设系统后续设计；本次不擅自给数值、价格、时长、回充、共享方式或额外免费次数。战斗行中的“打断敌牌法术”与玩家直接付费干涉是不同渠道，不能混为即时施放按钮。

## TL-19 中断与恢复

战中退出或异常关闭后，恢复**最近已结清的一刻及已提交操作**，进入暂停状态。必须保留：
- 已揭示敌牌、锁定目标、剩余倒计时与原程序位置；
- 当前生命／护甲、资源的可用与托管状态；
- 处理进度、每批有效容量预留、中断后待复用容量及可用拍、玩家队列的实际顺序和入行拍／最早翻开资格、已承诺规则；
- 基础路由／战前法器序、当前唯一临时供料方案及其优先级和结束拍；已被替换的旧临时方案不作为待恢复方案；
- 本场剩余费用与已提交支付，已经成立的胜负与领取状态。

不从开头重新决策，不刷新暗牌或材料；只保存时间位置而清掉费用或恢复原配置不符合该规则。暂停期间已确认且已付费的操作也必须保留，不能因为下一拍尚未运行就免费撤销。

保存失败时说明失败，保留同一结果供重试；不虚报成功，不重新抽取既定结果。已结束战斗不能继续行动或重复领奖。旧RC1开头锁定重播已被明确替代。

## TL-36 决策保存与信息可达性

保留一个进行中的本局存档，设置独立保存。节点选择、商店成交、休整方向与抽出的候选、铭文选择／放弃、已确认铭刻配置、开战、战果和奖励／携带提交均是需记录的决策边界。战中沿TL-19记录最近结清时点及所有已提交操作，不回到开场重决策。

保存失败明确报错，保留同一结果供重试，并停止接受后续不可逆提交；读档失败不自动覆盖存档或新开一局。新局替换进行中存档、主动放弃本局需清楚确认后果；普通可撤编辑不增加逐步确认。已结束本局不伪装成仍可继续的战斗。

设置和说明面板打开时暂停战斗，关闭后维持暂停直到玩家明确继续；画面播放与动画不改变逻辑支付、截止和结算结果。预览须区分已承诺与依赖未来条件的结果，不把预测表现成已发生。

详情可通过点击与键盘获取，不能只靠悬停；退出弹层后焦点回到来源。字号调整、滚动不遮挡关键操作；减动效、关闭闪烁／震动以及静音时仍能辨认威胁、成本和结果。这里复用操作与可达性约束，不采纳某个UI布局、倍速或每拍秒数。

## 展示状态与验收

DIR-028及其他旧UI候选已于2026-10-04随探索退役，具体布局和运动方式后续重新设计。已采纳的卡牌主战场、信息职责及可达性要求继续有效；发布可视化不构成设计采纳。

未来检查暂停与恢复、付费后退出、敌牌揭示后退出、行满后恢复及键盘／静音／减动效下的信息完整性。观察玩家是否能从画面比较生效时刻与截止、是否被迫日常搬卡。全部NotRun；具体UI交互在完整时序与卡表采纳后补齐。[CORE-052](../../sources/draft-changes/D-2026-10-05-production-queue-interfaces.md)已明确预留只占容量，展示不能把它画成已固定的未来牌序；恢复不能提前翻开、提前复用容量或复活旧临时方案。

## 战中恢复与战后携带分开

战中退出沿TL-19保存真实增幅、维护、休眠、托管和进度；不能借退出触发战后重置。真正战斗结束后按SYS-006结算可携带资源，只有种类与数量进入下场，增幅与运行状态重置。携带选择及结算提交也必须存档，不能重复领取或重新抽取奖励。

## 铭刻与打造的操作边界

完整暗句不作为自由构句编辑器暴露；玩家仍需能理解可填的名词／动词、器具兼容限制、辅槽预设修饰位置，以及对应行动与制造成本。材料说明供读取与供料判断，不是材料类别输入槽；卡效目标说明不成为核心目标槽。具体展示布局与隐藏程度仍待设计。

暂停只冻结时间，不自动开放重铭、打造或免费改写已承诺批次。允许打造的时机尚未决策；后续若确定打造提交，保存须保留同一已提交结果及支付，不能重领／返费。该提交要求不决定打造的跨战／跨局持久范围。
