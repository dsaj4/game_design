## 已确认的价值顺序

用户在 AUG-Q1 选择：**取舍为主、成长并存**。

辅槽优先提供局部专门化的装配选择：玩家根据法器用途、当前需求与标记条件，决定把一个装配机会用于什么。同时，获得更强修饰或更多可装配容量应能带来可见变化；是否实际做到，由体验页观察。

这项定位用于检查内容方案：同一装配机会占用后，玩家放弃了什么；什么情境值得选择，什么情境价值较低；成长体现在哪个实际结果上。它不要求每个辅槽都另加负面词条，也不要求所有不同用途在所有情境严格等强。

## 职责分工与设计理由

| 设计问题 | 当前处理 | 理由与限制 |
| --- | --- | --- |
| 生产参数过多，难以解释收益 | 生产侧只开放生成时间，量值放到行动卡 | 收敛需要理解的生产变化；不预先保证学习负担降低 |
| 构筑需要组合关系 | 通过共享标记连接法器 | 让收益有可追溯的来源与支付；标记争用仍可能增加理解负担 |
| 成长和用途差异容易混成一条升级线 | 稀有度表达强弱，其余直接写效果 | 减少并行等级；实际适配仍需结合条件判断 |
| 失败支付难以预测 | 完整检查成功后才扣标记 | 明确支付底线；退款与失败分支需要独立决定 |
| 更多槽位容易被误当成已有能力 | 容量、实体、兼容候选与推荐展示分别解释 | 打造不赠铭文，也不证明每种成长都有深度 |

本表是规则的设计理由，具体权限以 [rules.md](rules.md) 为准。既有框架中的“专注”减料、“蓄言”增加成品张数、直接跨法器增益及统一三阶数值不延续到本版；保留其原来源身份，不替旧名称或 ID 悄悄换义。

## 表达方向与理想效果

以下为**表达建议，尚非已采纳界面方案**：

- 主要信息使用“稀有度＋效果＋关键条件／代价”。生成时间与行动量值是设计核对维度，无需做成玩家必须学习的分类树。
- 配置时尽量显示基础值与实际改变量，并指出标记是否必需。不能只显示抽象“战斗力增加”，也不能把生成时间缩短画成生效承诺。
- 战斗反馈区分条件不满足、未开工、标记支付、完成入行与最终行动结果。具体排版、动效、文字密度与详情层级可继续迭代。
- 协同说明沿“谁产生标记—谁使用—谁获得结果”表达，避免让玩家以为另一法器直接给本法器加成。

理想结果是玩家能用简短理由解释一次配置选择和一次收益。风格、推荐展示数量与布局尚未确定；不从旧示例继承“统一推荐数”或局内阶段梯度。整体可达性与通用符号仍须遵守 [SYS-007](../../../common/interaction-save/rules.md)。

## 待补接口与当前建议

| 未决项 | 当前建议或候选 | 需要决定的内容 |
| --- | --- | --- |
| 生成时间何时确定 | 建议沿唯一 D，在开工前确定本批耗时；此建议未单独确认 | 条件读取与承诺时点、舍入、下限处理、多项时间修饰顺序，是否允许以及如何处理动态变化 |
| 标记不足后的行为 | 可按具体效果明确“基础回退”或“等待条件” | 哪个分支适用、怎样预览、是否产生反复等待；两者尚未选定 |
| 已付标记遇到中断／失效 | 不从材料退款类推 | 各支付阶段的归属、是否返还、返还可用拍、重复检查与重复支付边界 |
| 标记的可用时点与争用 | 接入 [标记实有状态与定时登记](../../action-card-system/mark-system/rules.md)；预告不是余额已明确 | 同拍兑现／读取／支付的相对位置、多个消费者争用；不另造辅槽事件顺序，不把材料供料序当已定答案 |
| 契合、标记、辅槽的叠加 | 普通量值引用 TL-37；特殊域单独声明 | 替代与共存、倍率合成、实际离散结果；不默认同类全加或全部相乘 |
| 稀有度强度映射 | 以后按方向和实际结果制定预算 | 稀有度名称／数量、强度差、限制、价格和投放；本轮无发行数值 |
| 打造与获取 | 打造接口由 [铭文系统](../rules.md#tl-42-辅槽打造) 维护；获取由 [局内经济](../../../common/run-economy/rules.md) 维护 | 实体供给、槽位费用、时机与持久范围；不在辅槽页补免费默认 |

这些是后续设计工作项，不要求重问 AUG-Q1—5。闭合接口时应保留已确认边界，并检查与阶段成果的明确差异。没有具体效果和经济输入前，不冻结内容结论。

### 后续可成组处理

1. **一批效果何时确定**：一起确认条件读取时点、D 的承诺／舍入／下限和多修饰次序；沿既有建议优先讨论开工前确定本批 D，以便解释完成承诺。普通量值仍用自身合同，不沿时间公式类推。
2. **支付失败与状态变化**：同批讨论标记不足时基础回退或等待、扣费之后被打断／目标失格的处理、退款及可用拍。推荐先明确每个效果的检查与收益阶段，再选适用分支；不把“成功才扣”扩写成默认回退或默认返还。
3. **共享标记的同拍关系**：在行动／标记共同规则中决定兑现与消费者顺序，辅槽引用结果。推荐只维护一处总序，避免法器供料序与标记消费序互相覆盖。
4. **槽位、强度和获取**：有实际效果后，联同 INS-Q04—06 处理契合／修饰兼容、稀有度预算与打造；推荐分别解释新增容量、获取实体和效果变强的来源。原 Raw 中“统一一个辅槽”“解锁一至两个”和金币价格不能填补 Unknown。

这四组是设计页中的待办与推荐，不是本轮新确认，也不启动资格采访或玩法实验。具体素材若要晋级，仍按原资格流程处理。

## 原始效果材料的使用边界

本轮仅核对相关段落，覆盖见 [来源记录](../../../../sources/inbox/2026-10-08-inscription-framework-review.md)。Raw 原件保留；其名称、ID、套组和“兼容／闭环验证”用语不授予发行或验证状态。

两类修改位置继续以 [规则权限](rules.md#2-修改权限)为准。原材料中“生成标记”须区分改变行动已声明的标记量值，和新增一种标记／额外事件／改变持续时间；后几项没有因为是数字或叫“增幅”就自动取得通用权限。名为“契合”的修饰也不能代替法器 TL-45 的正式契合声明。未合格的具体效果不移到本页或示例中作为候选正文。
