## 既有正反例

以下将原有六条短例展开，并补全相邻接口的失败边界。甲、乙为抽象生产者，拍号及单牌输入仅用于演示已确认规则，不登记为法器实体或正式数值。每例只在列明前提下确定结果；具体配置须先满足内容合同。

## 合法配置、缺料与缺位

- **用途／依据／状态：**区分配置不合法与合法配置等待。依据 [铭文 TL-40](../inscription-system/rules.md#tl-40-核心必填与有限兼容)、[法器 TL-03／05](rules.md#tl-03-一批生产的可见状态)，Inherited / Accepted 的推导。
- **前提／输入：**分别比较缺核心、核心合法但完整材料不足、材料齐全但本批所需可用容量不足；材料只包含当前已经可用的部分。
- **步骤／时点：**拍末统一开工检查逐一核对合法配置、完整材料和容量。
- **确定结果：**缺核心不能产出；合法而缺料／缺位者保持未开工，不部分扣料、不先预留或先加工，其他法器继续检查。核心合法且辅槽为空不因此失败。本拍新增补给或退料不能填本拍材料缺口。
- **未决部分：**不设配方、Q、补给量或法器数量；条件补足前不承诺具体开工拍。

## 先开工不等于先入行

- **用途／依据／状态：**说明预留不占队头及完工不等于生效。依据 [TL-03／05](rules.md#tl-05-开工预留与完成入行)、[行动 TL-08／11](../action-card-system/rules.md#tl-08-玩家战斗行)，Inherited / Accepted 的推导。
- **前提／输入：**仅为逐拍演示，甲在第 0 拍开工、D=3，乙在第 1 拍开工、D=1；两批各产一张行动，均已合法预留，无中断、其他入行牌或终局。两台后续批次均缺料，因此不续开。

| 拍 | 发生什么 | 规则结果 |
| --- | --- | --- |
| 0 | 甲拍末开工 | 本拍不额外推进一拍，预留只占容量 |
| 1 | 乙拍末开工 | 不因甲更早预留而排在甲的未来“牌后” |
| 2 | 乙完成并入行 | 甲仍处理；乙本拍不能翻开 |
| 3 | 乙已具备队首资格；随后甲幸存完工 | 乙取得本拍行动机会并离队，甲随完工入行，不能返回本拍行动阶段 |
| 4 | 甲具备队首资格 | 在前提持续成立时取得本拍行动机会 |

- **未决部分：**不指定卡效或目标结果；有其他队列牌时不能保证入行下一拍生效。D=3／1 不是发行值或辅槽改速公式。

## 两种顺序与完整开工检查

- **用途／依据／状态：**区分开工争用顺序与同拍实际入行顺序。依据 [TL-05](rules.md#tl-05-开工预留与完成入行)，Inherited / Accepted 的推导。
- **前提／输入：**情境一中，甲供料优先级更高且料齐，但本批所需容量大于可用余量；乙的合法单批条件可独立满足。情境二是两个已合法预留的法器同拍幸存完成，临时供料序与战前法器序不同。
- **步骤／时点：**情境一在拍末检查甲后继续检查乙；情境二在完工阶段将各自预留转为实际牌。
- **确定结果：**情境一跳过甲，不扣料、不占位，乙可开工；不授予甲保底轮转或先拿料等位。情境二沿战前法器序入行，不沿临时供料序，不新增容量占用、不留下完工待位成品。
- **未决部分：**多牌批次内部顺序未定；大批次是否长期等位须结合内容核对，本例不证明公平。

## 完工拍被打断与回收边界

- **用途／依据／状态：**保留“被打断者退料而不产成品”的反例，区分回收资源与其他可用资源。依据 [TL-07](rules.md#tl-07-打断与返工)、[行动 TL-11／12](../action-card-system/rules.md#tl-11-共同拍序与效果边界)，Inherited / Accepted 的推导。
- **前提／输入：**某批原定 t 拍完成；敌方明示打断已锁定该法器，t 拍仍有此批，打断有效且战斗未终局。
- **步骤／时点：**先结算打断，再处理幸存批次完工，最后作统一开工检查。
- **确定结果：**此批被中断，不交成品；材料退回、进度丢失，原预留转为待下拍复用。退料与释放容量最早 t+1 可用，本拍不能用它们重开。若另有原本可用的完整材料和独立空位，仍可在 t 拍末检查重开，不额外整机冷却。已入行旧牌不因来源法器被打断消失。
- **标记补充与未决：**若该批有CORE-055开工冻结标记，明确释放该量并在t+1最早可用；不类推其他阶段已付退款，自然失效与战终归属仍Unknown。

## 供料取舍与临时方案

- **用途／依据／状态：**保留临时防御优先情境，并说明到期恢复只影响未来。依据 [TL-06](rules.md#tl-06-路由与临时设置)，Inherited / Accepted 的条件性推导。
- **前提／输入：**面对已揭示攻击，玩家可暂缓下一轮运转端开工，把尚未承诺且配方兼容的材料优先分给防御端，换取护甲并承担资源积累延后；也可维持原计划或优先攻击。此处以已有合法内容确实提供相应行动为前提，不发行运转或防御配方。
- **步骤／时点：**在揭示后观察窗口提交合法临时方案，指定晚于当前拍的结束拍；方案用于本拍末尚未承诺批次的检查。
- **确定结果：**已托管运转批次照常处理、保有预留；防御有料但无位仍不开工，不能抢预留或把成品直接变护甲。防御须经完工入行及普通队列取得生效机会，改线不保证赶上攻击。
- **到期与替换：**结束拍先恢复基础方案，再揭示与接受新方案；本拍新方案不会被旧到期再次抹去。新临时方案替换旧临时方案，只保留一份，结束时不复活更早方案。恢复不撤销已付成本、延误或返工；结算途中提交留下一窗口。
- **未决部分：**具体运转行动与高阶材料来源、未来输出设置及自动暂停表现未定；供料不保证任意指定开工时刻。

## 标记支付与尚未到账的预告

- **用途／依据／状态：**解释法器接入标记的边界。依据 [辅槽支付原则](../inscription-system/augment-system/rules.md#4-检查成功才支付)、[标记读取与支付](../action-card-system/mark-system/rules.md#读取与支付)，Qualified 框架推导；制造材料及容量沿 Accepted TL-05。
- **前提／输入：**假设有一个已明确声明必要标记费用的开工侧修饰；只核对支付边界，不指定效果、费用或公式。依次考虑缺制造材料、缺容量、实有层数不足但存在未来预告。
- **步骤／时点：**完整检查该支付步骤的必要条件，未来预告不计入余额。
- **确定结果：**任一必要条件失败都不能提前或部分扣标记；没有消费声明的读取不扣层。生产出一张未来会产标记的行动卡，不代表现在已经持有该标记。
- **未决部分：**CORE-055已定必需不足等待、明确可选才回退，成功开工冻结标记、完工扣除、打断释放下拍可用。两个法器争同种未承诺标记、定时效果相对开工的位置仍未统一确定。

## 无目标、零值、取消截止与终局

- **用途／依据／状态：**明确交付后的责任边界，避免回退生产成本或绕过终局。依据 [行动 TL-08／10／13／29／30](../action-card-system/rules.md)、[资源 TL-37](../resource-system/rules.md#tl-37-参数来源与有限事件的共同合同)，Inherited / Accepted 的独立情境推导。
- **前提／步骤／结果：**下表各行是独立输入，不组合成一张复合卡。

| 输入及检查时点 | 确定结果 |
| --- | --- |
| 成功制造、入行，到生效时没有合法目标 | 空放离队，占本拍行动机会，不补翻、不补发、不退制造材料；正常离队容量可用于本拍末 |
| 普通量值依法得到 0，但对象及必要状态仍合法 | 0 不自动等于程序非法，不能据此回退制造；对象／必要计量状态消失须另按资格规则判断 |
| 取消行动在敌牌到期 T 前完工，却直到 T 才生效 | 来不及取消 T 的行动；提前完工不能替代提前生效 |
| 任一完整事件已满足终局 | 停止后续动作、完工和开工，不为未完成批次补发行动；此前完成的合法结果不回滚 |

- **未决部分：**战终未完成批次的托管材料归属仍待决定，不能从“停止”推出全退或全耗；完整复合总序不由这些边界例补齐。
