# 标记系统：规则

2026-10-11 · QualifiedFramework；冻结与定时接口沿CORE-055／057。[状态与来源](../../../baseline.md)。

[设计](design.md) · [体验](experience.md) · [示例](examples.md)

## 对象与宿主

标记只附着于玩家或敌人，以种类、极性和层数表达。正负相对宿主，两方各有正负两侧；不附着于法器、行动或资源，不转移宿主。标记定义、宿主实有状态、未来定时登记是三个不同对象。

## 叠层、上限与存续

同宿主同类按层数叠加，异类及不同宿主独立。每类声明上限、超限处理、层数效力、期限／刷新、移除和战终结果。层数可叠加不等于线性增强或定时登记合并。生命周期字段不足的具体内容不启用，缺项统一见[TL-Q02](../../../../governance/questions.md)。

生命和护甲沿TL-29，不套一般标记上限或支付权限。生命表现见TL-Q08。

## 读取与支付

条件只使用明确宿主、种类和层数。读取不消费；费用须另写付款者、种类、完整量、检查时点、结果及失败分支。

当前读取只认合法实有层，不认未来预告或其他批次冻结量。即时支付排除托管／冻结、玩家锁定及待下拍可用量。完整条件成功才足额扣费；不足不部分支付、不重试；只有明示可选回退才执行基础分支。

多个消费者沿TL-11逐个检查当时余额，不重复花同一层。即时新增层可供后续步骤或开工，不回头补救前面失败；释放量仍下拍可用。

## 批次标记冻结（CORE-055）

只适用于开工侧声明消费。完整开工成功后，冻结足额量，记录宿主、种类、数量和批次；幸存完工扣除。冻结是占用，仍属于宿主；其他效果不能读取／支付被冻结部分。

冻结仍受自然到期和合法移除。失效部分从实有状态清除，并在承诺记为失效；不补扣新增层、不重算D。完工只扣仍有效冻结量，再结清整项承诺；打断只释放仍有效量，最早下拍可用。

玩家主动锁定只约束自有未承诺数量的自动消费，不禁止非消费读取，不撤销批次。开工依有效供料序逐台检查，前一批占用后后一批读取剩余量。

## 定时登记与兑现

行动生效可留下独立定时效果；原卡离队，登记不占Q、不再次翻牌。声明来源、宿主／目标规则、基础量、首次兑现、周期、结束拍／次数和停止条件。未来砝码只是预告。

## 定时登记与有效期合同（CORE-057）

1. s拍建立，首次f≥s+1，f为整数；周期p为正整数。周期内容须有有限次数或结束拍e。只有兑现拍<e且次数足够才尝试；到期尝试消耗一次，即使落空也不补兑。
2. e拍边界先失效，无末次补偿。新登记不加入本拍候选，同登记每拍最多到期一次；按建立序，同源按步骤序。并存／覆盖／刷新及预算由具体内容声明。
3. 默认建立时按承诺规则绑定合法宿主实例；无合法宿主不建立、不支付该步费用。登记独立于原卡、来源法器和其他敌牌；宿主失去存活资格或终局时清理，不补发。
4. 保存基础量、来源和支付归属；每次兑现从该步骤开始时状态读取条件、层数与修饰。只有明确声明的快照按其声明执行。
5. 普通有限期状态同样有效至e但不含e。锁定不阻止到期／合法移除，消失部分从锁定量减去，不转锁未来新增数量。冻结量按承诺合同清账。

新增事件遵守TL-37；本规则不提供任意触发或递归登记。实际层数上限与登记预算分别检查。

## 信息与反馈

宿主旁用砝码堆叠及正负分侧，未来效果用虚幻预告。实际、上限、来源、期限、冻结、主动锁定、可消费、待释放及其可用拍须可查。必要信息支持点击和键盘，展示空状态可合并而不能混淆余额。
