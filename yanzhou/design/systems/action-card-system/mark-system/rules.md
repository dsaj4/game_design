# 标记系统：规则

2026-11-05 · QualifiedFramework；CORE-055／057已采纳接口保留未替换范围，round-plan.1替换开工竞争与当前时序，沿[基准](../../../baseline.md)。[设计](../../../../system-design/mark-system/design.md) · [体验](../../../../system-design/mark-system/experience.md) · [示例](examples.md)

具体标记只按实际声明读取对象、叠层与支付；只有开工费用才读冻结。CORE-065允许即时层供后续步骤／列使用；有限期、周期、独立定时接口未闭合，不按旧扩展启用。原首战标记已随CORE-071淘汰。[CORE-072](../../../../sources/draft-changes/D-2026-11-01-alchemy-executable-content.md)另行采纳炼金[咒定义](../../../../content-library/alchemy.md#alchemy-mark-curse)，具体上限、初始、支付与战终由该条维护；不恢复旧身份或启用其他周期标记。

## 对象与宿主

只附玩家／敌人，不转移宿主；种类、极性与层数描述状态，正负相对宿主各分两侧。标记定义、宿主实有状态和未来登记分别处理。

## 叠层、上限与存续

同宿主同类叠层，其他独立；叠层不自动线性增强或合并定时登记。具体上限、超限、效力、期限／刷新、移除和战终见[内容合同](../../../content/cards.md#内容必填字段)，缺项不启用。生命／护甲沿TL-29，不套普通标记上限或支付权限；未决见[TL-Q02／08](../../../../governance/questions.md)。

## 读取与支付

有合法玩家消费锁定时，须区分实有、锁定和可消费量，操作沿[TL-17／18](../../../common/interaction-save/rules.md#玩家消费锁定与预警core-055)。CORE-075已取消材料锁定与自动补料，标记锁解时点沿当前布置窗口；具体价格、不足分支与能力范围须由有效内容声明，退役首战数值撤下。

简单条件只查宿主／种类／层数，读取不扣费。当前读取只认合法实有层，不认未来预告或其他批次冻结量；玩家锁定不禁止非消费读取。即时支付排除其他批次冻结、玩家锁定及尚未到可用列的量。

逐步支付与失败沿[TL-30](../rules.md#tl-30-制造材料与效果支付分阶段)；战斗即时新增层可供后步／后列，不倒补失败，不倒补已结束生产阶段。下一轮生产才可读取战斗新增的合法未承诺量。没有生产打断释放路径，不沿旧“下一列释放”默增新权限。

## 批次标记冻结（CORE-055）

每生产拍开始前按宿主／种类合并本拍各器必要费用，与完整性及占用一起共同检查。全合法且足额才共同冻结，逐批记宿主／种类／数量；不足整拍拒绝暂停，不部分冻结或按法器位置选先后。冻结仍属宿主但其他效果不可读取或支付，完工结清。玩家锁定只作用未承诺量，不能撤批。

已合法发生的失效记入原承诺，完工只扣仍有效部分，不补扣新增、不重算D；期限、自然到期等扩展未迁移不启用。战斗暂停不开放标记锁解。生产总序及确定性恢复沿TL-11／19。

## 定时登记与兑现

以下两节保留CORE-057旧连续拍扩展；CORE-065首场未迁移，不能把敌后续手牌等同于独立定时登记。

有明确内容才登记，原卡离队，独立登记不占Q、不再翻牌。声明来源、宿主／目标、基础量、首次／周期、结束／次数及停止条件；虚幻砝码仅预告。

## 定时登记与有效期合同（CORE-057）

| 项目 | 规则 |
| --- | --- |
| 时间 | s建立，整数首次f≥s+1；正整数周期p，周期内容必须有限次数或结束拍e；只在兑现拍<e且次数剩余时尝试，落空也耗一次，不补兑 |
| 名单与顺序 | e边界先失效；新登记不进本拍候选，同登记每拍最多一次；保持独立身份／建立序，同源按步骤序，初始序由遭遇给定 |
| 绑定与清理 | 默认建立时绑定合法宿主实例，无宿主不建立、不付该步费；独立于原卡、法器及其他敌牌，宿主死亡／终局清理，不补发 |
| 取值 | 保存基础量、来源和支付归属，每次兑现从步骤开始状态读条件／层数／修饰；只有明示快照按其声明 |
| 有限期状态 | 同样不含e；锁定不挡到期／移除，失效量从锁定减去、不转锁新层；冻结按上段结清 |

并存／覆盖／刷新和登记预算由内容声明，实有上限与登记预算分别检查。不开放任意触发或递归登记，额外事件沿TL-37。

## 信息与反馈

标记锁解在布置窗口受理；生产拍事件处理中及整轮战斗锁定后不受理，恢复不会新增编辑点。新首场只展示实际采用的余额，未来登记不作为现行功能。宿主旁用砝码堆叠、正负分侧，未来用虚幻预告；实际／上限／来源／期限及各余额资格可查。点击、键盘和空状态合并沿[交互合同](../../../common/interaction-save/rules.md#tl-17-暂停与信息)，不能混淆余额。
