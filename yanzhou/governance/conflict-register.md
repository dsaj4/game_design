## 结论与证据边界

**关键应对的机制来源已明确：敌牌先揭示再生效，玩家在攻击、防御、资源积累之间调整未来供料，并通过供料改变未来开工以避开指定打断。**此前将具体窗口未定过度推成“免费路由没有明确用途”，这部分判断撤回。快攻持续占位也可以是玩家选择的代价，不能单凭拥堵认定系统失效。

当前应继续检查实际法器、配方、队列与延迟是否形成可用且代价不同的方案，以及玩家能否预判失误。资源调度的设计逻辑已说清，实际可行性和体验仍未验证；完整事件顺序、恢复条件、实际资源来源与铭刻内容仍有缺口。少量完整内容比继续增加机制更能检验这些问题。

证据标记：**Derived**为已读规则推出的约束或条件风险；**Assumed**为尚无玩家证据的行为／体验预期；**Unknown**为设计未定。以下没有本轮Observed玩家证据。历史Accepted不变；文档检查不能关闭体验问题，也不能将GDD-0提升为GDD-1。

### AUD-021 · P1：关键威胁可能只剩“看见但做不了”

当前状态：**意图已澄清；具体窗口与可读性待验证。**来源：[TL-06](../design/systems/artifact-system/rules.md)、[TL-09／10／12](../design/systems/action-card-system/rules.md)、[CORE-050](../sources/draft-changes/D-2026-10-04-routing-response-clarification.md)。全敌牌正延迟，临时供料可使未来防御优先、让积累延后；供料也可改变未来开工，避开指定打断。固定配方与卡种不排除资源用途选择，不能再以缺少即时施法或重铭认定没有战中行为。

Derived边界仍成立：取消实际生效须早于T，暂停只增加思考时间，已承诺批次和队列不回滚。揭示时若唯一取消法器忙于前一批、队列又满，当前可能无法取消；它可由此前选择造成，不是必须提供补救按钮的反例。尚需核对正常准备下的实际供料、加工、交付与等待是否支持不同代价的路径。防护按同拍防护阶段另判，规避打断还须检查加工暴露时段，不能只研究取消一种应对。

保留原失败路径：持续生产的专门取消牌在没有合法敌牌时可能空放，消耗材料和队列；断料等揭示又可能来不及。该取舍需由实际内容判定合理性，不据此先否定机制。关联TL-Q04／10／11与INS-Q01–03；原“用途尚未说清”的缺口已关闭，数值与玩家理解没有因此验证通过。

### AUD-022 · P1：队列饱和的代价能否被预判

来源：[TL-05](../design/systems/artifact-system/rules.md)、[TL-08](../design/systems/action-card-system/rules.md)、[TL-18](../design/common/interaction-save/rules.md)。Derived：N拍内最多兑现N张玩家行动卡；一旦持续入行需求高于1张／拍，有限缓冲最终阻塞，增加Q只能改变等待和滞留。这个上界针对卡数，不等于伤害或所有构筑收益上界。

用户已明确持续快攻占位可归于玩家操作。防护因前面攻击牌未清空而错过窗口，可以是持续攻击的代价；事后无法免费改已入行牌不构成单独缺陷。此前把这一场景直接列为系统问题的判断收窄为：资源优先级、争入行顺序和等待后果是否可预判，玩家是否能在承诺前有意识地牺牲攻击或积累。

保留条件风险：若所有合理配置都长期饱和，新增产能／提速可能只增加滞留；若资源积累也经行动牌生效，其步骤会竞争同一兑现额度。这些是内容与产能预算问题，须分别比较料不足、产能不足和队列饱和，不能由卡数上界推断多法器没有价值。付费调牌序仅保留[原始候选](../sources/inbox/2026-10-04-routing-response-clarification.md#付费调牌序候选)，对象与成本未知，未改现有1张／拍、争入行规则或已入行承诺。关联TL-Q04／06／10、INS-Q02／03，NotRun。

### AUD-023 · P1：部分时序不足以裁定复合牌与胜负

来源：[TL-11／13／29](../design/systems/action-card-system/rules.md)、[TL-17](../design/common/interaction-save/rules.md)。Unknown：防护→伤害／打断→完工是大类顺序，“完整事件”却没有定义到一张复合牌、一个效果步骤还是同类同时发生的一组行动。

反例：玩家与敌人都剩1生命，同拍双方造成1伤害；按逐牌完整事件先后会得到相反胜负，按同时事件又可能双亡失败。另一张牌既护甲又伤害，若拆到不同大类，中间终局和目标失效能否中止后半段也未定。不能把“双方同检查点归零判负”当成已确定同拍都处理。建议先给上述场景与同拍揭示／暂停一个唯一预期，再列完整事件顺序；第一组内容若不需要复合牌，可先明确排除，保留后续规则缺口。关联TL-Q02／05。

<a id="aud-024"></a>

### AUD-024 · P1：周期、批次与临时恢复缺少可执行定义

来源：[TL-03–07](../design/systems/artifact-system/rules.md)、[参数](../design/parameters.md)、[TL-44](../design/systems/inscription-system/rules.md)。Unknown：战前可选“周期”与D／J／R的关系、阻塞时J计时、入行最早翻开、一次多牌的部分交付，以及临时设置何时结束都没有闭合。

反例：一批产2张，玩家行只余1格；整批等、逐张进入、重新计交付各自影响占用与响应。临时改线若按“威胁解除”恢复，两个威胁重叠时谁覆盖谁、返工后的第一批用何设置也无答案。建议先选一批一张作为待确认的最小内容范围，并给一张逐拍状态表，明确阻塞前／中／后、取消后再开工和基础设置恢复触发；D/J/R零值域单列。不能从当前示意图补出公式。关联TL-Q04，新补TL-Q11。

<a id="aud-025"></a>

### AUD-025 · P1：维护优先可能造成长期断粮，而非短暂等待

来源：[TL-22／23](../design/systems/resource-system/rules.md)、[TL-30](../design/systems/action-card-system/rules.md)。Derived条件：若每次到期维护吃光可用补给，新加工永远得不到料；多个产物争用还可能使固定低优先级对象长期休眠。材料补足不代表所有对象都能恢复。

例如每次补1份、已有产物同时维护需1份，且没有其他供给，则基础行动无法重新开工。这里只是条件反例，不是正式数值。若产物又被托管且仍吃维护，短缺更难由玩家解释。建议先核对最低补给和最坏维护负担，明确休眠、托管与竞争结果；可以保留资源耗尽作为构筑失败，但要有预警与可追溯原因，不偷偷增加公平轮转或免费补料。关联TL-Q03／06、INS-Q03。

<a id="aud-026"></a>

### AUD-026 · P1：高阶资源链已被切断，不能用旧收益链证明新核心成立

来源：[TL-38](../design/systems/artifact-system/rules.md)、[TL-14／15／43](../design/systems/resource-system/rules.md)、[CORE-049](../sources/draft-changes/D-2026-10-04-artifact-inscription-core.md)。Unknown：高阶资源获取／加工目前没有正式路径，只有维护、增幅与携带接口。清理FX冲突后，这个缺口应保持可见。

后果：没有来源就无法比较即时攻防与高阶准备；若材料只能由消耗同种高阶料的行动生成，还会出现无法启动的闭环。建议先只选一条完整取得链，逐项写初始来源、消费、产出、排队和启动条件，确认不依赖免费组件；随后才评估维护和跨战。行动产资源是一种可另行设计的方向，不是本次默认答案。关联INS-Q02／03、TL-Q06。

<a id="aud-027"></a>

### AUD-027 · P2：契合与预设暗句可能把组合压成查表和固定答案

来源：[TL-39–45／26／28](../design/systems/inscription-system/rules.md)、[GDD体验支柱](../design/GDD.md)。Assumed：受限空缺更易理解、不同情境会选不同核心和辅槽。Derived条件：若契合组合只有正收益、成本相同且替代方案没有情境优势，玩家没有放弃契合的理由；同理，若打造只增益且资源无其他价值，它只是必做升级。

“符合器具内涵”能帮助说明主题，不能独自判定合法性。自然语言像同义词却因逐法器白名单产生不透明差异，会让玩家记答案。建议每个代表法器至少列契合方案、可行非契合用途和非法反例，显示基础行动／修饰／契合的各自贡献；先决定哪些词义可迁移理解，再扩专属组合。此为审查建议，不强制任何铭文通配。关联INS-Q01／04–06、TL-Q10。

<a id="aud-028"></a>

### AUD-028 · P2：旧随机获取结构可能不适合现在的有限兼容

来源：[TL-34／35](../design/common/run-economy/rules.md)、[TL-31](../design/common/interaction-save/rules.md)、[TL-39／40](../design/systems/inscription-system/rules.md)。Derived：休整保证词性分布，不保证适配现有法器；商店也不按构筑补齐。INS-1要求核心全部必填，所以有库存并不等于能用。

反例：玩家缺一个特定法器可用的动词，候选虽含动词却全部不兼容；为此放弃恢复，最后只得到未来也未必能用的部件。更隐蔽的是池中缺名词时，按既有TL-34连可用修饰词的拿取机会也整体关闭。建议用真实初始库存与小型奖励池枚举沿途可用、可留待未来、完全无用途三种结果；先收敛内容和渠道，再决定是否需要改抽取结构，不直接添加保底。关联TL-Q06、INS-Q01／05。

<a id="aud-029"></a>

### AUD-029 · P2：跨战收割、护甲储存与疲劳存在相反激励

来源：[TL-25／33](../design/common/run-economy/rules.md)、[TL-24／29](../design/systems/action-card-system/rules.md)。Derived条件：若留下最后一个弱敌能安全继续产可携带资源，而且新增资源的下场收益大于拖延生命成本，就会奖励故意不结束战斗。基础料清空和增幅重置不能消除“高阶数量”积累；战间维护状态重置还可能改变持有成本。

护甲无自然到期和统一上限，防护过量可能先积累缓冲，也可能只挤占队列；疲劳绕甲，但目前没有曲线证明它足以约束收割或保证所有合法恢复组合有限终局。建议同预算比较立即胜利／多等一批／更久拖延的跨两战结果，分别检查生命、资源容量和后续起跑优势；不直接恢复已被拒绝的全量清空或跨战维护。关联TL-Q01／07／10。

<a id="aud-030"></a>

### AUD-030 · P2：信息可查不等于因果可理解，自动运行也不等于有决策节奏

来源：[TL-17／19／36](../design/common/interaction-save/rules.md)、[核心循环](../design/GDD.md)、[验收](../design/validation.md)。Assumed：玩家能同时理解兼容、占用、托管、加工、交付、队列、截止、维护和付费等关系。当前“都有地方显示”仅保证信息存在，没有证明玩家能及时找出真正瓶颈。

反例：取消牌有料、法器已完工，但交付阻塞导致错过截止；玩家可能误以为是材料或按钮问题。另一方面，每张普通牌都弹暂停会变成碎片操作，威胁太少则可能长时间只观看。建议在实际内容中优先回答“哪项承诺挡住了下一步、现在能改变什么、预计何时生效”，同时观察普通区间的必要操作和无决定等待；逻辑时长与暂停思考的现实用时分开记录。参数和样本未定，不编造操作频率门槛。关联TL-Q08／10。
