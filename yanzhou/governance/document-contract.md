# 文档职责与维护

2026-10-23 · Accepted / Documentation · G002-DOC-030。资格、采纳和记录规则统一沿[设计流程](../../docs/design-workflow.md)，此处只规定归属及同步。

## 权威来源

| 内容 | 唯一维护处 |
| --- | --- |
| 游戏核心、循环与当前范围 | [design/GDD](../design/GDD.md)；版本／资格边界见[baseline](../design/baseline.md) |
| 系统精确行为、条件、公式与例外 | [规则索引](rule-index.md)所指rules；迁入GDD的核心TL由GDD维护 |
| 参数、实际内容与限定案例 | design/parameters、content、examples；案例数值不成为全局默认 |
| 理由、体验假设与规则情境 | 所属系统design／experience／examples；不在这些页新增规则 |
| 领域词义 | [CONTEXT](../CONTEXT.md) |
| 当前设计问题 | [questions](questions.md)；工程Bug留实现仓库 |
| 采纳决定、编号与别名 | [decision-log](decision-log.md)；来源细节沿D及design/source-review按需追溯 |
| 意图、资格、提案／评估与待采纳变更 | sources相应目录；探索方向用自己的README，沿[READ-1](../exploration/start.md)控制材料 |
| 任务最小设计与人工审阅 | development任务包／同轮意见；均为现行设计的派生视图 |
| 当前开发能力、阶段与工作方式 | development/README、production-plan、development-standard、iteration-spec各按职责维护 |
| 实现、构建、测试日志与技术决策 | 外部实现仓库；本仓库只保留范围、状态及固定证据入口 |
| 资产与历史 | 原件就地、AS／DM沿统一目录；结束的过程按[历史入口](../history/README.md)取证 |

README只导航；工作台只展示同一来源、状态和证据，不维护规则副本或第二套进度。共享方法、模板、注册分别在根docs/methods、game-design-workflow/templates、docs/registry；其他游戏与言咒不混用材料。

## 核心与细则的关系

每项裁决只在一处维护。核心解释整体并链接细则；具体例外须明确对象、规则ID与适用范围，不能由实现者在冲突文本中任选一版。任务包只派生本任务需要的结论，不能独立改规则。

规则写清实际对象、前提、触发／操作时点、成本、结果及失败；参数保留单位、合法域与范围。不适用字段省略，Unknown不得填成无标识默认值。Accepted、Qualified、Proposed与实现／体验证据分别表达。

## 按实际内容拆分

六主系统保留法器、铭文、行动卡、敌人、资源、局外成长；辅槽归铭文、标记归行动卡，路线、局内经济、交互保存归common。SYS保留旧身份，不按目录重编号。

导航、行为、理由、体验、示例是五种职责，**不要求五个文件**。短内容可同页分节，未设计系统只留占位；内容增长或按需读取确有收益时再拆。示例不复制已有案例参数，重复反例直接引用验收。

周期、维护、开工标记费、多目标等只在实际采用时展开；未用字段不变成首场实现要求。公共机制变化仍需检查完整依赖，不能用按需阅读省掉受影响接口。

## 修改与审阅

1. 按项目AGENTS选入口和材料，固定一个共同输入版本；链接不授权递归扩读。默认开发启动包保持5份，完整GDD另沿READ-1。
2. 改玩法沿设计流程形成必要来源、评估／提案、D及明确采纳；文档整理不授予新玩法或实验权限。已授权事项不重复确认。
3. 修改权威页后，同步受影响核心、案例、验收及活动任务包；来源已变而包未同步时明确标记。当前问题只在questions更新。
4. 人工按选择、成本、时机、胜负和信息公开影响，通过[场景对话](../development/design-review.md)审阅；纯推导、版本与引用一致性由agent检查。
5. 核对链接、状态、编号及实际差异，按[Git规范](../../docs/github-collaboration.md)提交推送本任务文件。

输入留决定摘要，不存原话；验收保留情境与预期，执行结果链接原证据。清理先合并独有结论和失败经验，原文用固定Git取证，不新增去向表、逐文件哈希或重复清理报告。冻结历史包保持原字节及原路径语境；退役目录和命令不恢复为当前入口。
