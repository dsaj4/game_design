# 当前问题登记

2026-10-11。本页是主系统未决设计与风险的唯一工作清单。规则正文说明确定行为；本表说明缺什么、影响哪一段开发、建议怎样处理。负责人为设计负责人；UI项由后续UI设计任务完成。

## 开发前先看

**可以开始：**已采纳的生产、队列、结算、敌情、保存行为，以及[EX-001首批案例](../design/examples/simple-spell.md)的明确配置。

**完整制作仍需决策：**自动暂停与生命展示、首批零材料调度、全局疲劳及完整局内内容。未决定的功能不显示成可操作入口，所需内容不填猜测值。首批案例只覆盖本页列明的已选内容，不能替代整局规格。

| 优先级／ID | 具体问题 | 对制作的影响 | 推荐处理与完成条件 |
| --- | --- | --- | --- |
| P0 · TL-Q08 | 自动暂停触发、每拍播放时长／倍速、布局、复合卡主类别、生命显示尚未选定 | UI行为与时间播放需要明确输入 | 推荐常态自动播放、手动暂停，关键揭示可配置自动暂停；生命先独立数字／条，标记用砝码，另保留生命砝码对照方案。这些是建议，UI设计须交付明确状态与操作表 |
| P0 · FB-Q01（关联TL-Q11） | 零材料护符没有可停供的材料；当前未提供单法器暂停。D=2／3且Q=5时，调供料优先级不能稳定改变攻防产出或错开批次 | 首批已有运行演示，但原构思中的主动攻防调度、躲打断操作尚不成立 | 推荐下一轮选择“未来批次启用／停用”这一项受限调度能力；只影响未开工，不取消当前批次。另一方案是部分配方使用有限材料。选定前按案例自动运行并承担中断，不造暂停按钮 |
| P0 · TL-Q07 | 疲劳起点、频率、增长曲线及恢复约束未定 | 任意构筑下的有限终局尚无保证；不能交付完整战斗参数集 | 推荐依据真实攻防和囤积收益选一套曲线，再检查极端防守／无伤害配置；首批短情境不启用未定义的疲劳，不作为完整对局结论 |
| P1 · FB-Q02（关联TL-Q06／10） | 当前“施法次数”只有储备支付价值，暂不随保留层数持续增强；普通／兑现两用途未必都值得选 | “越打越强”和保留取舍仅部分落地 | 推荐先对照4层、5层、9层、满层和接近击杀的局面；再决定是否补一种保留层数收益。没有依据时不增加新状态 |
| P1 · FB-Q03（关联INS-Q01／02、TL-Q06） | 积蓄没有行动；原休整另两张是空名占位；取得链不完整 | 不能制作声称完整的休整三选一或另一流派路线 | 本批暂缓积蓄，案例休整按TL-34只恢复／跳过；后续一起补真实名词、动词与第三候选，以及各自取得和可运行组合 |
| P1 · TL-Q06／INS-Q01／02 | 全局法器／铭文库存及副本资格、合法组合、行动配方、初始套组、奖励／商店池与价格、路线节点规模不全 | 整局与随机内容不能由EX-001的值代替 | 先登记一段真实路线和同预算替代配置；每物件按内容合同填写，核对缺核心、兼容反例、真实取得及可负担性 |
| P1 · TL-Q04／INS-Q06 | 多牌批次内部牌序、实际卡数；多辅槽冲突、覆盖和同类层数映射未逐内容明确 | 批量生产和多修饰内容缺输入；通用D公式已明确 | 首批每批1张、每器1辅槽；以后每种多牌／多修饰内容同时给顺序、叠加和失败例。不要重问已采纳的D冻结、乘算及总序 |
| P1 · TL-Q02 | 其他标记的上限／溢出、期限共享／刷新、移除指向、战终冻结归属；周期登记并存／合并及预算不全 | 泛化状态编辑与周期内容缺规则，层数上限不能限制登记吞吐 | 逐种状态填完整生命周期；先采用少量即时状态。EX-001的上限10与战终清零仅适用于施法次数 |
| P1 · TL-Q03／INS-Q03 | 真实材料性质／阶级／配方、补给数量／周期、同阶选择、复合配方匹配、催化剂与托管维护／休眠加工规则未定 | 资源流派与特殊持续对象无法制作完整内容 | 先设计最短“直用或继续加工”链，同预算计入每道行动机会与新资源下拍可用；再处理特殊对象 |
| P1 · TL-Q01 | 背包容量、种类上限、每份占用和携带标签未完成 | 有材料的跨战选留缺参数 | 随第一条资源链给出实际携带表，连同未投入库存计算；检查高阶囤积是否吞掉环境取材价值 |
| P1 · INS-Q04 | 法器契合的实际效应、表现及与其他量值修饰的合成未逐项完成 | 完整契合内容缺输入 | EX-001暂不启用两护符的候选契合数值；后续逐项列基础／修正／最终值。TL-45保留 |
| P1 · INS-Q05 | 打造费用、地点／时机、耗时、取消返还、跨战／跨局保存未定 | 不应把“可打造”做成免费按钮 | 推荐先限定战前整备，明确一种成本与替代用途；打造容量和获取副铭文分开设计 |
| P1 · INS-Q07 | 发现前后信息、免费试配、长期知识的Qualified意图尚未形成完整采纳／保存合同 | 配方发现与长期知识UI需要规则落点 | 推荐一次补齐发现状态、反馈、可读字段及知识保存；已有战前重配可做。战中重铭当前不提供，无需再询问是否已开放 |
| P2 · TL-Q05 | 附属物、其他类敌牌副记号、复杂敌人标记及意象出处未完成 | 扩展敌人内容受限 | 首批只攻击与打断，无护甲／附属物／其他类敌牌；制作正式文案时逐条核实意象 |
| P2 · TL-Q09 | 付费干涉具体能力、额度／单位、费用、时长、回充和共享未定 | 干涉操作暂不制作 | 等基础循环有明确不能解决的需求，再设计最少能力；不把取消敌牌行动改为直接施放 |
| P2 · META-Q01 | 局外成长尚未设计 | 不设局外属性、实体解锁或成长界面 | 先明确局内构筑和知识记录之外的需求，再决定是否需要独立系统 |

## 体验风险与最小验证（TL-Q10）

以下是待验证假设，不是已观察缺陷。获得具体测试任务后再执行；当前纸面核对只确认规则与算术。

| 风险 | 出现条件 | 最小检查 |
| --- | --- | --- |
| 共享行动出口使精炼挤掉防御 | 多道加工占用普通队列 | 同预算直用／短精炼链，对比实际防护生效而非只加D |
| 长批次或高优先级产线长期占位 | Q小、预留久、竞争强 | 记录一次关键防护从等位到兑现的完整等待；检查是否有可达替代 |
| 周期收益脱离普通出牌预算 | 独立登记持续增加但只给层数上限 | 分开数并存登记、未来总收益和实有层数 |
| 自动消费迫使玩家反复锁解 | 多消费者争同类资源／标记 | 区分有新信息的调整与重复维护同一计划的操作 |
| 配方发现变穷举 | 免费尝试，词义不能预测结果 | 先记尝试前理由，再看新反馈是否改变下一次预测 |
| 固定敌表只剩背板 | 隐藏Δ必需，或每轮唯一停供时刻 | 同敌表换实际库存、生命和队列，看是否出现有理由的不同判断 |
| 成长无实际收益 | 取整／D下限／排队抹平修饰 | 比较最终整数D、实际生效及支付，不只面板倍率 |
| 组件取得不支持构筑 | 发现配方却长期凑不齐器具／实体 | 用真实路线和库存逐节点核对可部署配置 |
| 拖战囤积支配现场取材 | 可积累、跨战携带，而疲劳未成约束 | 比较主动结束与继续拖战的净收益，连同生命和携带预算 |
| 少量对象仍有过多账目 | 预留、托管、冻结、锁定和预告同时出现 | 让玩家解释一次失败和下一步选择，记必要查阅及误判 |

## 本轮已处理

- 零材料配方明确允许；无需铭文与无需材料分开。多用途只影响未来批次，见CORE-059。
- 首批两护符都兼容迅速；一枚只装一处；契合暂不计入首批。
- 同时完工按战前法器序，不要求永不同时完成。
- EX-001重算开工／完工／生效、容量、13拍打断和标记余额；原稿错误不进入当前案例。
- 原登记第11项是误加序号，已关闭；第5项原用户允许忽略，本次新案例按现行规则重新书写。
- 通用总序、D公式、支付承诺和保存合同已完成，不再列为待选择问题。
