# 当前设计问题

2026-10-23 · game-002。这里是主系统开放设计问题与体验风险的唯一工作清单；工程Bug、制作缺口与运行证据留开发／代码记录。旧轮次已经回答的问题不会因整理重新打开。

## 开发前先看

用户已确认：2D是同一游戏的新表现方向，保留3D工程与证据；**先闭合首场核心玩法，再启动2D实现**。尚未选择新的主动调度机制，也未替换CORE-063的三维宿主条款；暂停停点与音画已由CORE-064更新。[直接答复与范围](../sources/inbox/2026-10-18-development-system-review.md#本轮批量澄清)。

| 顺序 | 必须解决什么 | 完成时应能回答什么 |
| --- | --- | --- |
| 1 · FB-Q01 | 零材料首批的主动调度支点 | 玩家何时可以改变什么；影响当前还是未来批次；代价和失败是什么 |
| 2 · FB-Q02 | 积累、保留与兑现的实际取舍 | 同一合法局面下，至少两种选择何时各自有理由；不用视觉强度代替收益差异 |
| 3 · 首场内容输入 | 按选定行为核对两护符、标记、敌程序、初态、胜败及完整恢复 | 内容能把目标玩法演出来；哪些配置只用于回归，哪些是新首场输入 |
| 4 · PRE2D-Q01 | 新2D展示合同与CORE-063的适用关系 | 二维操作、卡面、近观、系统页和精确读数如何承载既有行为；哪些3D限制仅保留旧方向 |

首场之外的路线、商店、完整资源链、复杂标记、打造和局外成长保留延期。若首场选用了其中某项，其依赖必须在同一设计轮补齐；不能以“延期”掩盖实际使用的缺规则。

### PRE2D-Q01 新表现方向的展示合同

状态：Open / Raw，来源为[2026-10-18整理要求与Q1答复](../sources/inbox/2026-10-18-development-system-review.md)。已确定同一游戏、先主系统后2D；尚未定义二维操作宿主和页面关系，也未完成具体资格、Draft Change与采纳。

推荐：保留自动推进、公开信息、事件结清、暂停／单步／载入及失焦的现行行为（停点沿CORE-064）；针对新方向列出CORE-063三维宿主约束的限定替代。保留3D旧包及原合同证据。引擎选择、工程拆分和复用代码不在本问题中猜定。

## 体验风险与最小验证（TL-Q10）

以下是待验证假设，不是已观察缺陷。获得具体测试任务后再执行；当前纸面核对只确认规则与算术。

| 风险 | 出现条件 | 最小检查 |
| --- | --- | --- |
| 共享行动出口使精炼挤掉防御 | 多道加工占用普通队列 | 同预算直用／短精炼链，对比实际防护生效而非只加D |
| 长批次或高优先级产线长期占位 | Q小、预留久、竞争强 | 记录一次关键防护从等位到兑现的完整等待；检查是否有可达替代 |
| 周期收益脱离普通出牌预算 | 独立登记持续增加但只给层数上限 | 分开数并存登记、未来总收益和实有层数 |
| 自动消费迫使玩家反复锁解 | 多消费者争同类资源／标记 | 区分有新信息的调整与重复维护同一计划的操作 |
| 配方发现变穷举 | 免费尝试，词义不能预测结果 | 先记尝试前理由，再看新反馈是否改变下一次预测 |
| 固定敌表只剩背板 | 隐藏Δ必需，或每轮唯一停供时刻 | 同敌表换实际库存、生命和队列，看是否出现有理由的不同判断 |
| 成长无实际收益 | 取整／D下限／排队抹平修饰 | 比较最终整数D、实际生效及支付，不只面板倍率 |
| 组件取得不支持构筑 | 发现配方却长期凑不齐器具／实体 | 用真实路线和库存逐节点核对可部署配置 |
| 拖战囤积支配现场取材 | 可积累、跨战携带，而疲劳未成约束 | 比较主动结束与继续拖战的净收益，连同生命和携带预算 |
| 少量对象仍有过多账目 | 预留、托管、冻结、锁定和预告同时出现 | 让玩家解释一次失败和下一步选择，记必要查阅及误判 |

## 下一批一起处理的问题

下一设计轮主动使用grill-with-docs，先查本页及现行案例，不把下面推荐当用户已选择。

| 编号／依赖 | 待决定 | 推荐与影响 |
| --- | --- | --- |
| FB-Q01-A | 首场主动调度通过未来批次启停，还是有限材料供给 | 推荐先研究未来批次启停：不取消当前承诺，较少引入内容依赖；必须明确操作时点、恢复与机会成本 |
| FB-Q01-B，依赖A | 该调度要支持哪些真实决策场景 | 推荐至少覆盖转防、准备兑现与避打断；每个场景列改变前后和代价，不承诺所有威胁都可化解 |
| FB-Q02-A | 保留标记是否需要持续收益，还是现有兑现已足够 | 推荐先比较4／5／9／满层与接近击杀局面，再选是否新增机制；避免提前加状态 |
| 首场输入，依赖前项 | EX-002保持回归，还是另立新首场案例 | 推荐保留EX-001／002原值与失败预期，新规则确认后另给明确配置；不改历史结果 |
| PRE2D-Q01，依赖首场行为 | 二维主桌、近观和系统页怎样分工 | 推荐先以实际首场操作列信息／输入合同，再做代表状态；C1—C3沿用，不先扩到全部页面 |
