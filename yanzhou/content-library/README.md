## 各写一处

- **设计方法、目标、体验与取舍**：写[系统设计手册](../system-design/handbook.md)及对应分册。教学例子可以引用具体物件，不另维护整张物件表。
- **具体物件、文案、规格与配方**：只改[catalog.json](catalog.json)。`items`存物件，`recipes`存具体配方，`builds`存构筑草稿；库内ID是定位键，保留原稳定身份，不另发FX／CORE编号。页面逐项显示范围、状态、来源与Unknown。
- **精确通用行为与内容填写合同**：仍在`design/`。规则不因物件出现了某个字段而自动扩展；案例初态、操作与预期结果仍由原案例维护，引用本库的对应内容版本。
- **历史输入与资格**：仍在`sources/`；旧交付HTML保留版本，不作为本库的第二个活动编辑入口。

`alchemy.md`、`ex004.md`、`reserve.md`、`sample.md`、`visual.md`、`recipes.md`、`builds.md`和`index.html`均由同一数据源生成，不能只改其中一个。EX-004分册仅包含该案例已采纳对象；全库中Raw／Qualified候选不因与其并列而获得采纳。

维护时先沿原流程记录意图及资格，再更新相应条目和来源。Raw可以作为明确标注的工作稿入库，不能当正式GDD、正式素材或Accepted规格使用。只有实际采用的字段才填写；未知写Unknown，不把空值补成0。
