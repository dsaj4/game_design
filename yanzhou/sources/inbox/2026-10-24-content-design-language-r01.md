### 语言要服务的判断

| 目标 | 本轮采用的手段 | 玩家应能看出的区别 |
| --- | --- | --- |
| 玩家安排生产、保留与兑现 | 明示载体、费用归属和读取时点 | 换用途改变下一批；整理改变成品位置；付层数改变这一步结果 |
| 玩家能解释自己的组合 | 同词同义，基础／修饰／契合来源可追溯 | 是哪个已装组件改变D或卡效；同主题名字本身不产生联动 |
| 内容便于比较和调整 | 参数变化与能力变化分开表达 | 改伤害量、费用或D，与多一个目标／事件／产物是不同改动 |
| 有可学习的特殊语言 | 共用获得／消耗／炼成动作，特殊对象保留稳定名字；复杂关系确有必要时才设词条 | 读到“获得1「咒」”知道增加的是哪种标记；读到“炼成”知道是生产结果，具体作用仍由产物定义 |

这是设计功能与体验假设；易懂、好玩、平衡均未获得验证。

## 2. 五种语言成分怎样连接

| 成分 | 职责 | 例子与关系 |
| --- | --- | --- |
| 语法用语 | 指定读取、支付关系、替换和步骤依赖 | “拥有”“改为”“成功后”，以及“消耗……，执行……”的支付结构；连接规则，不是可装配物件 |
| 基础动作 | 直接说明一次状态变化 | 行动卡获得／消耗资源或标记，法器炼成产物，以及造成普通伤害、获得护甲、取消指定敌牌。可写出不代表所有载体都有执行权限 |
| 机制词条 | 给值得复用的复杂行为关系起短名 | 候选“封缄”封装有对象限制和截止条件的取消；获得、消耗这类基础动作无需再加专名 |
| 世界观术语 | 提供对象身份和语感 | “咒”是施法标记名，“火露”是资源名，“止语”是候选行动名；名称不能替代对象定义或自动赋予能力 |
| 实体铭文 | 玩家实际持有、占用并装配的对象 | “打击”“迅速”具有已声明词性、词义和兼容关系；一枚一处。它可提供某项效果，但词条不自动变成铭文 |

关系是：**实体铭文装入合法位置 → 与法器预设形成已声明用途 → 开工承诺批次 → 炼成行动卡 → 行动按其语法和词条执行。** 中间工序炼成共享资源沿其已局部确认结构及待定接口另列。世界观命名横贯对象；语法与词条描述各阶段发生什么，不另加一层装备。

例如“迅速”是既有实体副铭文的名称；其已有作用写“本法器D−1”，不需要再造一个“疾咒”词条。“止语”是候选行动名，“封缄”是它可能使用的取消机制名；持有止语行动卡、安装某枚铭文和拥有封缄权限不能互相替代。

依据：[铭文TL-26／28／39—41](../../design/systems/inscription-system/rules.md)、[辅槽修改权限](../../design/systems/inscription-system/augment-system/rules.md)及[内容合同](../../design/content/cards.md)。跨对象复用一个词条只复用同一含义，各载体仍须分别获得内容授权。

## 3. 受约束的句法初版

完整含义仍按框架顺序记录：**来源与载体 → 读取时点 → 目标及选择 → 条件与费用 → 结果 → 步骤依赖、失败与结束**。玩家文本按实际判断需要裁剪；下面是编写约定候选，不是自由输入法术或通用条件脚本。

### 3.1 主要句式

| 用途 | 建议写法 | 关键限制 |
| --- | --- | --- |
| 直接行动 | 对〔明确目标／自动选择规则〕，〔基础动作与量值〕 | 己方在生效时按承诺规则选目标；不能省成含糊的“对一个敌人”，让人误以为可临时手选 |
| 行动获得 | 〔受益者〕获得〔数量〕〔资源或标记名〕 | 按对象定义增加资源量或标记层数；受益者只有在上下文唯一时才可省略。获得不等于立即可消费，仍沿对象可用时点 |
| 行动消耗 | 〔付款者〕消耗〔数量〕〔资源或标记名〕，〔明示结果〕 | 表示该步骤的支付；不自带增伤、替换、回退或退款，这些关系另写。不能因为用了同一动词就获得消费所有对象的权限 |
| 只读条件 | 若〔宿主〕拥有至少〔n层指定标记〕，则〔明示结果〕；否则〔明示结果或不执行〕 | 只读不付费。当前简单条件范围沿ACT-Q2，不由句法扩大成队列、资源或任意事件查询 |
| 支付增强 | 若〔完整费用可支付〕，消耗〔费用〕，将本次〔指定结果〕改为〔增强结果〕；不足则〔基础结果〕 | 这是自动分支，不暗示生效时弹出选择。目标失格不靠回退绕过；每步沿TL-30同状态检查 |
| 法器生产 | 投入〔完整配方〕，加工〔D生产拍〕；幸存完工时消耗投入，炼成〔数量〕〔资源或行动卡〕 | 统一生产用词，产物类型仍须明确。炼成行动卡只交付卡，不立即执行卡效；中间资源的具体承诺与可用时点另待裁决 |

这些句式能覆盖当前样本，只填写实际采用的部分。自然语言可表达更复杂结构，也不能越过载体权限。资源条件、催化保有、自动择一和复炼仍是候选能力，不能把它们塞进“若……”后就视为合法。“获得／消耗”统一资源和标记的表达，不把资源归并为标记；伤害继续直写，生命／护甲继续沿各自专门规则。

### 3.2 连接词的裁决边界

| 表达 | 本轮沿用或建议的明确含义 | 不采用的含糊写法 |
| --- | --- | --- |
| 拥有／检查 | 读取声明范围内的实有状态，不消费、不占用；与可消费量区分 | “需要5层”同时承担持有门槛与支付费用 |
| 获得 | 在该行动步骤增加明确对象的数量；生成、上限、超出与可用时点由对象定义 | “获得资源”被理解为可在同一结算阶段立刻投入加工 |
| 消耗 | 属于指定步骤的费用，足额检查通过才支付；无声明不另收费 | “使用材料”却不说明是读取、制造还是卡效支付 |
| 投入……完工消耗 | 开工承诺普通制造料、幸存完工结清；失败沿对应批次合同 | 开工先写“消耗”，完工又扣一次 |
| 炼成 | 法器生产形成明确资源或行动卡；其产物身份、数量和完成阶段有据可查 | 炼成行动卡被读成当场执行攻击；或自动升阶、增值 |
| 改为 | 替换被指明的结果；同一结果不同时执行基础与增强 | “伤害6，消耗5「咒」造成18伤害”却不说明18替换6还是另加 |
| 额外 | 保留原结果，并增加明确对象和数量；增加事件仍须独立权限 | “额外施放”偷带新行动、新目标或无限反应 |
| 随后 | 指定允许阶段内的步骤次序；不单独建立成功依赖 | 用“随后”代替“前步成功才执行” |
| 成功后 | 仅在被明确指认的步骤成功，且未因终局停止时继续依赖步骤 | “命中后”暗示必须损失生命；或“施放后”混同空放与成功 |
| 下一批 | 设置生效后下一次成功开工承诺的批次 | 回改当前加工或既有成品 |

“成功”不在语言层偷偷统一为“造成正数伤害”。具体步骤的成功判定由其行为依据维护；当前样本直接沿EX-004。未来出现零量值、部分多目标成功等内容时，须在模块3补清，不能把本轮正数例子外推为通则。

**句子顺序不能改结算组。** 简易护盾的护甲在防护组，依赖的“获得1「咒」”在其余组；不能因两步都使用“获得”就合并为同一阶段。复合牌在完整描述中注明各步骤所属组及依赖；同组按声明序，跨组按TL-11。一个基础步骤仍是一个完整事件，不因写成一句话而合并终局检查。

依据：[行动TL-11／30](../../design/systems/action-card-system/rules.md)、[GDD TL-21](../../design/GDD.md)、[标记读取与支付](../../design/systems/action-card-system/mark-system/rules.md)。

## 4. 词条何时成立、怎样命名与缩写

### 4.1 成立条件

建议同时满足以下条件才作为机制词条保留：

1. **值得复用。** 至少有两项内容使用同一行为关系，或它明确承担一个构筑中心；第二种情形先保留候选，待真实内容组检验。只把“伤害＋2”改成神秘名通常没有必要。
2. **展开唯一。** 同载体、同状态、同参数能得到同一解释；能回答宿主、读取、支付、依赖、失败和结束，未定处不能藏进简称。
3. **权限明确。** 指出来自固有效果、合法核心、辅槽或契合；名称本身不授权跨法器传递、增加事件或越过阶段。
4. **短名有预测价值。** 短名比完整重复段更便于识别，而且白话释义不依赖另一个陌生词。
5. **有对照和反例。** 至少能解释一次正常用法与一次容易误读的情况；只凭名称好听不晋级。

“两项复用”是本轮工作门槛建议，不是既定全局数量限制；封缄等首个内容可先作为中心候选，不能为了凑门槛虚构第二张卡。

### 4.2 命名家族与保留词

| 家族／用途 | 建议 | 限制 |
| --- | --- | --- |
| 行动增减与对象命名 | 已确认共用获得／消耗，后接数量与资源或标记名；“咒”为一种施法标记 | 共用动作不合并对象类型；新资源和标记仍须有完整定义，不能把所有对象称为“咒” |
| 制约敌方后续 | “封缄”作为取消的专名，“止语”可作行动名 | 不与打断加工、沉默来源敌人、延后敌程序混用 |
| 法器生产 | 已确认法器生产统一用“炼成”，包括中间资源和最终行动卡；器具／工序的其他命名用字仍为建议 | 产物类型及可用时点分别记录；不定义“凡带炼字就提阶”之类隐规则 |
| 加工可靠性 | “专注”保留原用户种子的含义方向 | 不扩成护甲、抗伤或成品牌保护；作为新增能力单列 |

语感优先简洁、可读、能与白话关联，不强求所有名字都两字或都带“咒”。这些是命名方向，不新建玩家必须学习的分类树。

**规则正文保留词：** 法器、铭文、用途、批次、工序、行动、资源、标记、护甲、生命；生产拍、回合、结算列；获得、投入、消耗、炼成、改为、额外、成功后、下一批。它们不另作含义不同的机制词条。正式对象名可以含这些字，但须有对象类型上下文，例如“强化打击”仍是行动名称，不是通用强化规则。

已有多义操作必须带限定：“玩家消费锁定”与“敌方目标锁定”分开；“开工冻结”不写成状态词“冰冻”。旧“预留”不得用于恢复成品牌位Q；若以后设计资源保留能力，必须明确是未定的新合同。

“蓄言、承句、催化、复行”暂保留为候选名称，不在R01词典中赋予可执行的现行定义。“冰冻、燃烧、回响”不因常见语感而默认拥有控制、持续伤害或追加事件。

### 4.3 同义、参数和变体

- **同一含义只有一个规范写法。** 在规则句中用“造成普通伤害”，不轮换“击中／削血／灼伤”；普通伤害可能先消耗护甲。氛围文案可自由表达，但不参与裁决。候选定名后，别称只作查找入口，不作为第二套定义。
- **同名跨对象须保持含义。** 获得／消耗可用于资源或标记，动作含义一致，实际对象与数量不能省成“获得2”。炼成始终描述法器生产，行动卡的资源效果写“获得”。
- **参数改变不换动作。** “获得1「咒」”和“获得2「咒」”都表示增加同种标记；数量合法域、计量单位与上限归对象定义。对照现行样本时，1「咒」对应1层施法次数；资源按自身份数计，行动卡写明张数。数量示意不自动发行新参数或改变上限。
- **结果分支不是裸数字参数。** “消耗5「咒」，本次普通伤害改为18；不足为6”仍须说明合法支付条件和被替换结果，不能压成“消耗5/18/6”。“炼成2「火露」”必须能定位资源定义，“炼成1张「简易攻击」”须能定位行动定义。
- **改变宿主、支付阶段、目标集合、事件数或生命周期，是行为变体。** 不同阶段可以沿用同一个“消耗”动词，但开工冻结、完工结清和行动步骤支付分别写清，不能因共用动词混成一笔费用。D、产量和伤害分别改，不通过“高级”自动同时提高。
- **重复出现不默认叠加。** 两个来源都提供同词条时，是否相加、覆盖、分别执行或不兼容沿明确内容；未声明就保持组合未定义。词条存在也不自动成为其他卡效可读取的标签。

### 4.4 简写、展开与例外

设计侧保留完整含义；玩家侧可有“短名＋本件参数”的摘要和一层直接白话展开。首次接触能获得完整白话，熟悉后可缩短重复部分；具体呈现交A，沿C1—C3，不重选UI。

**不能从判断入口消失的信息：** 影响本次选择的支付数量、基础／增强结果、目标资格、截止条件和关键例外。隐藏的来源明细可以展开；当前批次承诺与未来设置不能合成一个含糊的“效果”。预览须标明依据当前状态，不承诺一定到手、一定保住或一定成功。

例外建议写“本用途例外：〔覆盖哪一条〕；〔适用对象与时点〕；〔代价和失败〕”。若它改变词条核心含义，就用完整白话另列新能力，不允许“封缄，但也能取消暗牌”仍冒充同一词条。例外文本依然需要设计资格与采纳，写明例外不等于获准。

## 5. 首批语言：获得、消耗、炼成与特殊对象

本节按用户最新设计修订。获得／消耗是行动卡处理资源与标记的共用动作，炼成是法器生产用语；“咒”作为一种施法标记提供对象身份。其他专门机制仍为候选。参数来自既有样本时只在其限定范围成立，新增物件和资源尚未补齐，不作为可发行内容。

| 用语／对象 | 白话展开与载体／阶段 | 与现行规则的关系 |
| --- | --- | --- |
| **获得〈数量〉〈资源或标记〉** | 行动效果为明确受益者增加对应数量；例如获得1「咒」、获得2「火露」。前提、成功依赖、执行组及可用时点沿该步骤与对象定义 | 用户确认的统一表达。即时标记可供后续合法步骤使用；行动产生的新资源最早下一生产拍可用，不因共用“获得”而同速可用 |
| **消耗〈数量〉〈资源或标记〉** | 从明确付款者的合法可消费量中足额支付，再执行明示结果。例：消耗5「咒」，本次普通伤害改为18 | 用户确认的统一表达，沿TL-30。动词本身不携带增强、回退或获得标记的后续效果；这些内容分别写明 |
| **炼成〈数量〉〈产物〉** | 法器加工完成产生所声明的资源或行动卡；例如炼成2「火露」、炼成1张「简易攻击」 | 用户确认的法器生产统一用语。行动卡产物沿现行生产合同；中间资源沿DIR-041局部确认结构，承诺与可用时点仍待闭合 |
| **咒〔施法标记〕** | 一种具体标记名称，可出现在获得／消耗的对象位置；不是基础动作，也不是实体铭文 | 用户明确的对象设计。为对照既有小样，本稿暂以「咒」表达EX-004原「施法次数」的余额与效果，不另添第二份余额；这是样本表达映射，未修改现行GDD或扩定其他施法标记 |
| **封缄〔候选〕** | 行动在其结算列的其余组执行；R01第一版选取更右侧最左一张已公开、已铺桌且可取消的敌后续牌，取消后空位保留；无目标空放 | TL-10已有权限接口；选择规则与止语内容仍是新候选。不是已发行首场卡，不取消暗牌、敌手牌或同列行动 |
| **专注〔候选〕** | 由法器固有能力为批次提供保护；若后续打断命中具有此保护的在制批次，不执行中断结果。批次照常推进；保护随该批结束。仍按原规则可被敌锁定，不转锁第二法器 | 相对TL-07／12新增免打断例外，Raw。来源暂建议固有效果，不能塞进现行辅槽权限；不保护生命、不追溯成品、不解决缺料或溢出 |

### 统一语言之后仍要保留的解释

- **动作通用，对象独立。** 「咒」属于标记，「火露」属于资源；同样可以写获得／消耗，但宿主、上限、可用时点、制造资格和战终保留分别定义。名称「咒」不自动说明其他施法标记的分类或行为。
- **获得不自动意味着成功后。** 无条件获得与依赖前步成功的获得是不同写法。EX-004护盾的标记步骤依赖加护甲，攻击的标记步骤依赖伤害；致死后终局停止，不补后面的获得。
- **消耗不自动意味着增强。** “消耗5「咒」”只说明费用，替换哪项结果和不足时做什么须明确；无目标不支付。支付前检查的量值不因本步扣量重新计算，同一笔制造料不能在行动生效时再扣一次。
- **炼成不等于施放或升阶。** 炼成行动卡只完成生产；卡是否保住、上桌和执行另沿既有规则。炼成资源也不保证提高阶级、稀有度或价值，中间资源何时可用仍由对应工序合同决定。
- **封缄的目标规则不可隐去。** “更右、公开、后续、可取消、最左一张”共同限定目标；最左只是候选内容的固定优先级，不推广为全部取消能力的通则。
- **专注须先承担真实代价再进内容组。** 数值、兼容、取得和替代收益均Unknown；目前只能审阅能力含义。剩余加工最长者可能吸引后续打断、保护其他法器，是候选的组合风险，不能只按单器收益定价。

现行样本与规则依据为[EX-004 §3](../../design/examples/round-first-battle.md)、[GDD TL-10](../../design/GDD.md)、[法器TL-38](../../design/systems/artifact-system/rules.md)及前述TL-30。“专注／封缄”的旧命名线索见[DIR-037 §3](../../exploration/DIR-037-effect-framework/README.md)，按本轮回合语义限定；旧稿将炼成用于资源行动的命名不再沿用，旧Q、最早下拍翻开、不能留牌等条件也不迁入。

## 6. 三个最小表达对照

### 6.1 现行储层兑现：统一动作仍能表达完整分支

以下只改读法，数值限定EX-004，不重列其配装、敌表和整战路线。

| 对象 | 可供审阅的短表达 | 完整解释须补明 |
| --- | --- | --- |
| 简易护盾 | 自身获得4护甲。该步成功且未终局后：**获得1「咒」** | 护甲在防护组，获得「咒」在其余组；不是完工就加护甲／标记 |
| 强化打击 | 对存活来源敌人造成6普通伤害。**若可消费的「咒」足5，消耗5「咒」，将本次伤害改为18；不足仍为6。**伤害步骤成功且未终局后：**获得1「咒」** | 在攻击步骤读取可消费量，足额自动支付，无目标不支付；之后获得「咒」是独立的依赖步骤 |

短文加共同规则才能得到完整语义。首次遇到「咒」时解释其为施法标记并给出作用；对照现行样本时，1「咒」对应1层原施法次数。共用动作后，玩家学习的是对象的用途与实际分支，不必再为获得和支付分别学习一个专名。

最小反例：实有5「咒」、其中1被玩家锁定，强化打击仍因仅4可消费而走基础结果；拥有量与可支付量不能互换。另一个反例是目标已不合法：不能支付后凭空造成伤害或补获得标记。这里做的是描述等义核对，未执行战斗计算。

### 6.2 止语：行动名、词条和目标截止各自有用

建议表达：**止语〔候选行动名〕——封缄：取消更右侧最左一张已公开且可取消的敌后续牌。无合法目标空放，取消后空位保留。**

作为来源用途的完整内容，还需声明D、配方、兼容和类别；封缄不自动决定类别，也不因“打断类”就进入防护组。最小表达检验是：若唯一公开后续在本列或左侧，不能取消；改变止语位置可能改变合法目标。EX-004后续都落在第1列，不能为展示词条改其敌表，也不能声称这里已有成功取消情境。独立纸面敌情留待相应内容任务，不在本轮重造。

### 6.3 炼露炉：相同资源名不能抹平交付阶段

沿框架第8节小样，只抽出一段：

> **工序候选：投入1「原露」，加工1生产拍；完工消耗投入，炼成2「火露」。产物可用时点：待总控裁决。**

另一条结构则写：法器**炼成1张资源行动卡**，该行动卡的效果为**获得2「火露」**。这表示先交付行动，正常留存并结算该行动后才得到资源，最早下一生产拍可用。资源数量相同，但前者的生产结果直接是资源，后者的生产结果是行动卡；后者还要经历行动的留存和执行机会。法器生产都用炼成，交付阶段通过明确产物类型与行动正文区分。

可排列工序、中间产共享资源而不产行动卡，已在DIR-041 R03局部确认，直接沿用。它是相对现行TL-38的新生产结构，尚不等于现行首场已接入。逐段承诺、资源可用时点、法器序争料和无隐含自用保留，仍沿框架所记总控待决，不在这里选定或重复发问。共享火露被别器合法消费后不能再供本器重复消费；连线、主产或“随后”均不赋予独占权。

本段数值仅用于表达比较，不外推净收益、停机点、整局成长或平衡。

## 7. 交给模块2—3的最小边界

模块1定义“怎样读写”，模块2定义“哪类对象需要哪些信息”，模块3维护词条／状态／配方的完整行为。词典引用唯一行为依据，不在语言页另存第二套裁决。

| 来自本轮的具体需要 | 模块2最少保留的信息 | 模块3须决定的行为边界 |
| --- | --- | --- |
| 判断获得的是什么、是否发生 | 载体、资源／标记类型、对象名、数量、受益者及必要成功依赖；「咒」对应哪种标记 | 各对象的生成、上限、失效与可用时点；现行样本中的「咒」沿原施法次数内容，其他对象逐项定义 |
| 比较消耗与所得结果 | 明确付款者、对象及数量、基础与增强结果、读取阶段；制造／整理／卡效三笔账分开 | 新支付种类、非数值增强是否合法；消耗本身不决定回退，没有声明就不能擅自保基础 |
| 知道修饰改变了什么 | 基础值、实际生效的修饰来源、被改位置；当前批次与未来用途分开 | 重复来源的叠加／替代／冲突。现行辅槽不能改张数、目标或新增事件 |
| 解释封缄的合法性 | 候选目标、选择规则、公开状态、所在列及实际截止 | 各取消内容的权限范围；类别与结算组分开，不能仅靠类别授予能力 |
| 分清炼成产物和行动效果 | 炼成的是资源还是行动卡；若为行动卡，另列其获得／消耗等效果；两者各自的发生阶段与可用阶段 | DIR-041接口与现行TL-38如何正式衔接；统一动词不消除接口差异，承诺、争料、可用时点由总控集成 |
| 保持装配可解释 | 法器预设、核心空缺、实体身份、兼容、辅槽挂接、产物关联 | 工序与实体铭文如何映射；同词性／同主题不自动兼容，不先定新增槽或自由句法 |
| 避免标签替代规则 | 对象身份、确有用途的分类／属性及被哪个条件读取 | 属性、分类、稀有度、材料资格各自职责；未选五行／炼金体系，不凭名字推导配方 |

以上是信息需求，不是A的页面结构任务。C负责稀有度投放、取得频率、替换经济和成长跨度；本轮不替C填概率、价格或阶段。敌人、共同参数、战终保留和跨线取舍由项目总控集成。

为后续流派保留三种真实差异即可：用法器生产效率支持更多可用行动；通过获得／消耗「咒」安排储备与兑现；用共享材料连接加工者与消费者。三者分别受留存／执行机会、即时余额／支付、材料归属／可用时点限制。不把这三种职责预先变成新的流派标签，也不据此宣布已有三套成立的构筑。

## 8. 本轮静态核对与未验证部分

| 容易出现的错误 | R01处理 |
| --- | --- |
| 用统一动词省掉对象和支付条件；把拥有量当能支付 | 消耗明确对象及数量，锁定反例保留；拥有与可消费分开 |

后续获得相应验证授权时，可让读者根据统一动作与对象释义，预测锁定后的支付、致死后的依赖效果、同列取消，以及炼成行动卡和炼成资源的不同结果。若对象类型或可用时点被误读，先修正表达；若问题来自规则本身，则回模块3处理。此处仅记验证方向，未启动测试或安排实验任务。
