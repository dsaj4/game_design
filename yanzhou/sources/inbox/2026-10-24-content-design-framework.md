## 2. 共同设计目标

内容总控先固定以下判断依据，再展开各模块；未定项可占位，不阻止不依赖它的工作。

1. **玩家选择。** 明确配置法器、装配铭文、选择用途、安排配方、调整成品等行为各自改变什么；现行权限与候选权限分开。
2. **成长变化。** 识别效率改善、适配拓宽、不同兑现方式、新组合关系分别带来什么选择；不把成长默认写成所有参数同时提高。
3. **语言体验。** 玩家能理解哪个词改变了哪段生产或效果，并能追溯法器、批次与行动之间的关系；神秘命名配稳定白话释义。
4. **复杂度依据。** 每增加一种信息、类别或规则，都要说明它改变哪项玩家判断。字段数量、词条数量与体系完整不作为深度证据。
5. **规则边界。** 已定机制直接复用；新增能力单列，不能因同名、自然语言通顺或分类相同推导未声明的权限。

## 3. 六个设计模块

| 模块 | 设计范围 | 交付与进入下一轮的依据 |
| --- | --- | --- |
| 1．效果语言与特殊用语 | 基础动作、效果句法、条件与支付、步骤连接、命名、词条、简写及展开规则 | 语言规范与必要词典。不同设计者能把同一行为写成同义描述；读者能判断主要结果、代价、时点与限制。玩家可理解性仍须验证 |
| 2．物件信息规范 | 法器、铭文、行动、资源、标记分别记录／展示什么；信息服务规则、配方、比较还是表现；区分固定信息、装配结果和运行状态 | 各类对象的信息清单及每项用途。没有实际使用者或功能的字段不为填表保留；信息需求与具体UI布局分开 |
| 3．专用系统与配方规范 | 词条／状态行为、属性体系、分类体系、稀有度职责；配方资格、兼容、替代、转化和例外 | 各体系内部规范与相互关系。能解释为什么能装、能用、能作材料；冲突有唯一解释，不由标签暗送能力 |
| 4．流派与成长结构 | 预期体验、核心决策、积累与兑现、组件职责、联动、弱点、替代、混合空间和未成型到成型的变化 | 少量结构不同的流派轮廓。说明优势来源、缺组件时怎样玩、何时换策略，以及成长改变什么选择 |
| 5．具体物件与配方设计 | 法器、铭文、行动、资源、标记与具体配方；身份、来源、兼容、投入、D、产出、支付和失败 | 可组成完整构筑的内容组，包含合法替代和失败情境。先检查少量组合，再扩内容池；字段完整不自动晋级资格 |
| 6．综合平衡与体验验证 | 单件价值、组合强度、构筑可达性、成长节奏、敌情适用性、理解负担和实际选择 | 按授权获得证据后提出有条件的调整结论；区分数值、机制、投放、表达和操作问题。计划、静态推导、程序检查及真人证据分别记录 |

## 4. 模块1：效果语法与言咒的特殊语言

### 4.1 三种语言成分

| 成分 | 职责 | 设计要求 |
| --- | --- | --- |
| 语法用语 | 连接条件、费用、步骤、替代与结果 | 固定“消耗”“改为”“成功后”等表达的含义，让句式能够帮助预测关系 |
| 机制词条 | 为一段可复用规则提供短名 | 一词一义、载体与作用阶段明确、边界可查；参数变化不随意换名 |
| 世界观术语 | 命名器具、物质、力量和加工方式等 | 形成言咒语言风格，同时保持物件身份与行为可辨认；名称不独自授予能力 |

基础伤害、护甲等能直接说清的动作使用白话。成为词条的门槛是存在值得反复学习的共同规则，且短名帮助预测；不要求每个效果都有新名。效果词条不自动成为实体铭文或新装备槽。

须细化：命名家族与保留词；同义与歧义处理；跨对象复用边界；参数、条件与变体写法；简称／全称与首次解释；哪些信息可省略、哪些关键例外必须明示。第1模块维护语言和命名，第3模块维护机制的完整行为；词典引用行为依据，不双写两套裁决。

### 4.2 完整语义与对象描述

设计侧完整顺序：**来源与载体 → 读取时点 → 目标及选择 → 条件与费用 → 结果 → 步骤依赖、失败与结束。** 玩家描述按实际能力裁剪，不机械展示全部字段。

| 用语 | 约束含义 |
| --- | --- |
| 拥有／检查 | 读取状态，不表示消费或占用 |
| 投入……，完工消耗 | 制造承诺，与行动费用分开 |
| 消耗……，执行…… | 在该效果步骤检查并支付 |
| 改为 | 替换原结果，不同时领取两份 |
| 额外 | 保留原结果，增加明示结果；额外事件仍须权限 |
| 随后 | 步骤顺序，是否依赖前步成功另写明 |
| 成功后 | 前步成功才执行该段；实际成功判定沿内容与规则 |
| 下一批 | 改未来生产，不追溯当前批次或成品 |

法器重点是“装什么 → 合法用途 → 投入 → D → 产物”；行动重点是“对谁 → 结果 → 支付／条件分支”。第一眼展示关键结果、代价和限制；详情解释目标优先级、时点、失败与来源；运行态显示当前承诺、满足条件和等待原因。这是信息需求，不指定A的页面结构。

特色优先来自“改变哪个词，可以看见哪段生产或效果发生变化”：核心组合、预设挂接、加工承诺与成品兑现可追溯。词序承接、整句识别奖励等不随语言框架自动加入。

## 5. 模块2—3：信息、体系与配方的职责

“字段”保留为信息栏位；原先用来指“冰冻”等效果的字段系统，按确认后的框架称“词条与状态体系”。

| 概念 | 回答什么 | 例子与限制 |
| --- | --- | --- |
| 信息字段 | 对象要记录／展示什么 | 名称、D、属性、类别、效果描述；每项有用途与使用者 |
| 效果词条 | 对象具有哪段规则 | “冰冻”仅是用户举例；成为机制词条须另定行为，不视为已启用 |
| 状态／标记 | 宿主现在处于什么情况 | 若某行动施加状态，须分别声明宿主、生成、叠加、存续和解除；不自动迁移期限等旧扩展 |
| 属性 | 明示规则能读取哪些体系内性质 | 后续已确认炼金内部采用盐／固持、汞／流转、硫／激发；其他体系可另设内部性质。通用属性读取、替代权限仍须另定，不由三原质名称推导 |
| 分类 | 对象属于哪个法术体系 | 后续已确认分类按法术体系，例如炼金；不再设置并列的家族分类。器具形制、铭文词性、行动类别分别描述原有功能，不改变现行行动类别 |
| 稀有度 | 此物件承载多深的原理、多强的能力 | 已确认“原理层次与力量”主轴；等级名、档数、预算仍待定。单件能力与代价由物件设计说明，投放、取得与整局跨度对接C |

上述更新沿[世界与体系R01第6节](2026-10-24-content-world-systems-r01.md#6-分类按法术体系划分)及[阶段复核](2026-10-25-content-design-review-r01.md)。对象种类、法术体系、体系内性质和稀有度承担不同问题；器具形制等可按实际需要描述，不占用已确定的分类字段。体系之间的关联必须明示：分类不自动附送配方；属性不自动产生同名攻击；流派整理标签不自动成为卡效可读取条件。

### 配方通用规范须先于批量配方

先确定玩家通过配方作什么选择，再选择适合的属性表达。模块3至少覆盖：

- 要求指定物件身份，还是满足某组性质／分类的材料。
- 是否允许替代；替代保持结果还是改变产物；不合法的原因怎样解释。
- 数量、性质与阶级各影响什么，哪些不影响。
- 器具兼容、铭文兼容、材料资格怎样共同判断。
- 多个配方满足时怎样确定用途，选择与承诺发生在哪个阶段。
- 例外、冲突、支付、产物及失败由哪条规则唯一解释。

这些是待展开的设计问题，不隐含采用任意条件脚本、自动择一或新生产权限。

## 6. 模块4—5：流派、成长与完整内容组

流派记录：**核心体验 → 反复选择 → 优势来源 → 必要职责 → 可替代组件 → 成长变化 → 弱点与失败 → 混合方式。**

积累、兑现、调节生产、干涉威胁、加工衔接可作为设计侧职责分类，不能因此增加玩家必须学习的标签。连接须有实际载体并改变接收方，例如层数、材料或后续牌位置；同一主题名称不证明联动。

每个流派要覆盖未成型与缺关键件的阶段。供给者与消费者的兼容、共享通用件、专用件和替代关系须可解释；具体取得节奏交C，不能拿理论完整套组证明实际成长顺畅。成长可分别采用量值改善、成本改善、适配拓宽和新的配合方式；新增目标／事件／产物属于能力变化，不能藏在普通数值升级中。

模块5补齐各物件与配方实际字段，并沿[内容合同](../../design/content/cards.md)与[法器内容合同](../../design/content/wands.md)核对。配方是投入与产出的关系，不因本框架而自动成为一种实体卡。资源、标记也属于必要内容；敌人及共同参数由项目总控提供／集成。

平衡比较保留真实前提：装配占用、制造投入、D、执行机会、卡效支付、目标／截止、依赖及失败损失。不建立未经验证的万能强度分数，也不把生产数量直接当作有效收益。

## 7. 迭代与验证

推进顺序：**共同目标与边界 → 模块1—3初版 → 少量模块4—5样本 → 修订模块1—3 → 扩充流派与内容 → 模块6综合验证。**

第4模块在前期先提供少量构筑行为需求，检验语言、属性和分类是否有用；不必提前完成全流派。模块6负责综合验证，其余阶段在授权范围内尽早检查：

| 时点 | 最小检查与判断用途 |
| --- | --- |
| 语言初版 | 静态检查同义与歧义；未来读者根据描述预测结果，定位误解词语 |
| 属性／配方初版 | 用合法替代和相似但非法材料检验规则能否说明理由，避免背诵任意例外 |
| 流派初版 | 检查缺件、替换、加入通用件后是否仍有有效选择；记录不可达依赖 |
| 小内容组 | 检查明显支配、无用途组件、无界收益与不可恢复断链；静态推导不冒充试玩 |
| 综合验证 | 结合敌情、投放、整局成长观察玩家的实际构筑；实际执行需相应任务授权 |

分别判断语言、规则、组合、投放和操作问题；不以数值修补所有缺口。未执行状态保持NotRun，失败经验保留在相应设计来源中。

## 8. 2026-10-24接续样本与当时决定（历史）

本聊天此前三套小样只供检验表达和机制关系，用户认可其作为讨论基础，不据此提升为已实现或新规则Accepted：

1. **现行储层兑现。** 沿[EX-004](../../design/examples/round-first-battle.md)守护D1／施法D3，制造、整理点、卡效层数分别处理；正常与不足回退沿现行案例。未来设置不改当前批次。
2. **规则接口内的新取消内容。** 候选止语自动取消更右侧最左的已公开可取消后续，空位保留；无目标空放。调序可改变取消目标。EX-004后续只在第1列，没有合法目标，须独立纸面敌情，不能改该敌表。
3. **新增权限共享工序。** 炼露炉“原露1／D1→火露2；火露1／D1→6伤行动”，聚焰针“火露2／D2→12伤行动”。原露2有限投入下，炉先取料可两张6伤后跨轮12伤；针先抢料可能使炉停在封符、剩余原露不能继续加工。数值、实体映射、兼容和承诺均为候选，不是自养成长或平衡证据。
