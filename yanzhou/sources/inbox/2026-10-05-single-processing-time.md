# 法器生产简化：仅保留处理耗时

Project ID：game-002。日期：2026-10-05。文档角色：SourceRecord / IdeaInbox。状态：**Raw Idea / Unqualified；用户已明确简化方向，容量接口等边界待答**。证据：Hypothesis / NotRun。来源基准：`85fa475e6eee2acbc719c30cf691e6d02f8a8ab5`，GDD 2.1 / TL-1 + INS-1 / routing.1，GDD-0。没有实验或实现执行。

## 原始想法

用户在六阶段统筹聊天、阶段1第一批决定之后提出：

> 简化处理法器生产与编排的耗时，仅设处理时间耗时，无生产周期冷却、无完工后等待；

本条是用户新的设计要求，不是对上一轮五项推荐的整批同意。只保留处理耗时、取消独立生产周期／冷却和完工后等待的方向已明确，不重复询问是否简化。当前尚未说明有限战斗行已满时如何落实无等待；不将模型的容量预留方案当作用户决定。

## 触发来源

[六阶段统筹阶段1](2026-10-04-feishu-design-stage-research.md#阶段1第一批决定)中的S1-Q1–5。上一轮分别询问最早生效、行满时交付J、循环与D／J／R、时间域及临时供料恢复。本条改变生产耗时模型，应先更新问题，再继续配套情境；不能继续要求用户在旧J／R选项中作答。

### 已明确的变更意图

- 法器仅保留一段处理耗时；不再分别设置加工后交付J、休歇R和独立生产周期／冷却。
- 不再以完工后额外等待作为正常生产流程。正常情境可表述为“开工条件满足→处理→产出”；下一批不增加独立冷却。
- 处理耗时如何取值、下一批在同拍的哪个阶段启动仍未确定；“无冷却”不等于同拍免费完成下一批。
- 讨论对象是法器生产与编排；行动卡入行后的翻开／生效接口仍需单独裁定，不从这句话推导取消普通队列、每拍兑现上限或直接即时生效。

## 可能带来的玩家体验

设计功能是减少生产时间的独立概念和编排参数，让玩家更容易判断“何时做完”和供料变化的后果。玩家仍需比较材料、处理时机与行动生效时机。理解负担是否下降、时间取舍是否足够仍Hypothesis / NotRun；用户没有宣称体验已验证。

## 暂定标签

- 类型：生产规则简化／时序接口。
- 情绪：Unknown；预期可解释性是设计目标，不是玩家反馈。
- 玩法关键词：单一处理时间、无独立生产冷却、无完工后等待、供料调时。
- 风险关键词：有限队列容量、加工中预留、无位产物处置、首次编排、零耗时循环。
