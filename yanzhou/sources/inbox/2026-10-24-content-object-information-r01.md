# 言咒物件信息 R01：让玩家看懂用途、改变与当前状态

2026-10-24 · game-002 · 内容设计模块2首轮草案。2026-10-25同步分类口径。

**状态：Raw Idea / Unqualified；信息理解、比较效率和构筑价值均为 Hypothesis / NotRun。** 本文提出信息内容与用途，尚未确认整套规范，不是正式GDD、M、P、E或D。现行规则的复述、用户已确认的语言和新信息方案分别标明；不因信息栏位存在而启用新机制。

本轮建议：五类物件分别围绕玩家的实际判断组织信息，统一区分**固定定义、装配结果、运行状态**；比较时说明改变了什么、由谁改变、何时生效。完整规则必须可查，第一眼只呈现会改变当前选择的内容。这里的“第一眼／详情”是信息优先级，不指定面板、悬停、按钮或布局。

2026-10-25用户明确**分类按法术体系划分，例如炼金**；本稿据此同步字段称呼。法器、铭文、行动、资源、标记仍称对象种类；炼金三原质的性质划分及稀有度主轴见[世界观与属性体系R01第6—7节](2026-10-24-content-world-systems-r01.md)。具体属性标签与读取规则继续设计。

同日用户进一步明确：分类、属性主要帮助理解配方与生产，与行动卡用途关系不大。首批属性信息因此优先解释材料功能、配方资格与生产差异；行动仍说明自身类别、目标和效果，不根据攻防用途推定盐／汞／硫。[炼金生产样本](2026-10-25-alchemy-production-samples-r01.md)给出具体候选，不自动把全部字段加到每张行动卡。

## 2. 调研怎样影响本稿

原作观察、文本来源、版本缺口和推断详见研究报告。以下是迁移建议，不是玩家测试结论，也不把原作机制引入言咒。

| 原作中可定位的观察或文本 | 对言咒信息设计的启发 | 不据此迁移什么 |
| --- | --- | --- |
| STS的Zap+画面呈现0费、Skill及生成球规则；社区文本说明升级只改费用 | 铭文或成长对照要标出实际改变的分量；成本改善可以与产出不变同时成立 | 能量、球槽、基础／升级参数；未观察到完整升级对照交互 |
| Monster Train手牌与场上实体分别呈现规则、数值和位置；Animus of Speed文本分别列费用与容量 | 法器定义、已装配结果、在制批次承担不同问题；材料、时间和装配占用分别说明 | 楼层、容量点、单位生命；静帧变化数不直接认定为预测 |
| Balatro把Joker持有区、正在计分的牌和分数读数分开；Joker效果有不同触发条件 | 区分贡献来源、当前结算与有条件收益；不能只看最大效果数值 | 扑克牌型、倍率、槽位数；不承诺可预测所有隐藏结果 |
| Backpack Battles同时呈现商品价格、背包空间和人物状态；Banana文本另列周期与关联Food | 兼容、挂接和供需关系要能找到具体对象；买到、能装、能运行是不同判断 | 格子、邻接、自动战斗和配方参数；不把wiki排版当作游戏详情界面 |

据此优先解决三个言咒问题：**一枚铭文究竟改变哪里；法器现在造什么与以后造什么；一张牌何时支付、成功后又获得什么。** 不用统一“战力”替代这些关系。稀有度仍沿框架承担强弱表达及投放接口，本次不因其他游戏的分类方式改写其职责。

## 3. 共用信息关系

### 3.1 同一对象的三种信息

| 信息 | 回答的问题 | 言咒例子 |
| --- | --- | --- |
| 固定定义 | 它是什么，允许怎样使用？ | 迅速是副铭文，改变加工D；具体兼容与挂接须声明 |
| 装配结果 | 在这套合法配置中实际变成什么？ | 守护护符基础D2，装迅速后D1；产物仍为1张简易护盾 |
| 运行状态 | 这一个对象／批次现在发生什么？ | 当前批次的用途、已承诺投入、剩余加工；未来用途另列 |

这三种信息是语义区分，不要求五类对象都拥有三套数据。未被修饰的资源不补一个“装配结果”；没有逐件状态的同类资源不强造逐件实例。装配结果依据合法组合，运行状态依据实际事件，不能用未来设置反推当前承诺。

设计侧保留身份与来源，支持区分同名实体和追溯贡献；内部编号、来源提交、资格状态不作为玩家必读字段。玩家看到的对象名与关系应足以定位，例如“守护护符上的迅速”“施法护符当前批次”“桌面第2位强化打击”。具体定位交互由A决定。

### 3.2 三个查看情境

| 情境 | 应优先回答 | 必须能进一步查到 |
| --- | --- | --- |
| 取得／替换前 | 它做什么、主要代价、能否适配当前配置、将替换什么 | 兼容理由、完整规则、改前改后差异；真实取得条件由C及总控输入 |
| 配置／选择用途时 | 哪些组合合法、挂接到谁、各用途投入／D／产物如何不同 | 贡献来源、例外、当前选择影响哪一批；不把未开放的配置变成战中操作 |
| 生产／整理／结算时 | 当前承诺、进度或位置、可用预算、当前条件与实际结果 | 等待／失败原因、支付与依赖、已经发生和仍可能变化的部分 |

关键支付、替代条件和失败回退会改变选择，应随主要效果一起说明；不能只保留“最高伤害18”，把支付5「咒」及不足回退藏到另一份规则。详略可以变化，语义不能变化。

### 3.3 数字与标签的写法

- 数字同时交代对象和单位：材料数量、D、每批张数、伤害、护甲、标记量分开。缺失配方写Unknown，只有明示零材料才能写0。
- “基础／装配后／当前／预期”使用不同语义。预期须给条件和范围，不能把预测冒充已发生结果；没有可靠预测依据时，只说明当前检查状态。
- 分类按法术体系填写；属性、稀有度各按已定职责使用。攻击等现行行动类别仍表达功能，不单独决定所有步骤的结算组；资源名称含“火”不自动获得火属性；同体系不自动兼容。
- 不适用的能力省略；应该具备但尚未设计的内容标Unknown；暂不可见的信息沿可见性规则。三者不得都写成0或空白。

## 4. 五类物件的最小信息

下表是本轮建议的信息分工。现有内容合同要求保留的字段继续保留；“优先”不表示可以删掉完整定义，也不要求把设计字段全部挤进卡面。

### 4.1 法器：装什么，按什么用途炼成什么

| 信息组 | 具体内容与用途 | 何时优先 |
| --- | --- | --- |
| 身份与用途 | 名称、预设词义、有限用途；法术体系分类／稀有度仅在具体归属与内容明确后填。帮助识别和比较实际功能 | 取得、替换、选择用途 |
| 兼容与占用 | 核心空缺、合法组合；初始／可打造辅槽及预设挂接；当前实体占用。说明能装谁、占哪里、替换谁 | 配置 |
| 每个用途的生产 | 完整配方或明示零材料、加工D、每批产物种类与数量、多产物顺序、可接受修饰。回答投入和产出；“炼成行动卡”不等于执行卡效 | 选择用途、开工前 |
| 装配贡献 | 基础值、具体组件改变、有效结果；有契合时列真实差异。比较时注明固定的其他条件 | 配置、替换比较 |
| 当前生产 | 当前用途／批次、承诺内容、加工剩余或当前等待原因；未来用途与当前批次分别说明。完工去向沿现行规则，容量风险不写成停工原因 | 生产 |
| 取得与资格 | 具体内容的取得／持有／部署资格、可改动窗口；未知投放不自填 | 取得、配置详情 |

制造投入、加工D、装配占用是不同约束，分别解释；不折算成未经验证的统一成本。EX-004零材料且桌手满仍生产，不能显示“缺成品空位，无法开工”。

### 4.2 铭文：改变哪一段，能装在哪里

| 信息组 | 具体内容与用途 | 何时优先 |
| --- | --- | --- |
| 身份与词义 | 名称、实体身份、词性、基础词义；核心／副铭文角色。让玩家区分可装实体与纯语法用语 | 取得、识别 |
| 合法关系 | 兼容法器、核心组合或辅槽挂接、明确限制；能装与不能装均有规则理由 | 配置 |
| 实际贡献 | 修改生产还是行动、改哪个目标或参数、适用条件与下限／例外；只列本铭文实际能力 | 比较、配置 |
| 配置对照 | 指定法器与用途后的改前／改后结果；未选上下文时只写规则，不伪造通用收益 | 比较 |
| 持有与占用 | 有几枚、这一枚装在何处、是否可在当前窗口调整。取得规则归既有内容与C接口 | 配置、库存 |

迅速的重点是“加工D减少1，最低1”，而非一条抽象速度评级。固定EX-004中它已装守护；信息可解释这一贡献，不因此开放战中转移或新配装分支。铭文不随每批生产消耗，数量不能误写成使用次数。

### 4.3 行动：对谁做什么，何时支付，失败怎样处理

| 信息组 | 具体内容与用途 | 何时优先 |
| --- | --- | --- |
| 身份与主要规则 | 名称、现行行动类别、目标及主要结果；关键条件、支付与回退和结果共同可读。行动类别与法术体系分类分开 | 手牌、桌面、比较 |
| 完整步骤 | 目标选择／优先级、读取时点、各步量值与结算组、顺序、成功依赖、无目标及终局处理 | 规则详情、有条件效果 |
| 来源与生产 | 来源法器／用途、完整配方或零材料、D、每批张数，注明该实例承接的生产结果 | 追溯、构筑比较 |
| 实例状态 | 所在区域／列、已知目标资格、当前支付条件；已执行／失效等由实际事件给出 | 整理、结算 |
| 操作费用 | 整理行为的可用性及费用属于该操作；只有实际存在的卡效费用写入卡效 | 整理操作 |

卡效付费、制造材料和整理点不能共用一个“费用1／5”而不解释归属。当前满足支付条件不保证到所在列仍满足：之前的行动、目标变化或终局可能改变结果。现有成品不随法器未来用途改型，也不追溯套用后来设置。

### 4.4 资源：有什么性质，能作什么投入，多少可用

| 信息组 | 具体内容与用途 | 何时优先 |
| --- | --- | --- |
| 身份与资格 | 名称、普通耗材／特殊对象、已定义的性质与阶级；每项性质说明被哪条配方或规则读取 | 配方选择、比较 |
| 量与可用性 | 持有量，以及当前规则实际存在的承诺／暂不可用量和原因；可用量按相应生产合同解释 | 供料、开工判断 |
| 来源与用途 | 从哪里获得／炼成，可满足哪些已知合法用途；精确身份要求、性质要求和替代条件分别说明 | 选择生产链、替换材料 |
| 生命周期 | 携带标签与占用、使用时怎样扣除、战终处理；只有实际采用的维护／增幅能力才补字段 | 使用、携带和取得详情 |

现行EX-004没有具体资源，不能借表格补出材料池。候选“火露”可登记来自中间工序、供后续工序使用；其属性体系、阶级、跨战保留与共享生产的具体可用时点仍按所属模块／总控问题处理。本稿不以“能显示可用量”为理由决定逐段承诺、争料或自用保留。

### 4.5 标记：谁持有，现在多少，能怎样增减

| 信息组 | 具体内容与用途 | 何时优先 |
| --- | --- | --- |
| 身份与作用 | 名称、宿主／极性、每单位或整体作用；说明它是支付储备、持续效果还是其他已声明能力 | 首次识别、效果比较 |
| 当前量与使用限制 | 实有量、实际存在的锁定量／可消费量、上限与溢出处理；没有锁定能力的标记不补锁定字段 | 支付、整理 |
| 生成与消费 | 哪些步骤获得／消耗、读取与支付时点、足额或不足处理；具体卡的条件仍由该卡定义 | 卡效判断、追溯 |
| 存续与移除 | 期限／刷新、移除、战终处理；无自然期限明确说明，不能把未知期限写成无限 | 详情、结束判断 |

“获得／消耗”统一动作词，不保证所有标记可消费，也不默认所有标记有锁定、上限10或战终清零；这些仅在具体定义支持时出现。EX-004的「咒」只作支付储备，没有被动增伤。

## 5. 工序与配方怎样连接物件

配方表示投入、生产条件与产物的关系；本轮不把它自动做成第六类实体卡。工序信息至少能指出**所属法器／用途、这一段的输入、D、炼成的对象与数量、所处顺序、改变来源**。有这些信息，玩家才能看出是产资源还是产行动，以及后续哪一段依赖它。

DIR-041已有局部决定：有限可排列工序、兼容可见，中间工序产共享资源且不产行动卡。本稿保留该候选权限，不写成现行TL-38已经支持。一个工序是否对应一枚实体铭文、是否还有其他载体，仍Unknown；“能重排工序”不能推出“每段都是可移动的铭文卡”。

候选炼露炉可以按已有小样写“原露1／D1 → 炼成 2「火露」（资源）”，后段另写“火露1／D1 → 炼成 1 张伤害6的行动卡”。这仅检查关系和用词；产物正式名称、实体映射、兼容及承诺尚未闭合，不据此扩充正式物件池。共享资源何时可用、争料顺序与保留问题继续交总控，不在信息稿暗定。

## 6. 用现有内容填写，而非只留空表

以下是内容表达样例，不是新UI、完整教学或新的数值方案。除明确候选外，参数均取固定EX-004；相同定义的权威正文仍在原案例。

### 6.1 守护护符与迅速：改变生产效率

> **守护护符｜守护用途**
>
> 核心：庇护；副铭文：迅速。零材料；加工1拍；每批炼成 1 张「简易护盾」。
>
> 加工来源：基础D2，迅速−1，当前配置D1。
>
> 简易护盾：对存活玩家增加4护甲；该步骤成功且战斗未结束后，获得 1「咒」。

生产信息回答多久得到卡，产物说明回答卡生效后做什么。防护在防护组，「咒」在其余组，完整步骤可查；生产完工时不立即增加护甲或「咒」。该例只有D受迅速影响，没有强化护盾数值或每批张数。

### 6.2 施法护符：下一批不会改写当前批次

沿EX-004代表操作在首轮最终整理后的已有情境：

| 应分别呈现的信息 | 本例内容 |
| --- | --- |
| 当前在制 | 普通积累；批次3→6；零材料，D3，炼成 1 张「简易攻击」 |
| 未来用途 | 已改为集中兑现；当前批次结束后新批采用；零材料，D3，炼成 1 张「强化打击」 |
| 已有成品 | 已产出的简易攻击仍保持原规则 |

这里的3→6是生产拍，不是结算列。用途切换本例免费，不能在设置处混入整理操作的1点费用；结算列之间也不推进生产拍。

### 6.3 强化打击：条件与回退随主要效果出现

> **强化打击｜攻击**
>
> 目标：存活的唯一来源敌人。
>

## 7. 比较时保留哪些前提

比较的第一步是说明正在替换什么、其余条件是否相同，再列实际变化。不能把一张行动的结算收益与一件法器的整战产出直接放在同一数值列。

| 比较对象 | 至少保持可辨的前提 | 本轮不作的结论 |
| --- | --- | --- |
| 法器／铭文配置 | 合法槽位与实体占用、用途、投入、D、每批产物、组件贡献、生效批次 | D较短必然整体更强；更快生产必然得到更多有效行动 |
| 简易攻击／强化打击 | 同目标与伤害规则、当前及执行时支付条件、基础／足额分支、成功依赖 | 强化打击恒为18，或18就是整轮收益 |
| 材料替代 | 规则要求身份还是性质、数量、阶级是否参与、替代是否改变结果 | 同属性就都可替代，同名性质自动兼容 |
| 标记供给／消费内容 | 宿主、读取时点、限制与上限、生成依赖、消费结果和失败 | 增加1标记恒等于某个固定伤害或金币价值 |

取得频率、替换经济和整局成长跨度由C提供；敌情、共同参数和战终保留由总控集成。信息设计可以指出缺什么比较前提，不能替这些输入定值。敌人原生暗牌仍只暴露获准字段，设计侧已知敌表不能进入玩家预览。
