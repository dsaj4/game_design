## 标记系统核心规则

### 1. 标记的基础定义

**标记**是附着于玩家或敌人的效果状态，以**砝码**形式视觉化呈现。

| 属性 | 规则 |
|------|------|
| **附着对象** | 仅玩家和敌人，不附着于卡牌、法器或资源 |
| **产生来源** | 行动卡效果结算时产生 |
| **消耗方式** | 法器开工时、行动卡结算时、自动触发 |
| **视觉形式** | 砝码堆叠，正负面分两侧 |
| **极性** | 正面（有利）或负面（不利） |
| **层数** | 同类标记可堆叠，具有上限 |

### 2. 标记放置布局

#### 战场四格布局

```
┌─────────────────────────────────────┐
│           战场中央时间轴              │
├─────────────────────────────────────┤
│                                     │
│  【玩家区域】                         │
│  ┌──────────┬──────────┐           │
│  │ 正面标记  │ 负面标记  │           │
│  │  砝码堆   │  砝码堆   │           │
│  └──────────┴──────────┘           │
│      [玩家棋子]                      │
│                                     │
│  【敌人区域】                         │
│      [敌人棋子]                      │
│  ┌──────────┬──────────┐           │
│  │ 正面标记  │ 负面标记  │           │
│  │  砝码堆   │  砝码堆   │           │
│  └──────────┴──────────┘           │
│                                     │
└─────────────────────────────────────┘
```

#### 四格定义

| 位置 | 宿主 | 极性 | 典型标记 |
|------|------|------|----------|
| **格位1** | 玩家 | 正面 | 祝福、护盾、专注、先兆、蓄势 |
| **格位2** | 玩家 | 负面 | 虚弱、迟缓、诅咒、灼烧（敌施加） |
| **格位3** | 敌人 | 正面 | 强化、护甲、狂暴、再生（敌自施加） |
| **格位4** | 敌人 | 负面 | 蚀、破甲、灼烧、虚弱（玩家施加） |

**规则要点：**
- 玩家施加的标记大多数进入敌人负面格（格位4）
- 敌人施加的标记大多数进入玩家负面格（格位2）
- 敌人可对自己施加正面标记（格位3），如BOSS强化阶段
- 玩家可对自己施加正面标记（格位1），如防御/辅助行动

### 3. 标记的生命周期

#### 完整流程

```
[行动卡结算] 
    ↓
[产生标记效果] ──┬──→ [即时标记] → 直接落入砝码堆
                 │
                 ├──→ [延迟标记] → 虚幻砝码显示 → 中心线扫过 → 具现化落入砝码堆
                 │
                 └──→ [周期标记] → 登记周期效果 → 每N拍触发
    ↓
[标记存续] 
    ↓
[标记消耗或移除] ──┬──→ 法器开工时消耗
                   ├──→ 行动卡结算时消耗
                   ├──→ 自动触发（如战斗结束）
                   └──→ 达到持续时间上限
```

#### 各类标记的具体规则

##### 即时标记

```
定义：结算后立即落入目标砝码堆
触发时机：行动卡结算时
视觉：砝码直接出现在对应格位
示例：剑击·蚀 → 结算时，敌人负面格立即+1蚀砝码
```

##### 延迟标记

```
定义：预示未来某拍将获得的标记
触发时机：行动卡结算时产生虚幻砝码，指定拍数到来时具现化
视觉流程：
  1. 行动卡结算 → 行动行对应位置出现虚幻砝码
  2. 中心线扫过该位置 → 虚幻砝码发光
  3. 卡牌翻开 → 砝码落入目标格位
示例：预言·灼烧 → 在敌人T拍位置显示虚幻橙色砝码×3
```

##### 周期标记

```
定义：每N拍自动触发效果
触发时机：每拍边界准备阶段检查
持续时间：声明的拍数或战斗结束
视觉：周期标记本身作为砝码存在，每次触发时产生效果动画
示例：蓄势标记 → 每拍结束时自动+1祝福砝码
```

##### 条件标记

```
定义：满足特定条件时触发
触发时机：条件检查通过时
条件类型：
  - 敌牌揭示时
  - 受到伤害时
  - 法器开工时
  - 特定拍数到来时
示例：先兆标记 → 当敌牌揭示时，自动+2护甲
```

### 4. 标记的堆叠与上限

#### 堆叠规则

```
同类标记：按层数叠加，显示为多个砝码或单个砝码+数字
不同类标记：独立计算，分别显示
```

#### 上限机制

每种标记有**声明上限**，达到上限后无法继续增加。

| 标记类型 | 推荐上限 | 理由 |
|----------|----------|------|
| **持续伤害类** | 10层 | 防止DOT过度膨胀 |
| **增伤类** | 5层 | 防止伤害倍率失控 |
| **减伤类** | 5层 | 防止完全免疫 |
| **辅助类** | 3层 | 防止循环过度优化 |
| **特殊标记** | 按具体设计 | 如血量无上限，护甲参考现有规则 |

**示例：**
```
蚀标记上限：10层
- 当前蚀层数：8
- 行动卡产出：+3层蚀
- 实际增加：+2层（达到上限10）
- 超出部分丢失，不产生其他效果
```

#### 达到上限时的处理

| 处理方式 | 说明 |
|----------|------|
| **截断** | 超出部分直接丢失（推荐） |
| **溢出提示** | 显示"已达上限"提示 |
| **替代效果** | 超出部分转化为其他效果（可选，增加复杂度） |

### 5. 标记的消耗规则

#### 消耗时机

```
时机1：法器开工检查阶段
  - 检查辅槽是否有标记消耗效果
  - 满足条件则消耗标记并应用效果
  - 不满足则跳过

时机2：行动卡结算阶段
  - 行动卡效果包含标记消耗
  - 检查目标标记层数
  - 消耗后应用效果

时机3：自动触发
  - 战斗结束清除所有临时标记
  - 周期标记到期自动移除
  - 特定条件满足时消耗（如"受到致命伤害时消耗护盾"）
```

#### 消耗数量规则

```
指定层数：消耗N层标记
  - 若标记层数 ≥ N：消耗N层
  - 若标记层数 < N：消耗全部，但效果失败或按实际层数计算

全部消耗：消耗目标所有同类标记
  - 效果按实际消耗层数计算
```

**示例：**
```
辅槽效果：消耗3层祝福，伤害×2
场景1：祝福层数5 → 消耗3层，剩余2层，伤害×2生效
场景2：祝福层数2 → 消耗2层，清零，伤害×2不生效
```

#### 消耗优先级

当多个效果同时尝试消耗标记时：

```
优先级顺序（从高到低）：
1. 玩家主动触发的效果（如主动使用的行动卡）
2. 法器辅槽被动效果
3. 周期/条件自动触发
4. 战斗结束清理
```

### 6. 标记与时间轴的结算顺序

#### 每拍结算框架（扩展）

```
每拍t的共同框架（基于SYS-003 TL-11扩展）：

阶段1：边界准备
  - 上拍待用资源/中断容量转为可用
  - 周期标记检查与触发
  
阶段2：揭示与观察提交
  - 揭示本拍敌牌
  - 条件标记检查（如"敌牌揭示时"触发）
  - 提供暂停观察窗口

阶段3：已有行动结算
  3.1 防护效果先结算（含护盾标记）
  3.2 伤害与打断结算
      - 标记触发检查（如"受到伤害时"）
      - 持续伤害标记触发（如蚀标记）
  3.3 检查终局

阶段4：幸存批次完工
  - 法器完工，行动卡入行
  - 延迟标记具现化（如虚幻砝码落入砝码堆）

阶段5：统一开工检查
  - 法器开工前检查标记消耗条件
  - 满足则消耗标记并调整配方
```

#### 标记与行动卡的结算关系

```
同一行动卡结算中：
1. 检查标记消耗条件
2. 消耗标记
3. 应用卡牌效果
4. 产生新标记
5. 行动卡离队

不允许同一张卡先产生标记再立即消耗
```

### 7. 标记的展示与反馈

#### 视觉元素

| 元素 | 呈现方式 |
|------|----------|
| **砝码** | 立体小物件，堆叠于格位 |
| **层数** | 单个砝码+数字（≥4层时折叠显示） |
| **虚幻砝码** | 半透明，位于行动行对应位置 |
| **触发动画** | 砝码发光/震动，表示效果触发 |
| **消耗动画** | 砝码飞向法器或行动卡，表示被消耗 |

#### 信息提示

```
悬停砝码时显示：
  - 标记名称
  - 当前层数 / 上限
  - 效果说明
  - 来源（哪张行动卡产生）
  - 持续时间（若有）
```

#### 预警机制

```
显示关键信息：
  - 标记即将达到上限（90%时变色提示）
  - 法器即将消耗标记（开工检查前预览）
  - 延迟标记即将落入（虚幻砝码闪烁）
  - 周期标记即将触发（下一拍触发时提前提示）
```

## 血量砝码化方案对比

### 方案A：血量完全砝码化

#### 设计

```
生命值以砝码形式显示：
  - 每个红色大砝码代表1点生命
  - 堆叠于玩家/敌人中央位置
  - 受到伤害时砝码逐个消失
  - 恢复生命时砝码增加
```

#### 优点

- 视觉统一，所有数值都是砝码
- 直观表达生命的"实体感"
- 符合炼金世界观（生命也是砝码平衡的一部分）
- 砝码消失的视觉冲击力强

#### 缺点

- 生命值较高时砝码数量过多（如30点生命=30个砝码）
- 需要折叠显示机制（如10点显示为"大砝码×3"）
- 与传统血条UI差异较大，可能影响可读性
- 恢复生命的动画可能繁琐

### 方案B：血量独立显示

#### 设计

```
生命值以传统血条形式显示：
  - 数值+血条位于玩家/敌人上方
  - 标记砝码独立于血条
  - 受到伤害时血条减少，不产生砝码变化
```

#### 优点

- 可读性高，玩家熟悉传统血条
- 数值大时不影响显示
- 与标记系统清晰区分
- 动画简洁

#### 缺点

- 视觉不统一（血量是数字，标记是砝码）
- 失去"生命也是砝码"的世界观呼应
- 砝码系统的独特性减弱

### 推荐

**先实现方案B（血量独立显示），预留方案A的接口**

理由：
1. 方案B风险更低，可读性有保障
2. 可在alpha测试中收集反馈
3. 如果玩家反馈"希望更统一"，再切换到方案A
4. 技术上先实现方案B，再扩展到方案A的成本较低

## 标记系统与现有规则的完整兼容性

### 与SYS-002（法器生产）的兼容

| 现有规则 | 标记系统扩展 | 兼容性 |
|----------|--------------|--------|
| 开工检查材料 | 标记可作为虚拟材料或消耗条件 | ✓ 兼容 |
| 托管材料 | 标记消耗不影响托管流程 | ✓ 兼容 |
| 预留容量 | 标记不占用Q容量 | ✓ 兼容 |
| 辅槽修饰 | 辅槽可消耗标记改变配方 | ✓ 兼容 |

| 现有规则 | 标记系统扩展 | 兼容性 |
|----------|--------------|--------|

| 防护先于伤害 | 护盾标记在防护阶段结算 | ✓ 兼容 |
| 取消截止e<T | 标记不改变取消规则 | ✓ 兼容 |
| 打断退料 | 标记不影响打断机制 | ✓ 兼容 |

### 与DIR-038（资源机制）的兼容

| 现有规则 | 标记系统扩展 | 兼容性 |
|----------|--------------|--------|
| 资源区堆叠 | 标记不进入资源区 | ✓ 兼容 |
| 资源下拍可用 | 标记不占用资源逻辑 | ✓ 兼容 |
