## 3. 页面结构初案

玩家应能依次回答：本轮面对什么、已经产出什么、还能花几点整理、确认后按什么顺序发生。推荐采用上下对齐的中央五列，左右承载生产与详情，底部承载手牌和控制；不从参考图的空间结构反推布局。

| 区域 | 初案承载 | 信息与操作关系 |
| --- | --- | --- |
| 顶部窄状态带 | 回合、阶段、生产拍或结算列、疲劳状态；双方生命与己方护甲邻接各自区域 | 生产进度与结算进度分别呈现，不使用一条含义混合的倒计时；累计生产拍仍准确可查 |
| 中央上排 | 敌方本轮五位行 | 与己方五位逐列对齐；原生暗牌只露位置、类别及即时／延时，公开后续保持正面 |
| 中央下排 | 玩家本轮五位行 | 空位、实牌、已结算结果各有可辨外观；本轮从左到右执行；不把两排的对齐画成任意手动选靶 |
| 敌行邻侧小区 | 已生成、下一回合可用的公开后续牌 | 与本轮敌行分开，标明可用回合、效果、生成序和已锁对象；移入下轮行后仍公开 |
| 左侧生产区 | 守护与施法两台法器；当前批次及未来用途分列 | 当前承诺只读，未来设置有明确入口；生产中的牌不混入已成品桌面／手牌 |
| 下部手牌区 | 三张完整展开的跨轮手牌、容量和整理点 | 保持卡面可读，不用大幅扇形遮叠；换入与提前铺牌必须经过合法付费整理 |
| 右侧详情区 | 所选卡／法器／标记的完整说明，必要历史入口 | 优先保留中央两排可见，减少在详情与牌局间来回记忆；窄尺寸的具体展开方式尚未定 |
| 下缘操作区 | 随阶段变化的继续／暂停、单步、最终结算确认，以及整理入口 | 主动作标明具体后果；“继续生产”和“确认结算”须可区分，整理操作明确本次费用 |

这是信息分区草案，不锁像素、屏幕比例、具体键位或界面控件形式。左右区域宽度须在HTML阶段结合真实卡面检验；主桌读数过小时先调整布局，不以无限缩字解决。

## 4. 关键状态怎样落到页面

停点沿[交互TL-17／19／36](../../design/common/interaction-save/rules.md)及[回合包](../../development/task-packs/round-hand.md)，下表只提出页面承载，不改变推进规则。

| 状态 | 页面需要呈现 | 操作边界 |
| --- | --- | --- |
| 第0拍就绪 | 双方初态、敌方已布五位、空桌空手、两器尚未开工 | 明确继续才首次开工；单步完成第0拍开工后停 |
| 生产推进／收尾 | 本轮生产进度、两器当前批次、成品入桌或入手 | 请求暂停／详情先收完当前生产拍及音画；收尾期间不接受付费整理 |
| 生产暂停整理 | 已入区成品、当前点数、候选操作和费用 | 建议采用显式整理入口和提交前预览；成功才扣点；关闭未提交选择不当成撤销已付操作 |
| 最终整理 | 清晰的本轮准备完成状态、双方五位行、手牌、未来设置 | 等待明确确认；确认之后本轮排序、用途及锁定等玩法编辑关闭 |
| 逐列结算／列间停 | 当前列、真实翻牌、已结清结果、只读历史痕迹 | 不推进生产；暂停收完当前列；仅查看与设置可用，不提供看牌后反悔入口 |
| 第五列后／轮尾 | 区分“本列已结清”与“疲劳待处理” | 单步只处理待办轮尾和下轮准备，停在下一生产拍前；无终局才清行、布牌、重置点数 |
| 胜败／恢复 | 已发生致死或疲劳事件、清理后的结果、重试／返回入口 | 恢复静态停住；不重复付费或结算；重试重建EX-004完整初态，进行中放弃按既定保存合同说明后果 |

## 5. 用真实情境检查初案

- **整理与费用。** 用EX-004 §6第2轮的提前铺牌、桌手互换、桌面交换说明三种操作。页面要显示操作前后卡位和剩余点数；桌手互换原位完成，满手也不产生临时溢出。0点、同牌交换或满桌提前铺牌显示原因，均不扣费；已经成功的交换改回仍收费。
- **产出不等于效果。** 用EX-004 §5的首轮与满手情境：完工只改变桌手库存，不先加护甲／记层；满手丢的是刚到的新牌，给短反馈并留可查记录，法器继续按规则生产。
- **打断不毁成品。** 用EX-004 §5—6的第三轮：公开后续指向被锁法器，结算打断其当时在制批次；桌手成品与已记录溢出不回滚，重开按下一生产拍处理。
- **公开边界。** 暗牌详情和历史不显示未揭示名称、伤害或锁定对象。原生延时牌与已生成后续牌使用可辨状态；后者公开完整内容，但不能据此提供本场不存在的取消操作。
- **键盘、回看与恢复。** 必要操作都有点击和键盘路径；详情／历史先按阶段收尾后进入，关闭仍暂停并回到来源焦点。正常退出、异常恢复、保存失败、版本不匹配和终局恢复沿TL-19／36；页面不能把恢复当成新选择窗口。

本页仅做规则对应与文字建议，未运行程序、模拟战斗或进行真人测试。EX-004代表路线不是界面强制教学流程，也未证明每次整理均有独立价值；FB-Q01／02继续待验证。
