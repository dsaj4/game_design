# 任务设计包：回合、手牌与整理

2026-10-23 · Derived Design / CORE-065 · 设计已采纳，执行NotRun。包与来源共用任务开工时固定的设计提交，按[任务包规范](../task-pack.md)登记一次。此包交接机制；真实5位敌表、整场初态尚未冻结，不能直接宣称完整战斗就绪。

## 玩家目标与范围

法器在5个生产拍中自动产牌，玩家观察对面的5张牌背和己方进度，在有限点数内调整这一轮；最终整理后确认，观看双方从左到右逐列结算。牌的位置固定，结算结果保留到换轮，不再随中心线滚动。来源：[核心TL-08／11](../../design/GDD.md)、[交互TL-17／18](../../design/common/interaction-save/rules.md)。

| 换轮与疲劳 | 第10轮末首次5生命，此后10、15…，在全部列后且未终局时扣双方生命；同事件双亡判负；手牌／未完批跨轮，桌面结果清除 | [TL-24／13](../../design/GDD.md#tl-13-生命程序循环与终局) |

既有未来用途、路由与消费锁定免费；整理点不替代卡效费用。生产完成的牌可以本轮使用，但玩家不足5张时保持空位，不补牌。独立定时／有限期／维护尚未迁入当前首场；不能从旧扩展推导新轮中触发。

## 正常、反例与恢复

使用[EX-003](../../design/examples/round-hand.md)和[CORE-065验收](../../design/validation.md#回合与手牌core-065)，不复制旧EX的20／24拍胜败结论。

| 场景 | 要能解释的结果 |
| --- | --- |
| 最后一个生产拍才完成一张牌 | 先进入本轮桌面／手牌，再整理，可参加本轮 |
| 桌满、手里3张，再生产 | 新牌在右端被烧，法器仍可继续开工；加速不保证更多有效输出 |
| 普通攻击与兑现前后交换 | 可改变兑现时标记量；支付仍在具体步骤发生，排序花1点，不预付标记 |
| 同列敌攻击与己方护盾／下一列护盾 | 同列防御组可先挡；后列不能回头救已发生伤害 |
| 结算暂停后想交换或解锁 | 拒绝玩法修改，只允许查看；不能看见敌牌真相后再改本轮 |
| 第5列结束时暂停 | 本列结果保留，轮尾疲劳尚未执行；无剩余列时单步只处理待办轮尾和下一轮建局，停在新生产拍前 |
| 退出恢复 | 不重新铺敌牌、不重复消耗点数／烧牌／疲劳；旧连续拍存档不静默改制 |

## 条件展开与下一输入

更改X／H／点数要同时核对产牌吞吐、固定行、敌表覆盖和保存；更改打断读[打断包](interruption-restart.md)，更改用途／锁定读[用途包](future-purpose.md)。新敌表依[内容合同](../../design/content/enemies-encounters.md)填写实际牌名、即时／延时、后续效果、锁定及循环，再形成一场完整输入。新2D操作宿主仍由PRE2D-Q01另行裁定。

## 对话讲解

你不再追着向前移动的队列看牌，而是看一桌最多五列的本轮计划。法器继续自己生产；满桌后多出的牌存到手里，但只有三个位置。你每轮能花三点，把一对牌调换、用手牌换桌牌，或者提早填一个空位。确认之后，只能看结算，不能翻到敌牌后反悔。

代价也变了：护盾即使造得早，也要等整轮结束才生效；过量生产可能烧牌；你能重排已有牌，但不能保证造齐五张或知道所有暗牌。最需要用真实首场内容检查的，是这些三点调整是否有多种合理选择，而不是每轮重复同一套排序。
