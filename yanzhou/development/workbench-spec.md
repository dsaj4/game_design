# 工作台登记与展示规格

2026-10-18 · game-002 · WorkspaceDisplaySpec / G002-DOC-026。目标是让用户在一个入口知道当前在做什么、能看哪些产物、为何未完成、下一步是什么。这里定义信息职责与使用要求，不预设新的任务数据库或代码Interface。

## 权威信息只写一次

| 对象 | 权威位置 | 工作台职责 |
| --- | --- | --- |
| 玩法与参数 | design及正式来源链 | 打开获准的原文；不复制成可独立修改的规则 |
| 当前问题 | governance/questions | 显示问题ID、阻塞范围和原文入口；不另开待决表 |
| 当前开发能力 | development/README | 提供直接查看入口；区分最新源码、运行包、设计稿 |
| 阶段与前置 | production-plan | 解释当前任务对哪项玩家能力有贡献 |
| 单项任务与循环 | 所属设计／实现／治理记录 | 展示阶段、产物、意见、证据与下一步 |
| 资产身份与关系 | DA-1目录＋原件说明 | 预览和定位源／派生／使用版本；不搬原件 |
| 执行合同 | 本机任务面板 | 材料哈希、写入所有权、会话与暂停／恢复；结果回填所属仓库 |

卡片标题、简介、页签和日期是导航元数据。页签数量不是完成步数，卡片done不是验收通过。任何缓存摘要必须注明来源、核对日期和范围；与原文冲突时停止沿用旧摘要，修正入口后再派单。

## 用户看到的五个视角

| 视角 | 必须能回答 | 最小展示 |
| --- | --- | --- |
| 当前与下一步 | 现在做哪件事，为何先做它 | 本轮目标、阶段、主要阻塞、下一动作、当前状态原文入口 |
| 任务与循环 | 一项工作走到哪里，还缺哪些产物 | 所属记录与轮次、责任、依赖、定义／小样／核对／收口、未决项 |
| 审阅与对照 | 这张图属于哪版、改了哪里、意见处理了吗 | 对象／状态／尺寸、原版和候选、实际／示意标签、意见及结论 |
| 资产与交付 | 原件在哪、能否复用、游戏用了哪版 | AS／DM、版本、用途、源／预览／派生／运行、来源条件和使用者 |
| 开发地图 | 完成它以后离一场／一局／交付还差什么 | P0—P5位置、已具备能力、未完成的相邻能力与原证据 |

言咒卡复用稳定身份；第六页“使用与接手”只说明操作和Git取证。旧重复组件／交付页已删除，不在首页继续展示旧批次待办；原始资产和固定版本证据保留。

## 当前实际能力与本次接入

| 功能 | 本次可用方式 | 状态与限制 |
| --- | --- | --- |
| 当前状态、规范、阶段解释 | 项目卡薄导航＋顶部配置白名单只读预览／搜索 | 使用现有能力；权威文档仍在game仓库 |
| 执行任务 | 准备合同、打开CLI、复制启动文本、结束合同 | 已有；active只表示会话打开，closed只释放所有权 |
| 中间产物查看 | 卡内Markdown／HTML；Files打开本机图片、音视频、文档及原产物 | 已有；跨仓库绝对路径不应写入卡片step.path |
| 每轮进度与证据 | 由执行者按循环规格写入所属记录，项目卡提供入口 | 人工维护；没有结构化全自动阶段、依赖和验收同步 |
| 历史对照与意见 | 复用UI-REVIEW及原固定报告；浏览器意见导出后归入轮次 | 工具各有原覆盖；不声称所有新稿已集成或服务在线 |
| 按阻塞／阶段筛选全部任务 | 未来可选增强 | 未实现，不是2D启动的前置；先验证文件记录是否足够 |
| 自动资产缩略图、版本差异和采用关系 | 未来可选增强 | 未实现；先用原AS／DM入口和Files查看 |

本规格的“必须展示”是阅读和登记要求，并不声称现有应用已经具有所有专用控件。本轮只整理卡片、文档和白名单配置，不开发新的调度系统。

## 每次开工与交付怎样维护

1. 总控在所属记录创建或接续一轮，固定设计／代码／资产与预期。用已有任务ID，轮次写来源路径＋R01等，不再分配一套任务编号。
2. 有必要交给执行会话时，按同一范围准备本机合同；只读任务不占写入范围。合同与本轮记录互相注明入口。
3. 每形成一个可审产物，立刻记录版本、状态和可查看位置，不等整批结束才一次贴几十张图。
4. 审阅按对象、状态和尺寸落到该产物；原件与候选并排定位，注明真实运行／示意／生成图。反馈回到同一轮，而不是散落在另一个进度表。
5. 交付后更新所属记录的实际结果、失败和NotRun，再更新项目卡日期及必要摘要。结束合同只释放所有权，不代填结果。
6. 旧轮次用固定提交或包manifest取证；从当前卡退出不等于删除原件。恢复前先核对输入是否变化。

## 状态查询规则

| 用户问 | 回答时必须包含 |
| --- | --- |
| “这个做完了吗” | 对象与范围、产物版本、实现状态、检查结果、用户接受／未验部分 |
| “为什么还没好” | 设计待决、工程偏差、制作中、未验或范围外中的具体原因；负责人和下一动作 |
| “我现在该看什么” | 一个主审阅入口、2—3个关键状态、要判断的具体问题；不要倾倒全部资产目录 |
| “这张图用上了吗” | 源AS／版本、仅参考或已导入、使用包／对象、运行证据 |
| “能不能继续开发” | 本轮设计阻塞是否闭合、输入版本是否仍有效、具体恢复范围；不由active推断 |

## 展示检查

当前状态、规范、开发地图和使用入口在宽屏及窄屏可读；长表只在自身区域横向滚动。卡片页签路径必须指向工作台内存在文件。跨仓库原文通过顶部文档按钮或Files打开；普通Markdown中的Windows绝对链接不保证能触发应用文件预览，使用说明要给可复制路径。

白名单配置不得因方便而改成全仓库索引。读取游戏材料仍按READ-1，文档展示不自动发出任务、不运行Demo、不上传或发布。检查只证明工作台入口和文档可读，不能证明游戏功能完成。
