# 项目适配：证据检查与资格分开

game-project-1 / 2026-10-02。遵循根和目标项目AGENTS、[设计流程](../../../../docs/design-workflow.md)。本文件约束所有模式及上游README示例，不继承示例中的游戏设定。

- 先定目标项目、方向与允许材料。言咒探索先按[start](../../../../yanzhou/exploration/start.md)展开CORE/GDD/FULL/CUSTOM/NONE；已有方向保留自身版本，不因审查补读所有GDD、代码或其他方向。局部审查无法证明全局不存在冲突。
- 必要输入为用户要判断的承诺、已有规则/方案与证据；缺项写Unknown。批量澄清按项目流程，多个可独立回答的问题同批给推荐/影响；未回答不视为认可。
- Quick Reality Check、Full Design Review是分析深度，不是项目Evaluation资格。Raw输入只能形成Raw分析笔记，写所属DIR README或主系统inbox；正式Evaluation须合格来源并使用根登记模板。对现行文档的合规审查可进入目标governance，不能借此新增玩法决定。
- Observed/Sourced/Derived/Assumed/Unknown只描述一条陈述的证据来源，不能替代Raw/Qualified/Accepted。引用他人报告写Sourced并给原报告及固定版本；只有本次直接观察才写本次Observed。程序检查、模拟玩家与真人试玩分开。
- Test-ready仅指验证计划可执行，不是执行授权、素材合格或玩法通过。Validation Design只写计划；Evidence Update只更新所给证据覆盖的判断。没有实际结果时NotRun；不生成虚假玩家反馈、任意量化阈值或泛化分数。
- 正式GDD/Proposal/Evaluation/Draft Change仍用[登记模板](../../../../game-design-workflow/templates/README.md)，上游review-output只作分析维度。建议不回写正式design；有明确采纳再由责任人走原流程。
- 若用户授权原型/测试，先确认实现目标仓库与冻结输入，在对应实现仓库执行；本仓库记录范围/证据/偏差，资源按[DA-1](../../../../docs/demo-asset-standard.md)登记。没有任务授权不安装工具链、不启动测试或发布。
- 输出先给结论与最弱证据，再给具体反例、Unknown、最小验证和下一步决定。引用实际输入版本；不把参与审查的模型数当作独立玩家证据。任务需要落盘时直接在已授权位置写，不机械重复索要保存许可。
- 本skill不自动开启多agent。用户要求协作时按[言咒协作规范](../../../../yanzhou/governance/agent-collaboration.md)分配独立审查对象、允许读取范围与文件所有权；审查者不能批准自己新增的玩法。
