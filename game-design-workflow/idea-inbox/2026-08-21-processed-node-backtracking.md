# 已处理节点返程

> 当前状态：`Raw Idea / Unqualified`
>
> 边界：本文件先保留用户确认的返程规则；通过资格闸门前不能作为 GDD 或 Proposal 的正式依据。

## 原始想法

用户确认：玩家可以沿已知连接返回已经处理过的普通节点；返程经过这些节点不会自动重新触发其原始处理，每次移动到相邻节点都消耗探索移动预算；其他重复进入效果留到后续确认。

## 触发来源

2026-08-21，在确认节点结算完成后才返回地图后，agent 提出已处理节点返程方案；用户确认推荐方案。随后用户补充确认：经过已处理节点仍消耗移动预算，但不重新触发原始处理。用户进一步确认移动预算耗尽时本次探索按失败结束，不允许继续移动、自动传送或自动回满；首个原型在探索开始时固定预算，探索过程中不补充。固定预算按入口—撤离点基准路线长度加上返程余量确定。

## 可能带来的玩家体验

- 玩家可以沿已知路线承担返程压力，抵达单一撤离点，而不是被单向路线锁死。
- 已完成的节点不会因返程自动重复触发，路线状态更容易理解。
- 返程仍会消耗探索移动预算，并暴露于持续探索血量和其他地图风险之下。

## 暂定标签

- 类型：`System / Traversal Constraint`
- 情绪：返程、承诺、方向感、及时止损
- 玩法关键词：已处理节点、沿边返程、不可自动重触发、移动预算、撤离路径
- 风险关键词：软锁、预算耗尽失败、重复触发、回访状态、返程成本
