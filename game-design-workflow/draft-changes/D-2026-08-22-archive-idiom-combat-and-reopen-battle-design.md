# 归档成语组合战斗系统并重新开放战斗设计

> 状态：`Accepted / Applied`

## 修改目标

修改 `core-concept.md` 中把“回合制卡牌 + 通用辅助卡 + 成语组合 + 共享战斗能量”描述为当前战斗主框架的内容，将它改为“旧方案已归档，战斗系统重新设计中”。

## 来源

- 用户明确要求：2026-08-22，重新设计新战斗系统并归档现有战斗系统。
- 归档对象：`GDD-BATTLE-001` 与对应 `combat-lab` 原型。
- 提案/评估：本次不采纳新玩法，只执行旧方案归档和正式状态复位；新玩法必须从 Raw Idea 重新通过资格闸门。

## 拟新增内容

```md
### 战斗层（重新设计中）

战斗仍是共享世界中解决关键冲突并向地图返回结果的系统层。2026-08-21 的“唯一核心卡 + 通用辅助卡 + 成语组合 + 攻防共享能量 + 完整轮流回合”方案及其原型已经归档，不再作为当前实现基线。

新的战斗形式、核心动作、胜负目标、节奏、资源、核心卡参与方式和地图接口均为 `Unknown`。在新的战斗 GDD 被确认前，不得默认继承旧方案中的卡牌、回合、组合、费用或行动位规则。
```

## 拟替换内容

原文把旧战斗规则写成现行主框架，并在核心玩法假设、核心卡字段、玩家循环与关键差异中直接依赖通用辅助卡、组合规则和激活费用。

新文将保留两项已经确认的上层职责：

1. 唯一核心卡继续是当前项目身份与长期资产，除非后续单独变更。
2. 战斗继续承担世界关键冲突的解决职责，并需要向地图返回可理解结果。

具体战斗形式全部重新开放，由新 GDD-0 决定。

## 采纳理由

- 用户明确要求停止沿用旧战斗系统。
- 只移动 GDD 而继续在核心构思中声明旧规则有效，会造成实现与决策冲突。
- 把旧方案保留在归档而不是删除，可以继续使用其测试证据和失败结论，同时避免无意识继承。
- 不提前描述新系统，符合素材资格闸门和 GDD 写作硬约束。

## 仍需保留的疑问

- 新战斗是否继续以唯一核心卡作为玩家身份与战斗中心？
- 新战斗是否仍是卡牌、是否回合制？
- 玩家反复执行的核心动作、胜负目标和主要反馈是什么？
- 战斗向共享地图返回哪些状态？
