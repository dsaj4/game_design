## 调研目的

拆解《Noita》法杖为什么能用有限法术产生大量组合，以及这种结构能否帮助本项目建立“有限卡牌语义物理”，避免退化为逐条手写卡牌配方。

## 一句话理解法杖系统

一根法杖不是一张技能卡，而是一个带有资源、时序和容量限制的小型程序执行器；插入其中的法术不是简单效果列表，而是会依次读取、修改、分叉或延迟同一次施法上下文的操作符。

## 玩家实际在玩什么

### 1. 先选择“执行器外壳”

法杖自身提供容量、是否乱序、每次抽取数量、施法延迟、充能时间、法力上限、法力恢复和散射等约束。相同法术序列放入不同法杖，可能因为外壳参数不同而产生不同节奏、稳定性和可持续性。

### 2. 再编辑有顺序的法术序列

非乱序法杖会按槽位顺序读取法术；乱序法杖会改变本轮抽取次序。顺序因此是构筑内容的一部分：修正法术放在弹体之前通常会改变后续弹体，多重施法会扩大同一个施法块，触发法术会把后续法术包进命中、计时或死亡后的子施法。

### 3. 用多类法术组成一条“可执行语法”

- 载荷：真正生成弹体、场、物质或其他世界对象。
- 修正器：改变伤害、速度、轨迹、寿命、散射、法力或时序等共享参数。
- 多重施法/抽取：继续读取更多法术，使多个载荷共享当前上下文。
- 触发器/计时器：创建嵌套施法，把后续载荷延迟到碰撞、时间到达或其他事件发生时执行。
- 被动与工具：持续修改持有状态、移动、视野或其他外围行为。

### 4. 把结果扔进同一个物理世界验证

法杖结果不是只对固定敌人扣一个数字。弹体、爆炸、火、水、毒、气体、刚体和地形继续进入共享世界模拟，因此一个组合的价值取决于它如何和场景状态相互作用。玩家循环是“编辑—试射—观察—理解—再编辑”。

## 为什么它能产生涌现

法杖的组合量并不主要来自预写“法术 A + 法术 B = 产物 C”，而来自四层复用：

1. **外壳参数复用**：一套法术在不同法杖参数下重新表现。
2. **共享施法状态复用**：多个修正器依次改写同一上下文，而不是各自寻找专属配方。
3. **控制流复用**：抽取、多重施法、触发和计时改变执行结构。
4. **世界规律复用**：最终对象进入统一物理、材料和化学系统继续反应。

因此法杖系统更接近“小型解释器 + 世界模拟器”，而不是纯粹的配方表。

## 可推断的实现机制

下面是根据可观察行为和游戏数据脚本结构重建的概念模型，不声称等同于完整内部源码。

```text
法杖固定参数
  + 有序法术槽
  -> 本轮抽取队列
  -> 创建施法上下文
  -> 依次执行法术操作
       修正器：改变当前上下文
       抽取器：继续读取 N 个操作
       载荷：按当前上下文创建对象
       触发器：创建嵌套子上下文和延迟载荷
  -> 生成弹体/场/物质/状态
  -> 交给世界模拟继续结算
```

### 核心数据角色

| 角色 | 负责什么 |
| --- | --- |
| 法杖配置 | 定义容量、资源和基础时序边界 |
| 抽取队列/弃置区 | 决定这轮读取哪些法术以及何时重新开始 |
| 施法上下文 | 暂存伤害、速度、散射、寿命、延迟等可叠加修改 |
| 法术操作 | 消耗资源，并修改上下文、抽取更多操作或生成载荷 |
| 嵌套施法 | 把一段后续操作绑定到命中、时间或其他事件 |
| 世界对象 | 接收编译后的结果，并进入像素物理和材料反应 |

### 真正的底层逻辑

Noita 没有消除手工规则。开发者仍需定义：法杖字段、法术操作、共享状态字段、触发语义、世界材料、反应规律和安全边界。它减少的是“组合级规则”的数量：当新法术遵守既有接口时，它可以与大量旧法术和世界状态发生此前没有逐条设计的关系。

## 能否迁移到卡牌上

结论：`可以，而且很适合；但应迁移解释器结构，不应复制无限法术链和实时像素物理。`

### 对本项目的概念映射

| Noita | 本项目可对应为 |
| --- | --- |
| 法杖外壳 | 核心卡提供的语义边界、容量和固有规则 |
| 法术槽位 | 有顺序或有角色的合成输入位 |
| 弹体法术 | 有限效果载荷，如伤害、防护、恢复、控制 |
| 修正法术 | 改变目标、传播、时序、形态或强度分配的操作符 |
| 多重施法 | 有限分叉；在同一预算内产生两个兼容分支 |
| 触发/计时法术 | 条件、事件或延迟结算结构 |
| 法力 | 整条组合共享的价值预算 |
| 施法延迟/充能 | 卡牌费用、冷却、时机或永久材料机会成本 |
| Always Cast | 核心卡固有且不可移除的解释规则 |
| 像素世界 | 确定性情境结算与有限状态关系 |

## 三种迁移方式

### A. 战斗中直接编辑“卡牌法杖”

玩家在战斗中排列多张卡，由解释器当场执行完整链条。

- 优点：最接近 Noita，构筑表现力和实验感最强。
- 风险：操作与阅读负担大，组合空间会迅速超过对战平衡、投影和复盘能力。
- 当前判断：不适合作为本项目第一迁移目标，需要单独 Proposal。

### B. 用 Noita 式解释器生成一张有限卡牌

玩家选择概念材料、行动和核心卡；内部解释器执行有限序列，得到一条可审计的状态变化链；系统再把它投影为一张只有一个或两个兼容公开效果的卡。

- 优点：保留规则组合和未见结果，同时符合完整投影、确定性发布、价值预算和效果数量上限。
- 风险：如果最终压缩过强，玩家可能看不出内部推演为何得到该卡。
- 当前判断：`最推荐`，可作为现有离散语义动力学的结构升级，而不是第三套互不相干的生成器。

### C. 仅借用视觉与命名包装

仍由人工配方表决定结果，只把卡牌描述成修正器、触发器和载荷。

- 优点：制作风险最低。
- 风险：没有真正迁移 Noita 的组合逻辑，仍是配方编译器。
- 当前判断：只能作为对照基线。

## 推荐的混合架构

Embedding 和离散语义物理解决“一个概念是什么”；Noita 式解释器解决“多个概念按什么顺序和作用域发生关系”。

```text
概念定义
  -> 语义落地：类型化性质与候选操作符
  -> Noita 式有限解释器：顺序、修正、分叉、触发、上下文
  -> 状态变化/执行轨迹
  -> 效果投影：一个效果或兼容双效果
  -> 价值预算与合法性验证
  -> 冻结、版本化的卡牌 IR
```

这比“Embedding 直接找最近效果”更有因果结构，也比“为每个概念组合写一条规则”更容易产生真正的未见组合。

## 必须保留的边界

- 操作符、状态字段和最终效果原语都是有限集合。
- 不允许模型在运行时创建新操作码或任意执行代码。
- 解释器必须确定、可追踪，并对递归深度、抽取数量和总预算设硬上限。
- 内部可以有多步过程，公开卡牌仍只呈现一个或两个兼容效果。
- 无法合法投影的结果保持 `Unmapped / 待审`，不为追求覆盖率强制生成。
- 已发布卡牌在同一内容版本内不因新增概念而改变。

## 需要避免的直接复制

- Noita 单机环境允许极端失控、崩坏和近似漏洞的组合；多人或长期资产系统不能把这种失控直接当作平衡策略。
- 不复制几十个隐含施法字段和难以解释的顺序例外；第一版只保留玩家能学习和复述的少量轴。
- 不让玩家必须理解递归、抽取栈或脚本执行顺序才能进行基础合成。
- 不把真实世界语义强行等同于游戏效果；语义只负责确定候选性质，游戏规律仍需设计与验证。

## 最小验证建议

在现有 48 组合实验上增加一个“有限施法解释器”变体：

1. 只允许少量通用操作：载荷、修正、目标变换、有限分叉、条件触发和延迟。
2. 每个概念只能贡献类型化性质，不能引用具体组合或最终效果 ID。
3. 每个行动只改变执行方式，核心卡只改变少量边界或固有规则。
4. 对未参与规则设计的组合生成执行轨迹和最终卡牌 IR。
5. 与当前离散动力学和 Embedding 路线比较语义合理性、可预测性、结果多样性、拒绝率、预算守恒和专用补丁数量。

成功不等于“组合越多越好”，而是少量规则能产生足够多有差异、可解释、可预测且不需要组合级补丁的合法结果。

## 对本项目的判断

Noita 法杖系统为本项目提供了一个比“效果区域最近邻”更接近真正涌现的中层结构：底层仍是有限语义性质，上层不是查配方，而是让通用操作在共享上下文中执行。推荐把它视为离散语义动力学的“组合语法/执行器”，先做并列原型，不直接改写 GDD-BATTLE-003。
