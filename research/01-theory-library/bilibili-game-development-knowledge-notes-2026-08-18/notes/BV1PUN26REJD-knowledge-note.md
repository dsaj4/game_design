# UI Blueprint：游戏UI概念图智能识别拆解工具演示

## 核心结论

- 该工具解决AI生成的完整UI概念图无法直接导入游戏引擎（如Unity、UE5）的问题，核心思路是直接识别并拆解原图中的独立元素，而不是重绘画面。
- 识别精度与所选模型直接相关：本地模型的一键测绘精度有限，接入GEMINI API后精细度大幅提升。
- 工具输出独立素材、干净背景板和各元素的位置信息（layout），可用于AI精准复刻概念图。
- 真实项目中，通常只提取核心元素（如两个小球）再交给AI重绘，而非直接使用全部识别结果。

## 背景：游戏UI资源拆分的难题

在游戏开发中，美术资源往往是最难的部分。一张完整的游戏画面可能包含角色、按钮、图标等多个元素。当前AI可以轻松画出一张完整的画面，但若要导入Unity或UE5使用，这些元素必须以独立资源的形式存在，不能直接使用整张图。在拆分这些元素时，保持风格一致性也很复杂，这就构成了一个核心痛点。UI Blueprint正是为了解决这一痛点而制作的工具。

## 工具设计思路：直接识别拆解，不重绘

UI Blueprint不会对概念图进行重绘，而是直接识别并拆解其中的各个UI元素。其输出包括：

- 独立的元素素材（透明背景）；
- 一张干净的基础背景板（可直接用作游戏场景）；
- 各元素的位置信息（layout）。

演示中，作者用一张AI生成的概念图来展示完整流程。

## 两种识别方式与精度差异

### 一键测绘：本地模型识别

点击"一键测绘"相当于使用本地模型进行识别，其精度有限。演示中，它只能识别出大概的整体框和球球等概略位置，两个作为主角的小球没有被识别出来。如果用户没有接入具备图像识别能力的AI API（如GPT或GEMINI），可以依靠一键测绘配合手动拖动、放大调节来使用，但识别能力明显不足。

### 接入GEMINI API：精细识别

接入GEMINI API后，识别精细度大幅提升。在同一张图片上，能够同时识别出整体、两个头像、文本以及两个主角，基础元素均能被准确定位。作者强调，识别精度与所选模型直接相关，这说明选择更强大的视觉模型能显著改善拆解质量。

## 手工精细处理与位置信息应用

识别出的元素可以手工进行精细化处理，为后续导出和AI生成做准备。作者提到，可以将Unity/虚幻引擎所需的位置信息以及导出的图片素材，通过MCP（Model Context Protocol）提供给AI，让AI直接生成对应的图片场景。

### 导出面板：提取与擦除

导出面板分为两列：左侧选择要提取的概念图元素，右侧选择要擦除的元素。擦除后可以获得干净背景板，并且系统会自动弥补背景。

### 手动框选擦除区域

当部分区域未被自动识别时，可以通过双击框选来手动指定擦除范围，例如擦除文字、灰尘、特效等干扰元素。这样可以保留基本结构作为透明背景板。

## 实践要点：真实项目的使用策略

作者指出，在真实项目中，通常不会直接使用全部识别结果，而是只提取核心元素（比如两个小球），然后交给AI重新绘制。这意味着识别工具的价值在于快速获得关键元素和布局信息，而非直接得到最终资产。这也解释了为什么工具强调"识别+提取"而不是"重绘"。

## 导出文件检查与后续计划

删除待处理内容并导出后，工具会生成layout文件，包含各元素的位置信息，可直接提供给AI用于精准复刻概念图。输出文件中还包括：

- **base图层**：擦除文字等干扰后的基底效果，背景被自动弥补；
- **overlay图层**：最终识别结果，用于检查框选是否准确。

如果对效果不满意，可以点击"重扣"重新调整位置。

作者计划后续发布视频，演示如何在虚幻引擎或其他游戏引擎中，直接使用导出的素材生成概念场景。

## 总结

UI Blueprint是一个面向游戏UI概念图的AI拆解工具，通过本地模型或接入GEMINI API实现元素识别，输出独立素材、干净背景板与布局信息。它桥接了AI绘画与游戏引擎资产之间的鸿沟，并采用"识别-提取-重绘"的工作流策略，为美术生产流程提供了一种自动化辅助方案。
