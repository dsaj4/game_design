## 一句话结论

原型不是缩小版成品，而是回答一个主要问题的可观察实验。先让自己确认它能运行，再让未参与设计的人确认是否可理解，最后才判断目标玩家是否愿意重复做出核心选择。

## 原型和试玩的区别

| 名称 | 关注问题 | 可接受的外观 | 不能推出 |
| --- | --- | --- | --- |
| 可行性原型 | 规则能否运行、平台/输入是否可行 | 纸面、白盒、占位界面 | 玩家一定喜欢 |
| 可理解性测试 | 玩家能否理解目标、信息和操作 | 粗糙但可操作 | 长期留存或平衡成立 |
| 体验测试 | 玩家是否产生目标行为和感受 | 足够稳定、目的明确 | 所有玩家都适用 |
| 平衡/回归测试 | 变更是否改变选择、胜率、时长或风险回报 | 可重复、记录版本 | 单次胜负就是定论 |

课程 `SJ-003` 把测试描述为渐进的多个阶段；它不是替代 S0-S7 的另一套生产阶段（`E-SJ003-P001-001`）。

## 最小验证流程

### 1. 写测试合同

| 字段 | 必填内容 |
| --- | --- |
| Test ID | `TEST-YYYY-MM-DD-short-name` |
| 主要未知 | 这次只回答哪个问题？ |
| 目标玩家 | 经验、偏好和招募边界 |
| 版本/材料 | 哪个原型、哪些规则、哪些占位内容？ |
| 玩家任务 | 玩家要完成的可观察动作，不要提前告诉解决方案 |
| 观察字段 | 行为、误解、犹豫、顺序、结果、口头解释 |
| 成功信号 | 看到什么才允许 `Go` 或保留假设？ |
| 失败/停止信号 | 什么结果说明必须改向、搁置或停止？ |

### 2. 先自己验证可运行

设计者先执行完整流程，发现规则缺口、材料不足和无法操作的步骤。自测只能证明“我能让它跑起来”，不能证明新玩家能理解，也不能证明体验成立。

### 3. 让未参与设计者复述

请对方只读规则和界面，完成同一任务，再复述：

- 你以为目标是什么？
- 你看见了哪些可选动作和代价？
- 你认为刚才发生了什么？
- 下一次会改变哪个选择？

把“哪里不对”和“我建议改成 X”分开记录。玩家通常更擅长指出问题，不一定能给出可行修复（`E-SJ003-P007-001`、`E-SJ003-P028-001`）。

### 4. 观察行为和环境

测试结果同时受游戏、玩家群体和环境影响。记录设备、座位/先后手、规则熟悉度、测试顺序和中断情况；识别离群值，不用一次测试替代重复观察（`E-SJ003-P009-001`）。

### 5. 只改变可解释变量并回归

规则改动前写出预期一阶和二阶影响。可行时一次只改一个主要变量，例如只改组合费用、只改触发时机或只改先手补偿；再用同一任务比较版本。小改动可能改变行动顺序、攻防倾向和战斗频率（`E-SJ003-P010-001`、`E-SJ003-P021-001`）。

如果必须同时改多个联动规则，明确标记为“组合实验”，列出无法排除的替代解释。

## 阶段门：S2 → S3 或回退

| 判定 | 证据要求 | 下一步 |
| --- | --- | --- |
| `Go` | 代表性玩家能完成目标动作，核心反馈可被复述，主要未知已有可接受解释 | 选择一条完整体验链，进入 S3 |
| `Iterate` | 方向可能成立，但存在稳定误解、反馈弱或代价不清 | 缩小改动范围，重新测试同一问题 |
| `Park` | 原型可运行但价值/成本暂不匹配 | 保存材料、失败路径和复议条件 |
| `Stop` | 核心动作无法形成目标体验，或不可行性风险不可接受 | 记录证据、替代解释和不可再用的假设 |

## 常见错误

- 用完整美术、地图数量或演示视频证明原型成功；这些不能替代玩家行为证据。
- 只问“好不好玩”，不记录玩家做了什么、何时犹豫、为何失败。
- 把最热情的专家玩家当作全部目标受众。
- 收到“改成 X”就立即采纳，没有先定位问题。
- 同一轮同时改费用、卡牌效果、界面和胜负条件，导致无法归因。
- 只记录正面反馈，删除失败、离群值或中途退出。

## Wiki 推断（Inference）

本页将课程中的测试目标整理为“测试合同 -> 自测可运行 -> 外部复述 -> 行为观察 -> 可解释变更 -> 阶段门”的最小循环。该顺序服务于一次减少一个主要未知，是 Wiki 综合方法，不是单一课程的逐字流程。
