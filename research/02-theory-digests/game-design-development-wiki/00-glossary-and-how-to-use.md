## 一句话结论

先问“这条话是什么类型的内容、证据在哪里、当前能推进到哪一步”，再决定把它写进研究摘要、Wiki、GDD 还是规则候选。一个“已经写下来了”的内容，不等于事实、决策或完成。

## 初学者解释：四个抽屉

| 抽屉 | 里面放什么 | 例子 | 能否直接改核心构思 |
| --- | --- | --- | --- |
| 材料 | 逐字稿、视频元数据、外部文章 | `SJ-002 P009` 的转写 | 否 |
| 证据 | 从材料中抽出的单条可核对主张 | “原型应回答核心未知” | 否 |
| 设计 | 本项目正在考虑的假设、提案和 GDD | “先做一条核心卡组合链” | 只有走正式决策流程后 |
| 规则 | agent 何时必须做什么、如何验收 | “部分课程必须标缺失 P” | 只改变协作方式，仍需评审 |

## 证据状态

| 状态 | 用通俗话解释 | 必须补什么 |
| --- | --- | --- |
| `Observed Fact` | 材料或测试直接显示/记录了什么 | 来源和范围 |
| `Source Claim` | 某位讲师、作者或项目明确这样说/做 | 说话者、上下文和边界 |
| `Inference` | 多条证据支持的合理推断 | 推理链、替代解释 |
| `Hypothesis` | 还要通过原型或试玩验证的判断 | 测试任务、成功/失败信号 |
| `Decision` | 项目明确作出的选择 | 决策记录、备选方案和复审条件 |
| `Unknown` | 现在没有足够答案 | 影响、负责人、下一步 |
| `Out of Scope` | 当前明确不处理 | 边界和复议条件 |

## 生产阶段状态

本 Wiki 和 agent 标准共用 `S0-S7`，但它们描述的是项目生产位置，不是材料是否读完：

| 阶段 | 用一句话理解 |
| --- | --- |
| `S0` | 先确定值得解决的问题 |
| `S1` | 把概念和核心循环写到可复述 |
| `S2` | 用最小原型验证主要未知 |
| `S3` | 用一条代表性体验链验证质量和生产方式 |
| `S4` | 在范围内稳定生产内容 |
| `S5` | 关键系统全部接通，暴露二阶影响 |
| `S6` | 冻结内容，完成质量和发布候选检查 |
| `S7` | 发布、支持、观察和复盘 |

每个阶段门只允许四种判定：`Go`、`Iterate`、`Park`、`Stop`。`Revise` 和 `Hold` 只作为历史别名，不在新记录中继续使用。

## 文档成熟度与设计状态

- `GDD-0`：概念对齐，回答“是什么、为谁、反复做什么、为何值得验证”。
- `GDD-1`：原型验证，补齐规则、状态、反馈、异常和测试。
- `GDD-2`：制作交接，补齐内容生产、依赖、可读性、无障碍、回归和版本。

GDD 成熟度不等于设计被采纳。设计状态仍使用 `Idea / Proposal / Evaluation / Draft Change / Accepted / Parked / Rejected`。

## 使用步骤

1. 把原话和来源先放进正确的材料位置，不要先润色成结论。
2. 用稳定 ID 连接来源、分集、证据卡、Wiki 页面、规则和假设。
3. 一条证据卡只承载一个可核对主张，标明上下文和可信度。
4. 把来源观点、跨来源推断、本项目假设分成不同小节。
5. 如果关键字段没有答案，写 `Unknown`，不要用“应该”“通常”遮住缺口。
6. 需要改核心构思时，回到 `Proposal -> Evaluation -> Draft Change -> Decision Log`。

## 正例与反例

**正例：**

> `E-SJ003-P021-001`（Source Claim）：主要规则变更可能产生二阶影响。本项目假设：调整组合费用时先改一个主要变量，下一轮回归记录选择率、回合长度和胜负；状态为 `Hypothesis`。

**反例：**

> “课程说要迭代，所以核心卡费用现在改成 2。”

反例把来源建议、项目决策和具体数值混成一件事，没有测试或决策记录。

## 自检清单

- [ ] 每句话都能归入材料、证据、设计或规则之一。
- [ ] 证据有稳定 ID 和 `BV + P` 定位。
- [ ] `Source Claim` 没有被写成 `Confirmed` 或 `Accepted`。
- [ ] `Hypothesis` 有最小验证方式和成功/失败信号。
- [ ] `Unknown` 有影响、负责人和下次行动。
- [ ] 阶段、GDD 成熟度、设计状态和代码状态没有互相替代。
- [ ] 缺失分集、冲突和失败路径没有被删除。

## 对当前项目的转化

当讨论核心卡、辅助卡、费用、组合、共享世界或交易时，先把未经确认的内容标为 `Hypothesis` 或放入 `idea-inbox/`。只有通过项目流程并记录决策，才可作为正式 GDD 或核心构思引用。

## 未确认信息

- 目标玩家的熟练度分层、平衡阈值、原型样本量和发布质量门槛仍为项目级 `Unknown`。
- 本页的状态和 ID 约定来自知识系统 Spec；集成到 `AGENTS.md` 前仍需反例审查。
