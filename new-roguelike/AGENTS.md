# 独立肉鸽项目操作规则

继承[根手册](../AGENTS.md)的资格、批量澄清、来源追踪与Git保护。Project ID：new-roguelike；W=`new-roguelike/`。不再继承已删除的根exploration。

- 先按任务读取README和CONTEXT；管理任务只读必要规则。玩法探索先读exploration/start.md和exploration/AGENTS.md，默认NONE空白背景，续作沿所选方向的登记版本。
- 与言咒、旧卡牌游戏独立。不读取它们的规则、背景包、数值、代码或实验结果填补Unknown；跨项目来源需明确选择。
- design/仅存正式采纳的规则；当前没有Accepted核心或GDD。不凭目录补造核心设计。
- 探索按exploration/DIR-NNN-short-name/README.md保存原话、阅读范围、构思、未知及来源；默认Raw Idea / Unqualified。候选不得直接进入正式GDD。
- 非方向的原始输入进入sources/inbox；合格素材进入sources/materials；Proposal、Evaluation、GDD草案和Draft Change分别进入sources/proposals、evaluations、gdd-drafts、draft-changes。按实际产物建子目录，不建空壳。
- 当前问题在governance/questions.md，采纳与管理决定在governance/decision-log.md；实现范围与证据在development，代码和工程细节留外部代码仓库。
- 资格按[设计流程](../docs/design-workflow.md)和登记模板；先查允许材料，再批量澄清。已获明确采纳授权不重复询问；模型补全、目录迁移、写入GDD都不等于Accepted。
- 正式规则变更先合格来源、提案/评估、目标Draft Change及明确采纳，再更新design和决策。实验需明确任务授权；计划与真实结果分开。
- 日常只写所选方向和必要索引。管理任务可在明确范围调整元数据；不扩大普通任务材料权限。保护文件修改同轮提交推送，仅暂存任务文件。
