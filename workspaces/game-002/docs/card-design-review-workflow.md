# 卡牌与流派：设计—评测—采纳流程

日期：2026-09-11。Project ID：game-002。状态：Workflow Guide，依据现行资格、模板和采纳流程。本页是项目操作入口，不是新增玩法或未登记的共享GDD模板。当前先按[修饰词与镶嵌入口](modifier-and-inlay-design.md)补足系统，再进入流派成套物品；先积累设计与待测项，下一次由用户启动合批测试。

## 一个设计单元是什么

词卡提供可复用词义，完整法术由合法组合求值，流派由一组实际组合与取舍构成。三者分别记录。一次可以处理一张词卡及其代表组合，或一个小型流派包；不要求先填满全卡池。

类型沿[当前特征](spell-type-index.md)列出全部命中项，多类型共同引用一份词义。未归类时按既有主动扩展要求评议；不能只因缺标签就新设类型。

## 流程与出口

| 步骤 | 本步交付 | 离开本步的条件与位置 |
| --- | --- | --- |
| 1 原始记录 | 用户原话、想影响的选择、与核心关系及Unknown | 按[idea-template](../../../game-design-workflow/templates/idea-template.md)进入本项目idea-inbox；未合格内容继续隔离 |
| 2 资格确认 | 设计对象、玩家行为／反馈、价值、依赖与验证问题 | 用grill-with-docs查现行规则；字段清楚后按[合格素材模板](../../../game-design-workflow/templates/qualified-gdd-material-template.md)晋级并双向链接 |
| 3 形成设计候选 | 可复用词义、代表组合、流派取舍、候选参数与本次纳入范围 | 依[提案模板](../../../game-design-workflow/templates/proposal-template.md)组织玩法假设；参数放素材或适用GDD，不把Proposal写成完整数值系统 |
| 4 文档评议 | 对照核心、GR依赖、同词复用、成本、边界与可读性 | 按[评估模板](../../../game-design-workflow/templates/evaluation-template.md)给出推进／修改／搁置／拒绝建议；本轮可做，不需要立即跑测试 |
| 5 积累测试包 | 同预算场景、版本、预期、比较方式、回归范围、缺项 | 追加到[固定交接](test-handoff.md)，当前保持Draft／NotRun；有缺项的内容不伪装Ready |
| 6 合批评测 | 规则结果、数值／策略比较、覆盖与限制、可读性证据 | 用户启动后，先固定所有输入并列入批次；测试agent回填。只有需要时扩大执行范围 |
| 7 用户采纳 | 准备加入或替换的具体文本、理由、证据、剩余风险 | 按[Draft Change模板](../../../game-design-workflow/templates/draft-change-template.md)组织，用户明确采纳后同步权威素材、必要的核心及decision-log，再提交推送 |

若需要完整GDD，使用已登记的[GDD写作模板](../../../game-design-workflow/templates/gdd-writing-requirements-and-template.md)，依目标选GDD-0／1／2，并审查相关素材；本页不替代模板。测试结果不是自动采纳，用户也可以明确采纳仍属Hypothesis的设计方向，此时保留未验证限制。

## 词卡候选必须能回答的问题

这些问题放进现有素材／GDD相应章节，不另建与其竞争的规格文档。

| 字段组 | 必须说清的内容 |
| --- | --- |
| 身份与来源 | 词条ID／版本、名称、名词／动词／修饰词及形容词／副词子类、来源、候选／采纳状态 |
| 修饰词专有声明 | 所挂原词与角色、通用／适配／不兼容、各版本的数值和附加结果、宿主／时点／能力边界、同值合并和附加左右顺序 |
| 核心词义 | 哪些角色可用，允许的对象与动作；同一词跨句哪些含义保持 |
| 引用与关系 | 实例／条件、角色数量与配对、受术者、同宿主关系、选择优先级与范围 |
| 数值与资源 | 每个参数的归属／单位／公式／候选值、实体副本、法杖、时间、明示额外费用及获取资格 |
| 过程与状态 | 作用阶段、持续／周期／结束、重施／归零、取消／失效、来源与目标读值时点 |
| 结果与失败 | 合法零值、无对象、成本不足、免除／禁止、成功事件、收益和终局边界 |
| 组合与反例 | 至少两个体现同词复用的合法组合及一个不合法或无效果情境；若当前词池不足，明确受限覆盖 |
| 评测安排 | 预先登记目标、同预算对照、场景和缺组件条件、影响的GR项、待测批次及报告入口 |

不适用字段写“本卡不涉及”，不要为填表而新增机制。不能用类型、名称或演出代替词义。

## 流派候选必须能回答的问题

- 玩家围绕什么具体组合和节拍作选择，主要收益从哪里来。
- 使用哪些名词、动词、形容词／副词和实体副本，以及明确的法杖／镶嵌组件；各自的槽位、渠道和成本是什么，哪些是核心、替代、可混搭组件；获得不到核心卡时还有什么可用方案。
- 同预算下比直接作用或其他候选多付出了什么，在哪些敌方压力、范围和进度下会失效。
- 关键资源是生命、状态量、时间、法杖还是获取机会；不把疲劳的扣血算成某条法术的输出。
- 用哪些结果判断具有独立取舍；不以换名或换起点凑流派数量，不增加职业锁、持有数量套装奖励或类型自动加成。

## 评测如何回流

| 发现 | 回流位置 |
| --- | --- |
| 句子无法唯一求值／缺少该卡具体声明 | 先按GR v1补齐词义字段；出现新的独立规则选择时另走设计变更，不重问已采纳GR处理 |
| 同词跨句意义或成本不一致 | 修改该词的共用定义，列出全部受影响组合；不能只修一条例句 |
| 计算或实现与明确规则不一致 | 实现证据进入代码仓库及开发索引，设计状态不自动改变 |
| 单场数值失衡／某流派全面占优 | 保留场景和资源分母，调整候选并登记新修订，旧报告继续对应原输入 |
| 玩法可理解性不足 | 更新反馈方案和玩家观察问题；自动测试通过不能替代这项证据 |
| 合格且用户采纳 | 按明确范围落入Draft Change及决策记录；未测结论继续标Hypothesis |
| 不适合当前方向 | Parked／Rejected并保留原因和来源，不悄悄删除 |
