## 持续维护规则

- **新测试提出时**：设计agent先更新本页当前测试包，写明目标、类型、来源与状态、固定输入、用例、完成判据、阻塞和回填位置。若输入不完整，标记Draft或Blocked并指出缺项；能够独立测试的部分单列。
- **输入改变时**：影响测试的词义、数值、规则、资源或实现版本变更，更新来源并增加交接修订号；输入先形成可追溯提交。仅修链接或排版可记维护日志，不改变测试输入修订。
- **测试进行中改变设计时**：保留在测提交与修订，新增修订并注明影响用例；旧结果只对旧输入有效，不静默套到新版本。
- **交给测试agent前**：核对文件可读、来源版本、当前状态、阻塞和预期交付；在设计回复中给出本页固定路径。此页准备完成不等于已经分派了测试任务。
- **测试完成或受阻时**：测试agent回填结果、证据、限制与差异；设计agent根据结果更新待决清单和下一步，涉及代码的证据同步开发索引。运行失败、规则歧义和目标不满足分别记录。
- **切换测试批次时**：先把当前批次的输入版本、执行结果和证据写入下表，再更新当前包。已结束的执行记录不覆盖；同一修订重测新增执行序号。每个批次在实际执行时记录交接文件所在提交，配合Git历史可恢复当时的完整交接内容。
- **完成协作修改后**：遵守仓库Git保护，提交并推送本轮涉及文件；不提交其他人的改动。此流程由后续参与本项目的agent在相关工作时执行。

任务状态使用Draft、Ready、Running、Completed、Blocked、Superseded；Completed只表示本批约定测试和报告已完成，不代表全部用例Pass，也不代表参数采纳。
