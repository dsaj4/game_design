## 登记单位与分类

一个ID对应可辨认的效果语义。一个效果可被多张卡、修饰词、镶嵌或流派复用；同一载体也可引用多个效果ID。FX-019、FX-028、FX-029目前是未具名方向，必须在具体设计前拆分，不能当作万能效果交接。

| 维度 | 用途 | 规则 |
| --- | --- | --- |
| 效果行为分类 | 数量改变、状态施加／清除／持续结果、对象生成、过程干预／时间改变、条件数值修饰／被动、资源产出、复合变化 | 可多选，按实际改变分类；不是新增法术类型 |
| 承载内容 | 名词／动词、形容词／副词、镶嵌、其他明确内容 | 登记效果从哪里获得及作用于哪里，不因载体不同复制同义效果 |
| 法术类型 | 简易／状态／元素／召唤等已采纳类型 | 按完整句特征逐句记录；范围被动本身不是法术，不能直接给它套法术类型 |
| 设计状态 | Raw／Candidate／Accepted／Parked／Rejected，允许明确分项 | 从来源逐项引用；框架Accepted不代表其具体卡牌Accepted |
| 清晰度与交接 | 待澄清／语义闭合／批次就绪，或限定参照闭合 | 与采纳、数值验证和实现证据分开；不能用一个“已完成”覆盖所有维度 |

同名不同义先分开登记，确认等价后才建立别名。“寒冰／冰霜”“造成伤害／伤害”“反弹／转移”“抵挡／护甲抵伤”均不能自动合并。基础效果与修饰版本分别记录依赖；复合效果不能把自身总收益与子效果收益再相加。

条目中的“关联效果”是跨版本的关系索引，包含前置、输出或对照，不等于全部硬依赖。形成具体效果版本时必须逐一标明关系并选择实际必需项：例如强化火焰只依赖火焰对象规格，不要求先完成雷电和冰霜；解除冰冻不依赖完整召唤，只有“解除恶魔的燃烧”才涉及召唤宿主。未标清该版本必需项时不能称为语义闭合。

基础世界规则作为外部约束引用，不能伪装成可装备效果。疲劳扣血／禁疗、伤害打断、战后护甲清除、死亡清理、胜负与金币奖金等放在[框架边界表](case-coverage.md#framework)，只有用户实际提出其可用内容版本时再登记候选并审查权限。

## 每项效果必须明确的规格

不适用写明理由，未知写明缺项和阻塞对象，不能留空或按常识补齐。

| 字段 | 需要明确的内容 |
| --- | --- |
| 身份与来源 | 稳定ID、修订、原话／案例、来源章节、承载卡／物品、状态及确认依据 |
| 一句话效果 | 谁在何时对什么做什么，改变哪个可观察量或对象 |
| 分类与适配 | 行为类别、适用完整句与类型、通用／特殊／不兼容、合法与非法组合 |
| 触发与计次 | 启动／释放／施加／周期／成功等具体事件；一次的边界；计数归属与初始化／重置 |
| 来源与目标 | 玩家／单位执行者／非单位载体、受益者、付费者、宿主配对、范围与阵营、数量及选择 |
| 输入与读值 | 参数归属、当前量或快照、每个读值时点，状态／对象存在及可操作窗口 |
| 改变量与公式 | 单位、量纲、固定／比例、取整域、下限／上限、零值与负值是否合法；区分符号定义与候选值 |
| 时间与存续 | 所属阶段、即时／延迟／周期、首次时点、持续、到期、结束、跨战／换来源是否保留 |
| 成本与资源 | 实体卡、时间、法杖／镶嵌资源及明示额外费用，按次／对象／实际量支付与失败记账 |
| 顺序与叠加 | 基础步骤和附加步骤顺序，同值合并、同效果／异效果并存、触发自己或彼此的边界 |
| 失败与终止 | 无对象／非法／成本不足／合法零值，部分结果、死亡、取消、范围变化、离场、终局 |
| 对象或产出专项 | 生成身份／窗口／来源／结束；掉卡／产金资格、次数、空池、有限来源、领取方式 |
| 依赖与版本 | 依赖效果、规则及明确Candidate分支；反向查受影响卡／例句／物品／流派／测试 |
| 证据与下一步 | 正常、边界、反例的预期；批次／输入／报告；缺项与下一次设计顺序 |

已有记录采用精简表，通用部分引用下述检查约束；一旦形成具体卡牌，须补齐上表适用字段。精简登记不是跳过完整规格的理由。

## 复用约束与职责边界

1. 语法、实体卡与绑定由现有框架判断；一个词保持核心含义，名称或演出不额外授予能力。先合法性，再本次对象资格，再支付与求值。
2. 直接名单在完整法术开始时固定，本次不追加、不补位；逐对象仍读当前合法性与资源。源方适用修正在法术开始读取；对象当时数量与存续依各自规则读取，不把两种时点混为一谈。
3. 普通数量按GR01合并固定／百分比后取整截断；时间参数须另列合法域。不能自行增加乘区、默认倍率或自动时长。
4. 固定消耗、按实际量消耗、一次费用与逐对象费用按GR05声明；缺费用不是免费。基础实体／时间成本继续适用，复用某效果不额外制造一张实体卡或一次施法。
5. 完整法术中的有限子步骤与独立派生事件分开；完整事件后检查胜负。GR07-C01和IN-C事件补充仍为Candidate，使用前须指定版本与有限响应证明。
6. 同义规则只维护一份。框架正文是通用规则依据；已存在效果的权威参数和确认文本仍在来源素材，本登记是有来源的规格摘要与缺口台账。新效果在资格确认后可把本条登记指定为唯一细则正文，素材／物品只引用其ID＋修订；指定时记录决定，不能同时改两份互相竞争的正文。
7. 来源不一致时在审查表登记冲突，确定当前有效来源再同步；用户已确认决定不重复询问，未决定的具体效果不替用户默认采纳。
8. 当前全部条目均未做本轮实现审查或玩法测试；少数已有外部限定证据仅按原输入引用。

## 后续讨论中的主动维护

每次用户提出、改写或举例一个效果，设计agent在本轮结束前执行：

1. 保存新原话并定位既有ID。相同语义补案例；新语义新建ID；语义改动增加修订并列差异。ID不复用，撤回／合并保留去向。
2. 原话未通过资格闸门时以Raw登记，只能关联inbox；明确缺项，不生成正式GDD结论。按grill-with-docs先查已有决定，再问确需用户选择的问题。
3. 按实际行为分类，逐句标全部法术类型，拆清来源、目标、触发和结果。复合效果引用子效果及顺序；特殊版本、通用版本与非法组合均有案例入口。
4. 检查同词一致、依赖、叠加、循环、目标失效和终局。只写具体效果的缺项，不能要求普通伤害卡先补齐完整召唤等无关系统。
5. 同步目录、来源／案例覆盖、审查缺项，以及受影响的素材／物品／流派入口；提出测试或改变测试输入时同步固定交接并增加修订。不自动运行或分派。
6. 给用户简述本轮ID、已明确内容和剩余阻塞。需要采纳玩法变更时沿用Proposal／Evaluation／Draft Change及decision-log，不因登记绕过流程。
