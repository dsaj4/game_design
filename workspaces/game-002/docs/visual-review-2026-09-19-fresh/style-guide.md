# 《言咒》简明视觉风格 v0.1

2026-09-19 · **Visual Draft / 待用户确认** · 基于全游戏 GDD RC1。

推荐方向：**可以亲手摆弄的言咒工坊**。墨色石台托住战场，羊皮纸承载词义，旧木与黄铜区分法杖器具；火与冰是画面里最明确的亮色。先读懂自己的编排，再欣赏它执行时留下的变化。

本包从 GDD 文字重新设计，未打开或引用仓库既有示例图、模型渲染和旧视觉稿。已写入 GDD 的桌面、长法杖袋、地图红线等文字要求仍保留。当前仅供风格评审，图片不是可运行 Demo，视觉确认不改变玩法规则或验证状态。

## 1. 视觉语言

| 项目 | 建议 |
| --- | --- |
| 整体 | 暗色工坊环境＋明亮纸面；安静、精密、有旧器物触感。通过少量道具营造氛围，视线聚焦词卡和战场 |
| 场景 | 固定视点、低透视畸变、清晰前后排。石台和敌人用简化体块，材质保留大尺度磨损；生成图较写实的细节作为气氛上限 |
| 卡面 | 浅纸底、墨色大词名、一枚刻印图形、词性、时间贡献、短规则；复杂语义放详情。词卡持续占配置，不能画成战中手牌 |
| 器物 | 木杖和黄铜固定芯形成主要轮廓；可换镶嵌独立两槽。原木杖同款身份一致，装饰差异不表示属性加成 |
| 敌人 | 守卫共同基础体型，靠轮廓和标志区分：藤缠、霜棱、焰纹、轻装、锤、盾；刻印守门者体量更大，仍单阶段 |
| 元素 | 火焰为上挑软轮廓，冰霜为尖晶硬轮廓；本体落在格子内，宿主状态贴附宿主，不把两者合成一个标记 |
| 地面 | 草地与石地有独立可点选标签；树木是上层占位。前排遮挡时保留后排列表入口 |
| 装饰浓度 | 边缘有书、卷轴、灯与工具；信息面板内部少纹理，不让道具、辉光或景深遮字 |

| --- | --- | --- |
| 炭墨 | `#202629` | 场景暗部、栏底、正文 |
| 灰青石 | `#465759` | 棋盘与非选中面板 |
| 羊皮纸 | `#E7D8B5` | 卡片、阅读面板 |
| 旧木 | `#655046` | 桌面、法杖 |
| 黄铜 | `#B89B67` | 层级、边线、固定芯 |
| 朱橙 | `#E47B48` | 火焰／燃烧，配火轮廓与文字 |
| 冰青 | `#8FC9D5` | 冰霜／冰冻，配晶体轮廓与文字 |
| 草灰绿 | `#839572` | 草固有属性与草地 |
| 赭红 | `#A44E42` | 路线、确认按钮与警示辅色，靠形状和文案区分用途 |

标题建议思源宋体 Semibold，正文建议思源黑体 Regular/Medium，数值使用等宽数字。独立 Demo 制作时选择可随包分发的字体并保留许可。

以 1280×720 为基础排版：正文建议 18 px 起、辅助文字 16 px 起、词名 24–28 px、主要按钮高 44 px；1920×1080按同一逻辑尺寸适配。支持 GDD 的100%／125%／150%字号；放大后允许面板滚动，开战、返回和生命信息保持可访问。这些是制作建议，需实际界面验证，不能由概念图像素尺寸证明。

## 3. 页面骨架

| 页面 | 主画面与信息顺序 | 必须保留的行为 |
| --- | --- | --- |
| 战前编排 | 左侧实体库存，中央四根杖及完整句，右侧所选杖的范围／名义时序；上方构句→法术→法杖 | 点击放置与拖动等价；词性筛选、词义详情、实例／条件绑定、移序、起点±、拆下、保存、开战 |
| 自动战斗 | 中央第一人称2×5石台；左侧四杖只读状态；右侧共同纵向刻轴；底部播放与记录 | 暂停／逐刻／0.5×、1×、2×、4×；对象、地面与来源可查；不能战中重配或出牌 |
| 路线桌面 | 红线纸地图占主区域，法师木雕指当前位置，后沿横置长皮法杖袋 | 全图可查、选中预览后进入；法杖袋与“法杖与词卡”文字入口等效 |
| 商店 | 同一桌面语言，四词卡＋两镶嵌＋一法杖的分区货架 | 固定价格、持有数、余额、售空说明；期1无可售法杖；没有刷新／出售／退款 |
| 休整拿词 | 背景压暗，三张候选大卡横排，名词／动词／其余合格名称 | 进入拿词后选择一张或拒收；不能返回领取治疗 |
| 普通结算 | 一包金币、剩余生命、成立刻、最近结果 | 整体领取或放弃；词卡不是普通战斗掉落 |
| 首领／失败 | 最终构筑、路线、结果原因与查看记录 | 首领胜直接结束本局；失败可复盘，无局外数值成长 |

主菜单、设置与规则册沿上述字体和面板复用。当前效果图只展示关键页面，不表示其余流程不需要制作。

## 4. 最容易画错的规则

1. 玩家在十格之外。棋盘永远两排各五格；草地是地面，敌人／树／元素才占上层位置。
2. 起始是4根原木杖、12张实体词卡、100生命、0金币；四句默认配置占9张。首次冷却起点0／1／2／2，对应首次名义释放4／5／7／8，第三杖持续7–9刻。
3. W01锚点F3覆盖F2/F3/F4/B2/B3/B4。范围六格不等于元素邻近；后者只有本格地面与正交邻格。
4. 共享槽只仲裁释放开始。同刻后杖覆盖前杖，已经开始的持续段可以并存；图上不能画成“排队等前杖放完”。
5. 火焰和冰霜是元素本体，燃烧与冰冻是状态。**普通冰冻周期给宿主护甲**，不能套用常见“冰冻=眩晕／减速”的表现。
6. 当前状态、固有属性、历史痕迹分栏。没有燃烧层数的焦树停止冒火；草树不会自行继续传播；石地不出现火冰层数。
7. 被覆盖、生命伤害打断、无目标、材料不足、合法0结果要用不同文字＋符号。被取消的释放不播放正常释放特效。
8. 路线19个图上节点、12种遭遇，一局走6普通＋1首领。问号、装饰书、金币箱不自动成为奖励入口；桌面不放猫。

## 5. 动效建议

先让落点、量值与原因清楚，再增加气氛。选中用细亮边；直接命中用短促冲击线；得甲用盾形扩张；火冰补层用向内汇聚；异种抵消用两色向中间收缩；转化用旧身份淡出、新本体出现；取消在刻轴上划断并显示原因。

1×仍按0.5秒一刻观看。演出不改变结算顺序；高速可以合并提示但记录完整。提供降低特效、关闭闪光与镜头震动，静音和低动效模式仍能读到全部结果。图片不会证明动效与可读性已验收。

## 7. 确认后的独立 Demo 边界

建议采用01–03的主风格、02的编排布局和06的选词层级；04的实体感少量用于桌面，05作为密度更高的对照方案。

用户确认后，再在独立代码目录／仓库从RC1建立Demo，不沿用已有Demo的代码、场景或资产来替代此次独立开发。先交付能构句→调杖→自动战斗→看原因的真实核心闭环，再接路线、获取、保存和首领。中间单场版本应明确为阶段性切片，最终试玩目标仍是GDD的完整单局；若要缩减最终卡池或局长，应另行记录范围变更。

本轮没有选择引擎、创建游戏代码或运行玩法测试。开发技术方案与完成度将进入代码仓库及[代码开发索引](../code-development-index.md)，不写回GDD。接下来只需确认这套主风格和页面组合，或指出要调整的图号与部分。
