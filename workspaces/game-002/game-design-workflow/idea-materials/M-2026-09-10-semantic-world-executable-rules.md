## 规范化表述

战斗世界由有明确身份、结构、材料、属性、状态、空间关系和进程的对象组成。可辨认的战场事物与真实作用具有语义身份和操作入口；具体对象只开放材料、结构、状态与词义共同允许的能力。对象引用支持实例与条件绑定，单次直接名单在完整法术开始处理时确定，本次不重选、追加或补位。

法术可以按明示规则改变位置、连接、能力及未完成过程。名词位置允许复合对象短语，所增加的词义仍由实体词卡承担；多端点、数量、去重、顺序、成本、介入窗口与反应阶段均有明确约束。玩家固定战前的词卡分配、绑定条件和法杖顺序；运行中的对象与时间安排可由已配置法术改变，变化原因公开。

共享槽仲裁释放开始，直接效果在开始时完整结算一次；释放时长计入周期，持续作用由明确过程或状态承载。修改冷却默认作用于当前未完成的剩余冷却，实际释放完成后继续基础冷却，最早进入下一刻调度；覆盖和生命伤害打断保持当时计划中的后续周期。胜负判定与全局四阶段保持固定，胜利立即停止其余处理。环境、关系与过程变化默认限于本场，资源产出和战前配置权限不能通过复制或转化绕过。

### R01–R32正式规则

以下正文与已获用户采纳的推荐逐项对应。所有规则状态均为Accepted；实例词条和具体参数须按规则填写，不自动生成词卡、能力或数值。

| 编号 | 设计问题 | 已采纳规则 |
| --- | --- | --- |
| R01 | “所见”包含哪些东西？ | 可辨认的战场事物、部件和真实作用均有语义身份与可操作入口；界面和纯演出指回对应对象，明确区分装饰。 |
| R02 | 操作粒度细到哪一层？ | 单位、部件、表面、材料、状态、关系和过程可分别引用；粒度由内容明示，不自动细分到任意像素。 |
| R03 | 能力从哪里来，能否改变？ | 能力由材料、结构和状态的明确规则共同决定；法术可按词义赋予或移除能力，不能任意改写规则定义。 |
| R04 | 材料、属性、状态如何区分？ | 材料有来源与持有位置，属性描述对象，状态附着于宿主；同一份内容不能同时计为两份可消耗材料，痕迹不等于仍在生效的状态。 |
| R05 | 条件可以表达多复杂？ | 支持词义许可的属性比较、与/或/非及有限关系路径；所有条件战前可见，入列后轮到对象再检查原条件，不满足只跳过、不补位；复杂度容量另定。 |
| R06 | 一次选全部还是选部分？ | 词义声明全部、单个或限量选择；允许的优先选择方式写入配置，不默认所有名词代表全体。 |
| R07 | 两种绑定能否混用、重叠如何处理？ | 同一法术可在不同语义角色使用两种绑定；同一角色、同一效果步骤命中同一身份只处理一次，明确的不同效果步骤仍各自生效。 |
| R08 | 对象按什么顺序处理？ | 默认沿公开初始顺序，新生对象按确定的生成先后追加；同刻按既定阶段、来源顺序和效果内顺序定先后，选择优先级须显式声明。 |
| R09 | 空名单如何反馈和收费？ | 仍完成一次无效果释放并进入后续周期，不计成功事件、不扣对象材料；区分无匹配、对象失效和材料不足的原因。 |
| R10 | 多对象操作如何计算成本？ | 每个动词明确按次、按对象或按实际量计费；一次性成本在首个可结算对象前支付，无合法对象不支付，若不足则本次无合法结果；各对象固定成本不足只跳过该对象，不重复扣费。 |
| R11 | 能否跨对象取材料？ | 默认在词义指定宿主或来源取材；跨对象取材必须明确来源、去向和消费顺序，不自动从全场凑足材料。 |
| R12 | 是否开放位移和结构变化？ | 允许明确法术改变对象位置、部件连接或局部结构；基础行动保持预设，战中仍不新增手动控制。 |
| R13 | 范围如何跟随位置变化？ | 战前确定法杖范围形状与锚点，实际覆盖按锚点当前位置求得；实例身份不免除范围检查，效果落到该对象时检查作用距离，移出则跳过。 |
| R14 | 空位置和区域能否作为对象？ | 可引用明确位置、表面和区域；区域具有边界、锚点与存续，生成需合法落点，作用场与法杖选取范围分别定义。 |
| R15 | 分离、合并、转化后还是原对象吗？ | 普通属性变化保持身份；已独立登记部件分离保留自身身份，新生碎片建立新身份；合并默认产生新身份，其他转化逐条声明身份延续。 |
| R16 | 拆分后的材料和状态归谁？ | 材料和状态按明确归属转移或分配，整体失去转出部分；部件与整体共享的内容只计一次，不自动复制完整状态或生命。 |
| R17 | 遗体与残留物是否可操作？ | 死亡单位身份失效；内容可明示生成独立遗体或残留物作为环境对象，其能力另定，不能继承原单位攻击或专属引用。 |
| R18 | 基础句式如何承载复杂对象？ | 保留两种外层句式，名词位置可扩展为可读的复合对象短语；增加的词义仍需实体词卡，绑定配置不代替词义成本。 |
| R19 | 多端点操作如何表达和配对？ | 动词明确执行者、材料来源和结果去向，端点由合法词义与绑定逐个指定；一对一、一对多、多对一须声明，不隐式做全部交叉组合。 |
| R20 | 条件是否能免费变成事件触发？ | 条件默认只在循环释放时求值；若需要“每当发生某事”，必须是独立声明、具有触发条件和成本的效果，不能由筛选条件自动变成额外施法。 |
| R21 | 攻击、冷却、飞行物何时能被操作？ | 每种过程明确准备、进行、完成阶段及可介入窗口；仅能改变尚未完成的作用，演出和已经完成的记录不能被拦截或回滚。 |
| R22 | 过程开放哪些操作？ | 建立取消、延迟、加速、偏转、改向等操作类别，逐类声明适用过程；取消一次实例不自动删除整个循环或发起者。 |
| R23 | 改冷却后如何排后续周期？ | 默认修改当前未完成的剩余冷却；本次实际释放完成后按基础冷却继续循环，不直接改基础周期参数；不能在当前结算内产生额外释放，最早进入下一刻调度。 |
| R24 | 多刻释放怎样使用共享槽？ | 共享槽仲裁释放开始；直接效果在开始时结算一次，释放时长仍计入周期；需要分段或持续效果时由明确的过程或状态承载。 |
| R25 | 自动变化后怎样保持信息可读？ | 公开对象能力、来源、关系和失败原因；时间轴展示当前已知安排及修改原因，未来条件未定时展示条件，不伪装成必然命中名单。 |
| R26 | 间接反应在哪个阶段结算？ | 法术明示的直接变化归本次法术；环境性质诱发的反应归环境阶段，状态周期归状态阶段；已错过所属阶段的新事件转到下一刻对应阶段。 |
| R27 | 传播和反应循环怎样结束？ | 环境传播按刻推进，每次有明确资源或状态变化；同一根因、对象和反应规则在同刻不重复触发，跨刻也须声明持续或终止条件。 |
| R28 | 是否采用通用物理反应？ | 建立材料、能力与反应表，热、湿润、燃料、导通、支撑等只按明示规则互动；具体燃烧、导电和坍塌机制按后置约定单独启用。 |
| R29 | 环境作用是否伤及友军和自己？ | 受明示名单或传播范围覆盖且能力匹配的对象均可受作用；阵营保护必须由选择条件或效果明确提供，不默认免疫友军。 |
| R30 | 法杖物体与法术配置能改到哪里？ | 区分物体、运行状态和配置；按词义允许作用于已定义物体或运行状态，战中不能因此重分词卡、换法杖顺序或改镶嵌槽位。 |
| R31 | 复制、转化能否绕过奖励限制？ | 复制战场实体不自动复制库存、金币、词卡或配置权限；任何额外产出仍经对应资格、额度和成本规则，不因改名或转化跳过检查。 |
| R32 | 世界改变会保留到下一场吗？ | 环境、关系与过程变化默认只影响本场；玩家生命、已领取库存和收益遵守已有跨战规则，永久世界改造须有独立机制。 |

### 共同解释边界

- R08的“新生对象追加”指纳入世界的公开对象排序；SW02-A的单次直接名单不在处理中追加。每次释放按当时名单与公开顺序处理。
- R05复查条件、R13复查距离、能力和材料检查都只会使已入列对象继续或跳过；不会自动选入另一个对象。选择优先级与处理顺序分别说明。
- R10的首个可结算对象须满足当前合法性及本次适用材料条件；同一来源承担一次性与对象成本时须能覆盖合计需求，不因重复引用重复付费。未产生合法结果不生成成功事件。
- R15–R17不让死亡单位继续存活或自动复活。原单位引用与附着状态按离场规则结束，只有内容明示的独立产物获得自己的身份、材料与能力；原状态不自动完整复制。
- R23改变的是过程当前剩余时间；基础冷却由已分配词卡决定。覆盖、生命伤害打断和显式改期分别解释，不能把改期效果写成玩家战中改配置。直接效果完成后，持续过程的后续作用不自动新增一次法术释放或成功事件。
- R26–R28保留四阶段及胜利停止；明确过程须声明所处阶段和有效窗口。传播按刻产生下一步，不能靠同刻反复重新选取直接名单传播。
- R20、R22、R28与R30确认框架及权限，不自动启动完整召唤指挥、镶嵌触发或BF1–BF3具体反应。每种具体操作须明示适用对象、代价、结果和终止条件。

## 设计对象与 GDD 映射

- 作用对象：法术语义世界、构句与引用、对象变化、过程时序、反应与资源权限。
- 目标 GDD：尚未创建；作为统一GDD的系统规则与验证章节输入。
- 建议章节：构句与法术、战斗对象、时间与空间、环境交互、反馈与边界。
- 对应完成度：GDD-0 / GDD-1素材输入；不宣称达到完整GDD-2内容规格。

## 玩家处境、行为与反馈

- 玩家处境：战前使用完整库存构句与配置法杖，战中观察自动求值，战后调整下一场方案。
- 玩家看见/知道什么：对象身份、结构、能力、来源、关系、可操作过程窗口，以及当前已知攻击与循环安排。
- 玩家会做什么：选择对象粒度、实例或条件绑定、数量、端点和成本；规划位移、转化或过程修改的先后。
- 系统反馈：解释匹配、失效、材料不足、范围变化、改期、产物身份与反应阶段；图像变化对应真实结果。
- 预期价值：同一词义跨对象复用，玩家能凭结构与规则推导结果；开放表达伴随明确时间、材料和范围取舍。

## 机制—行为—体验假设

| Mechanics：规则/约束 | Dynamics：可能行为 | Aesthetics：目标体验 |
| --- | --- | --- |
| 明确对象结构、能力和条件引用 | 玩家根据当前与未来对象安排可复用表达 | 发现与因果理解 |
| 位移、材料转化、端点和有限过程操作 | 比较空间、代价与时间先后 | 有成本的创造与规划 |
| 名单边界、公开排序、分阶段反应和资源权限 | 能回溯失败与变化原因并调整配置 | 可解释且可学习的自动战斗 |

## 未知项与验证

| 未知项/风险 | 影响 | 下一步验证或决策方式 | 成功信号 | 失败信号 |
| --- | --- | --- | --- | --- |
| 对象、能力和词卡目录未完整 | 类别可能只有名称而无法操作 | 每类填写合法句、失败句和变化后的引用 | 每个声明可操作对象有可执行表达 | 只有图谱或隐含例外 |
| 复合短语与关系路径的学习负担 | 自定义能力可能难以读懂 | 以同场成功/失败配置进行玩家解释测试 | 能说明角色、来源、目标及失败原因 | 依靠猜测或无法区分职责 |
| 动态改期、范围及反应组合 | 结果可能难以预判 | 先作规则走查，再带参数逐刻验证 | 同一配置有唯一可追溯结果 | 同刻无界循环、重复结果或隐式补位 |
| 数值与资源转换 | 可能出现支配策略或无成本产出 | 按重新设计任务比较快、稳、产出方案及跨战压力 | 不同取舍有代价与用途 | 无限套利、单一表达全面优于其他 |
| 完整后置系统未启动 | 不能声称所有能力已成为可用玩法 | 启动时局部资格确认并填写内容 | 可识别框架与实际内容边界 | 将范围确认当作全部机制已实现 |
